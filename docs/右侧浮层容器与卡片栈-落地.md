## 定义表驱动

新增 `lib/workspace-cards.ts`，对齐 Hana 的 `kY` + `CY` + `TY`：

```ts
export const MAX_STACK_CARDS = 12;   // hana 的 const E8 = 12

export const WORKSPACE_CARDS = {
  files: {
    id: 'files',
    title: '文件',
    visibleWhen: () => true,          // 主卡常驻
  },
  preview: {
    id: 'preview',
    title: '预览',
    visibleWhen: (s) => s.hasSelection,   // 有选中项才出现
  },
};

export const WORKSPACE_CARD_ORDER = ['files', 'preview'];

export function visibleCards(state) {
  return WORKSPACE_CARD_ORDER
    .filter((id) => WORKSPACE_CARDS[id].visibleWhen(state))
    .slice(0, MAX_STACK_CARDS)
    .map((id) => ({ ...WORKSPACE_CARDS[id], meta: ... }));
}
```

**关键行为：预览卡在没选中内容时不渲染。** 这是 Hana 的做法，没有内容就不占空间，而不是留一张空卡。

## 一处必要的例外

预览卡的内容区不能用通用的 `.workspace-card-scroll`：

```css
.workspace-card-studio .workspace-card-scroll {
  display: flex;
  flex-direction: column;
  overflow: hidden;
  padding: 0;
}
```

原因：`overflow-y: auto` 会让 flex 子项的高度塌成 0。实测预览区 `height: 0`，iframe 完全不显示。改成 `overflow: hidden` + flex 撑满后：

```
previewH: 388    bodyH: 388    hasFrame: true
```

Hana 的 `_previewPanelBody_11fea` 也是 `overflow: auto` 但在 `[data-preview-content-type=pdf]` 时改成 `overflow: hidden`，同一个道理。

## 三个踩到的坑

**坑一：CSS 注释缺了 `/*` 开头**

上一轮替换时把注释起始符删了，留下一段裸露的 `hana 的真值：...` 文字，Vite 报 `Invalid declaration: // 6px`，全站 500。

这是第五次踩注释相关的坑。

**坑二：`workspaceTab` 在声明前被使用**

我把 `cards = visibleCards({ tab: workspaceTab })` 放在了 `useState` 声明之前，报 `Cannot access 'workspaceTab' before initialization`，页面全白。

**React hooks 的声明顺序必须严格自上而下。** 加派生值时先确认依赖已声明。

**坑三：用假 PDF 验证视觉**

「报表.pdf」只有 10 字节，Chrome 无法渲染，截图里是一片黑块。我一度以为是布局问题。

换成合法 PDF 后 `hasFrame: true`、`frameH: 388`，一切正常。**验证视觉前先确认测试数据本身有效。**

## PDF 底部黑边：保留

Chrome PDF 插件在 iframe 高度大于页面时，会用查看器自己的深色背景填充空白区。

实测四种参数（横版 420×300 PDF，容器 408×388）：

```
view=FitH    截图 23616 B
view=Fit     截图 23616 B   ← 与 FitH 完全相同
view=FitV    截图 27426 B
无参数        截图 25702 B
```

`FitH` 与 `Fit` 结果一样，因为容器宽度（408）小于页面宽度（420），两者都按宽度缩放，下方必然留白。

**这是 Chrome 查看器的固有行为，CSS 碰不到。** 要消除需要 PDF.js 自绘，代价是引入 300KB 依赖并重写渲染。
