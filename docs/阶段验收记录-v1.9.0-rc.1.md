# 墨衡 v1.9.0-rc.1 阶段验收记录

日期：2026-10-14  
基线：`v1.8.0-rc.1`  
本轮范围：对照《施工单位成本管理系统完整设计方案 v1.0》，实施只读操作追溯与审计 CSV 导出；不改变账务规则或数据库结构。

## 1. 已完成内容

- 新增 `GET /api/audit-logs`，支持项目、业务对象、关键字、日期范围、分页以及 CSV 导出。
- 服务端根据管理员身份或 `ProjectMember` 项目成员关系进行查询限域；普通用户不能通过修改前端参数读取未授权项目记录。
- 新增“操作追溯”页面，展示时间、操作者、项目、业务对象、操作类型和摘要；可展开查看只读变更快照；提供加载、错误、空状态、刷新、筛选、分页与导出反馈。
- 经营总览最近操作区域增加“查看全部”入口。
- CSV 使用 UTF-8 BOM 和标准引号转义，处理公式注入；读取和导出快照时递归隐藏凭证类敏感键。
- 未修改 Prisma Schema 或 migrations；没有修改合同金额生效、业主结算/应收、分供应付、退款冲销等金额与状态规则。

## 3. 尚未通过/尚未执行的发布门禁

当前工具环境使用 Node.js 22.16.0，而根目录和 API 包均声明 Node.js `>=24.0.0`；未安装本项目完整 `node_modules`。因此下列项目未执行，不得推断为通过：

- 完整 TypeScript 类型检查（API `tsc`、Web/Vite 构建）。
- `npm run build` / `npm run lint` 的完整 workspace 执行。
- Prisma Client 生成、Schema 校验、真实 PostgreSQL 权限集成测试。
- 浏览器 E2E，特别是普通用户跨项目访问、管理员全局日志查询、CSV 下载及筛选分页。
- Windows 原生部署与实际数据库备份恢复演练。

## 4. 风险与后续 Gate

1. WP4 仍需逐条盘点财务写操作的审计覆盖度，当前不能宣称所有金额修改路径已经完全审计。
2. 本轮 CSV 是 Excel 可打开的 CSV，不是原生 XLSX；目标成本之外的关键台账导出、导入预览/映射还需分阶段建设。
3. 正式开放前需在 Node.js 24+ 环境通过完整构建和数据库集成测试，并验证普通用户无法查询未关联项目的审计记录。
4. 不应先实施财务离线写入；须先建立幂等键、冲突检测、重试和人工合并策略。

结论：本轮增量实现和当前环境可运行的检查通过，版本仍为 **RC（发布候选）**，不是生产验收完成。
