## 一、搜索框：输入框必须有透明底

### 问题

用户观察到「框内底色与框外底色不一致」——搜索框看起来是个**白块**，而不是比侧栏略深的凹槽。

### 根因

moheng 有两层底色叠加：

```
容器 .sidebar-project-search      → color-mix(--sidebar-bg 97%, --text 3%) = #eeebe5  ✓ 正确
输入框 .sidebar-project-search-input → 全局 input 规则给了 --bg = #fcfaf5       ✗ 盖住容器
```

**输入框比侧栏底色更浅**（`#fcfaf5` > `#f4f0ea`），所以视觉上是凸起的白块。

### hana 真值

```css
._sessionSearchBox_afbfa {
  height: 30px;
  padding: 0 var(--space-8);
  background: color-mix(in srgb, var(--sidebar-bg, var(--bg)) 97%, var(--text) 3%);
  border: none;
  border-radius: calc(var(--radius-sm) * var(--corner-radius-scale, 1));
  corner-shape: squircle;
}
```

**hana 的输入框自身没有背景**，容器底色直接透出。

### 修正

```css
.app-sidebar .sidebar-project-search .sidebar-project-search-input {
  background: transparent !important;
  border: none !important;
  box-shadow: none !important;
}
```

### 实测

```
侧栏      : #f4f0ea
容器      : #eeebe5   ← 比侧栏深 3%
输入框    : transparent  ✓
```

## 二、操作按钮：移到分组标题行，与「本年」同行

### 用户原话

> 不要标题「项目」这两个字，把这一行的排序按钮和管理项目按钮移到下面一行，和本年同行

### 修正前

```
[项目]                        [+ 排序]     ← 独立工具行
[本年]
  项目 A
  项目 B
```

### 修正后

```
[本年]                        [+ 排序]     ← 按钮在分组标题行
  项目 A
  项目 B
```

**「项目」二字已完全删除。**

### 实现

删除整个 `.sidebar-project-toolbar`，改为 `SectionTitle` 的 `actions` 属性：

```jsx
{groupIndex === 0
  ? <SectionTitle actions={ACTIONS}><span>{group.label}</span></SectionTitle>
  : <SectionTitle><span>{group.label}</span></SectionTitle>}
```

`ACTIONS` 常量只渲染在**第一个分组标题**上（对齐 hana：操作区属于列表头部，不属于每个分组）。

无分组模式（`sort === 'recent'`）用「项目」作标题，同样带按钮。

### 实测

```
[本年]  按钮=2  同行=✓ 中心线一致
独立「项目」标题行: ✓ 已删除
分组标题总数: 1
```

## 三、操作按钮显隐：触发区是整个滚动区

### hana 真值

```css
._sectionTitleActions_8338c {
  display: inline-flex;
  gap: var(--space-4);
  flex-shrink: 0;
  opacity: 0;
  transition: opacity var(--duration-fast);
}

._sessionListScroller_5f4dd:hover ._sectionTitleActions_8338c,
._sessionSectionTitle_eb6ae:hover  ._sectionTitleActions_8338c {
  opacity: 1;
}

._sessionSectionTitle_eb6ae:focus-within ._sectionTitleActions_8338c {
  opacity: 1;
}
```

**触发区是 `._sessionListScroller`（整个滚动区），不是只悬停标题行。**

### 上一轮我犯的错

上一轮我把按钮改成**常显**，理由是「去掉标题文字后悬停区太窄」。

**这是错的。** 标题文字现在恢复了，而且触发区本来就是整个滚动区，不窄。

### 修正

```css
.sidebar-section-title-actions {
  display: inline-flex;
  align-items: center;
  gap: var(--space-4);
  flex-shrink: 0;
  opacity: 0;
  transition: opacity var(--duration-fast);
}

.app-sidebar-scroll:hover .sidebar-section-title-actions,
.sidebar-section-title:hover .sidebar-section-title-actions,
.sidebar-section-title:focus-within .sidebar-section-title-actions,
.sidebar-drawer:hover .sidebar-section-title-actions {
  opacity: 1;
}
```

### 实测

```
鼠标在画布 : opacity=0  ✓ 隐藏
鼠标在侧栏 : opacity=1  ✓ 显现
```

## 七、一个方法上的教训

**这三处问题的共同点：我把「局部改动」当成了「完整实现」。**

| 问题 | 我做的 | 应做的 |
|---|---|---|
| 「项目」去掉，按钮与标题同行 | 只去掉了文字，按钮留在原行 | 文字去掉 + 按钮移到分组标题行 |
| 排序按钮显隐 | 改成常显（理由错误） | 恢复 opacity 0 + 滚动区触发 |
| 搜索框底色 | 只查了容器，没查输入框 | 输入框也必须透明 |

**规则**：改一个组件的视觉时，必须把它的**每一层**（容器、内部元素、状态）都量一遍，不能只改看得见的那一层。
