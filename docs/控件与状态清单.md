这 19 处结构一致、eyebrow 各异，正好是 `Modal` 的 `eyebrow` + `wide` + `className` 三个参数能覆盖的范围。`ProjectsPage` 那处多了进出场动效，收编时要把 `is-closing` 传进 `className`，别把动效丢掉。

### 2.2 原生 `<button>`：177 处 / 37 文件

集中在三类：

| 类别 | 例子 | 判断 |
| --- | --- | --- |
| 壳层自绘 | `WindowControls` 17、`Layout` 18、`ToastHost` 2、`PreviewTabBar` 1 | 不动。窗口按钮、导航项、提示条关闭都不该长得像业务按钮 |
| 选择型控件 | `AppearanceSettingsPage` 12（主题块、图标、字体、纹理、开关、分段、宽度档）、`SystemDictionariesPage` 10、`SystemGovernancePage` 9 | 暂不动，但缺一个共享的「可选项 / 开关 / 分段」组件；现在每页自己挂 class 和 aria |
| 直写按钮类名 | `SystemDictionariesPage` / `SystemGovernancePage` 里的 `<button className="button-primary">` | 视觉无差异，维护有差异 |

最后一行今天实测过，不是推测。1600 视口下，`/system/dictionaries` 上直写 `className="button-primary"` 的按钮与 `/projects` 上共享 `Button` 渲染出的按钮，计算样式完全一致：

```
border-radius 9.20448px · corner-shape squircle · height 32px
padding 0 12px · font 13.6px / 500 · background rgb(70, 107, 128)
```

差别只在 `.button` 基类由谁补。收编的理由是将来改一处要改两个地方，不是眼前难看。

### 2.3 分页：两套并存

| 位置 | 形态 | 语义 |
| --- | --- | --- |
| `/audit-logs` | `.audit-pagination`：共 N 条 + 上一页 / 第 x / y 页 / 下一页 | 服务端分页，页码可回跳 |
| `/system/security` 两张表 | `.load-more-row`：已显示 x / N 条 + 显示更多（每次 +20） | 客户端展开，只能往后 |

两者不是同一个东西，暂时不该硬合成一个组件。要统一的是外壳：文案格式、按钮尺寸（现在一个是 `Button variant="secondary"`，一个是 `button button-secondary button-small`）、以及条数不足一页时是否显示。

## 3. 状态清单

七种状态，按用户能看到的顺序。

| 状态 | 实现 | 覆盖 | 缺口 |
| --- | --- | --- | --- |
| 加载 | `LoadingBlock` | 76 处 / 33 文件 | 无骨架屏，整块替换；短请求会闪一下 |
| 空 | `EmptyState` | 41 处 / 17 文件 | 子面板里刻意用单行空态（`暂无…`），不进 `EmptyState`，这是有意为之 |
| 错误 | `ErrorBlock` | 42 个调用点 / 32 文件，**全部带 retry** | `describeError` 已按 5xx / 403 / 登录失效 / 断网 / 迁移未应用分化标题与下一步 |
| 表单内错误 | `.form-alert` | 49 处 / 22 文件 | 与 `ErrorBlock` 分工清楚：一个在表单里贴字段，一个占整块内容区 |
| 局部提醒 | `.inline-notice` | 34 处 / 13 文件 | 承载「部分成功」「需二次确认」这类非阻断信息 |
| 成功反馈 | 两套并存：页面内 `.success-notice` 14 文件；全局 `toast()` 2 文件 | — | **真正的不一致在这里**：同一个「已保存」，有的页面在表单下方留一行，有的从右下角飘一下就没了 |
| 禁用 / 忙碌 | `Button disabled` + mutation 的 `isPending` | — | 提交中多数靠禁用，少数改按钮文案；没有统一的 loading 按钮形态 |
| 关闭动效 | `ProjectsPage` 的 `closeWithMotion`、`PaperDialogMorph` 的 `is-closing` | 2 处 | 只有这两处有退场动画，其余对话框直接消失 |

**无障碍缺口（实测）**：`role="status"` 16 处 / 13 文件、`role="alert"` 8 处 / 7 文件，`aria-live` 只有 2 处。`LoadingBlock`、`EmptyState`、`ErrorBlock` 三个共享组件本身都不带 live region，异步刷新时读屏不会播报「加载中」变成「空」。

## 4. 已核实、判定不改的项

盘点时被标成「不一致」，逐项实测后确认是合理变体的，记在这里免得下一轮再查一遍。

| 现象 | 结论 |
| --- | --- |
| 输入框 / 下拉框普遍 32px，个别 30px | 30px 是搜索框内框，外框仍是 32，符合[组件不变量](组件不变量.md) §4 的嵌套算术 |
| 徽标 20px，设置窗内字号 13.6 | 徽标尺寸由行高定；设置窗是放大字号后的等比结果，不是漏改 |
| 子面板空态没有走 `EmptyState` | 单行空态在大表格里比插图卡片更合适 |
| tab 高度 38px 与其他按钮不同 | 选项卡不是按钮，不参与三档高度 |
| `ErrorBlock` 有一处没传 retry | 那一处在注释示例里，不是运行路径 |
| 分页两套都留着 | 见 §2.3，语义不同 |

## 5. 待办

按「改一次收益最大」排序。

**P0 · 对话框收编**（19 处 → 0）
先 `ChangesPage` 5 处，它占了四分之一，且五个对话框的 eyebrow 结构最齐；再 `DownstreamContractsPage` 4 处。每页收完用现有 26 路由视觉回归比对，确认宽度档、eyebrow、按钮位置不变。

**P1 · 成功反馈定一套**
选 `toast()` 还是页内 `.success-notice`。倾向 toast：14 个文件的内联提示各占一块版面，内容通常只有一行「已保存」，而且用户滚到列表底部时根本看不见。这一步要改 14 个文件，但改完能删掉一整套 CSS。

**P1 · 分页外壳统一**
只统一文案与按钮尺寸，不动分页语义。

**P2 · 选择型控件抽组件**
开关、分段、可选项现在散在 7 个设置页里，各自维护 `role` 与 `aria-checked`。抽一个 `ChoiceGroup` / `Switch` 之后再谈样式统一。

**P2 · live region 补齐**
给 `LoadingBlock`、`ErrorBlock` 加 `role="status"` / `role="alert"`，成本极低。

**P2 · 原生按钮收编**
上表第三类（直写 `button-primary`）先收，壳层与选项控件不动。
