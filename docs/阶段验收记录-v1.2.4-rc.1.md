# 阶段验收记录：v1.2.4-rc.1（信息架构与付款状态边界）

日期：2026-10-14

## 1. 本轮目标

在 v1.2.3-rc.1 已有分供合同、付款/退款和成本关联模型基础上，针对主合同页面形态、项目业务入口、结算后付款边界，以及全局/单项目视图的职责分离进行源码修改。此版本没有新增数据库表或迁移，不需要新的 Prisma 数据结构迁移。

## 2. 本轮实现

1. **主合同页面改为摘要优先。** 默认呈现合同名称、编号、签订日期、业主、原始合同金额、当前有效合同额、调整净额、税口径与关键条款。新增/编辑表单移入对话框，建档后的原始合同金额仍为只读。
2. **新增项目工作台统一入口。** `/workspace` 为单项目工作台，默认进入项目驾驶舱；通过共享页签进入业主主合同、预算与目标成本、进度款、变更签证、分供合同与付款、实际成本、成本分析。每个业务页保持独立路由与表单，不合并成单一超长页面。旧路由保留重定向兼容。
3. **分供合同模块命名更专业。** 左侧/工作台入口采用“分供合同与付款”，页面标题为“分供合同台账”，成本录入与关联入口也使用“分供合同”用语。数据库模型名和 API 路由名保留以确保兼容。
4. **修正结算后的付款边界。** `SETTLED` 在界面上显示为“结算已确认”。ACTIVE、COMPLETED、SETTLED 均可登记付款/退款；新付款计划与已生效补充协议仍仅允许 ACTIVE/COMPLETED。结算确认不再误当成款项已付清。当前累计付款校验仍以合同当前金额为上限；本轮没有新增独立结算单/应付账款模型，不能将其描述为正式结算金额核销。
5. **拆分全局经营总览与项目驾驶舱。** `/` 只请求全局 `/dashboard`，展示当前账号有权限访问的全部项目的指标、项目经营组合、待跟进变更和最近操作，不读取选中项目的成本分析接口。新建独立的 `/workspace` 项目驾驶舱，用于查看单个项目的核心指标、成本走势、待跟进事项和业务入口。成本分析保持为独立专业分析页。
6. **修正无目标成本时的偏差表达。** 若项目没有目标成本基准，项目列表的成本偏差显示为“—”，项目驾驶舱提示“尚未建立目标成本”，避免把实际成本全部误标为超支。
7. 同步更新开发维护指南、用户操作手册、README、更新日志与发布候选静态检查规则。

## 4. 信息架构原则

- **全局经营总览**：只用于跨项目管理视角；数据范围为当前账号可访问项目。项目数据行可点击进入项目驾驶舱。
- **项目驾驶舱**：为单项目的经营工作总览，汇总本项目的收入合同、目标成本、实际成本、收款、待跟进事项及各业务入口。
- **项目工作台**：提供统一业务入口和项目上下文，但业务页面仍保持独立。
- **成本分析**：专注三算口径、目标成本与实际成本偏差和相关成本趋势，不兼任整个项目的导航/待办门户。
- **主合同管理**：摘要优先、编辑按需打开，原始合同金额锁定规则不变。

## 5. 结算确认后的付款语义

`SETTLED` 的展示名称为“结算已确认”，表示当前状态机已标记结算完成，不保证现金款项已付清。合同状态允许的现金流行为如下：

| 状态 | 新增付款/退款 | 新付款计划 | 登记新的已生效补充协议 |
|---|---|---|---|
| DRAFT | 否 | 否 | 否 |
| ACTIVE | 是 | 是 | 是 |
| COMPLETED | 是 | 是 | 是 |
| SETTLED（结算已确认） | 是 | 否 | 否 |
| TERMINATED | 否 | 否 | 否 |

注意：现阶段付款累计上限仍按当前合同金额校验，不是独立的正式结算应付上限。后续如需严谨控制已审定结算额、累计应付、累计净支付、质保金、预付款抵扣与尾款，应新增结算单/应付账款模型，不宜直接把 `SETTLED` 当作全部付款核销完成。

## 6. Windows 测试机建议验收

源码包解压到新目录，不覆盖已经验证的旧版本。在 Node.js 24+ 环境生成 `package-lock.json` 后，执行：

```powershell
node --version
npm install
npm run validate:release-candidate
npm run db:generate
npm run lint
npm run build
npm test
```

然后启动 Windows 原生 API，验证以下 UI 流程：

1. 打开 `/`，确认没有把某个选中项目的单月图表当作全局统计；切换工作台项目后返回 `/`，全局指标范围不变。
2. 从经营总览点击项目进入驾驶舱，再进入主合同、目标成本、进度款、变更签证，确认页签与项目上下文保持一致。
3. 主合同已建档时默认只看到摘要；点击编辑后才出现表单，并确认原始合同金额仍只读。
4. 结算已确认的分供合同仍能登记未付的付款和合法退款；新增付款计划和补充协议操作不应出现/应被 API 拒绝。
5. 没有目标成本的项目，成本偏差显示为未建立基准，而不是自动显示为超支。
6. 检查不同项目成员的权限，确保全局视图只汇总当前账号可访问的项目。
