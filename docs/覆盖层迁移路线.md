# 覆盖层迁移路线（2026-10-22）

## 结论先说

`legacy.css` + `v6.css` 共 **849 条外观规则**，实测分类：

| 分类 | 数量 | 占比 | 含义 |
| --- | --- | --- | --- |
| **可删** | 342 | 40.3% | `hana.css` 已完全覆盖，删了不影响渲染 |
| **需接管** | 246 | 29.0% | 部分属性仍靠旧层，先搬进 `hana.css` 再删 |
| **须保留** | 261 | 30.7% | 旧层仍在承担功能，暂不动 |

换句话说：**旧层的大部分规则确实已经死了，但有三成还活着。**

## 这份数字怎么来的

不是靠数规则条数，而是靠**逐元素实测**。判据是：

> 一条旧规则的某个外观属性，如果 `hana.css` 里**同样能匹配到该元素**的规则也声明了这个属性，则视为已覆盖。

工具：`scripts/map-migration-full.mjs`，跑 27 路由，对每条旧规则在其匹配的每个可见元素上做交叉比对。

### 工具怎么验证的

用已知答案校准：

- `.button` 家族 → 已在上一轮删除，地图里查不到，符合预期
- `.field input` → 判定为"部分覆盖"，唯一未覆盖属性是 `width`，符合"皮肤已接管、布局仍由容器控制"的事实
- `.toolbar-search input` → 判定为"可删"，因为它只声明了 `font-size` 一个属性

## 已知的坑

1. **混合规则**：一条规则同时管多个组件时，不能整条删，要把已迁移的组件从选择器里摘掉（`.button` 那轮踩过，5 条）
2. **`@layer` 包裹**：`legacy.css` 整个在 `@layer legacy {}` 里，Chrome 里 `CSSLayerBlockRule.type` 是 **0** 不是 4，递归删除时必须靠 `rule.cssRules` 存在判断
3. **Vite 开发模式**：CSS 注入为 `<style>`，`sheet.href` 为空，必须靠 `data-vite-dev-id` 识别来源
4. **`!important`**：遇到带 `!important` 的旧规则，改源规则本身，不要用 `!important` 去覆盖（`hana.css:5485` 那条踩过）
5. **几何与皮肤分离**：一个类只接管几何（高度/圆角）而不接管皮肤（背景/边框/颜色），会形成"看起来正常但靠巧合"的状态。输入控件就吃过这个亏
6. **属性名被覆盖不等于行为等价**：工具把 `.route-transition` 判为"可删"，因为 `animation` 这个属性名在 v6 里也有声明。但 v6 声明的是 `animation: none`（有意关闭页面入场动效），旧层声明的是 `animation: pageReveal .24s`。属性名相同但语义相反。

   所以删之前必须实测 `getComputedStyle` 的实际值，而不是只看"谁声明了这个属性"。`.route-transition` 实测 `animation: none`，旧层那条确实无效，可以删；但如果当初 v6 没写 `none`，删了就会丢掉动效。
