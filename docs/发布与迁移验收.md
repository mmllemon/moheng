## 迁移相关核心规则

- 已提交的历史迁移文件不重写；新增兼容性改变采用追加迁移。
- 对历史项目保留原始合同基线与重算有效合同额，存储迁移前后值和原因码。
- 有效调整只计算未删除且外部确认状态有效、外部确认金额有效的记录；主合同正式金额按既定规则优先于旧项目自由值。
- 主数据由历史文本回填时保留未核验标记；名称相同但身份未核验的记录不自动合并。
- 缺少历史责任人与审计证据的记录保持未解决，不得推测责任人。

## 仍未关闭的发布阻断项

1. 使用用户的脱敏、代表性预发布快照运行同样迁移演练，并逐项目比较迁移前后金额及 reconciliation reason。
2. 由业务/审计负责人审核同名历史/正式往来单位、缺少责任人的历史变更，以及无法恢复的内部审批人/外部确认记录人；保留签认与异常记录。
3. 在实际部署拓扑做登录、项目权限、报表预览/XLSX 导出、后台任务和备份恢复 smoke test。
4. 完成 Windows 原生安装/启动/停止、ACL、凭据附件目录、日志与密钥恢复的受控演练。
5. 产品侧完成报表/全站 UI/AI 路线图验收；所有验收项应对应实际代码、测试/浏览器证据或明确业务签认。

## 备份与恢复证据边界

隔离 PostgreSQL 16 的 pg_dump/pg_restore 合成演练可以证明备份脚本和数据比对路径工作，但不证明生产权限、加密异地备份、生产级数据规模、灾难切换、RPO/RTO 或实际暂存数据可正确恢复。

具体测试程序和可复现夹具见 `docs/gates/`。真实数据必须由授权运维人员在隔离环境中处理；原始 dump、连接字符串和密钥不得提交进仓库或上传到聊天。
