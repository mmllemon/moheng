## 迁移与历史数据核对规则

- 不重写已经提交的历史迁移；兼容性变化通过追加迁移实现。
- 历史项目需保留原始合同基线，并核对迁移前后有效合同额；差异应保存前后值、原因码与项目级核对结果。
- 有效调整仅将未删除、外部确认状态有效且外部确认金额有效的记录计入；按既定业务规则处理正式主合同金额与旧项目自由值。
- 由历史文本回填的往来单位关系须保留未核验状态；仅名称相同不得自动认定为同一法律主体。
- 缺少历史责任人、内部审批人或外部确认记录人的资料保持未解决并进入业务/审计复核，不得推测补齐。

## 尚未关闭的发布阻断项

以下项目尚无足够的最终验收证据。关闭前不得将当前 RC 视为生产就绪，也不得仅凭 CI 绿灯进入正式发布：

1. 使用经授权的脱敏代表性预发布数据库快照重跑迁移，逐项目比较金额并由业务负责人签认 reconciliation reason。
2. 由业务/审计负责人审核同名但主体未核验的往来单位、缺少责任人的历史变更，以及无法恢复的内部审批人/外部确认记录人；保留签认和异常清单。
3. 在目标部署拓扑完成登录、项目数据权限、报表预览/XLSX 导出、后台任务、备份与恢复的端到端 smoke test。
4. 在 Windows 目标环境完成原生安装、启动/停止、ACL、配置与密钥管理、日志/凭据目录权限以及备份恢复演练。
5. 完成真实浏览器中的报表预览/导出一致性、复杂模板边界、日期/下拉控件交互与视觉签认。
6. 只读 AI 助手需通过受控真实模型供应商端到端测试，并完成成本、隐私、超时/重试和限流评审；`ASSISTANT_POC_ENABLED` 必须保持默认关闭，直至准入审批完成。

## 备份恢复的证据边界

隔离 PostgreSQL 16 的合成 `pg_dump/pg_restore` 演练可以验证脚本和基本数据比对路径，但不能证明生产规模、生产权限、加密异地备份、灾难切换、RPO/RTO，或用户真实预发布数据可以正确恢复。

可复现的迁移/恢复程序与样例数据保存在 `scripts/gates/`、`docs/gates/`。真实数据应由授权运维人员在隔离环境处理；原始 dump、连接字符串、凭据和密钥不得提交仓库或上传到聊天。
