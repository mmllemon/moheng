### 2.1 依赖与锁文件证据（2026-11-05 重封）

`source-bundle` 门禁自 2026-10-18 起一直红着：期望的 lock 哈希停在 `a6f8a53a…`，而 `c253948`（zod 3→4 升级）已经改过 `package-lock.json`，哈希从那天起就是过期的。本次按门禁自己要求的流程重封，不直接改数字：

1. 先发现锁定依赖里挂着 1 条高危（Vite）与一批 moderate，于是先把阈值内的安全补丁升到位：`vite` 6.4.3 → **6.4.5**、`@fastify/static` 10.1.6 → **10.1.10**，再 `npm audit fix`。
2. `npm ci` 连续两次均成功（720 包，44s / 46s），两次之后 `git status` 无变化，说明锁与清单自洽。
3. `npm audit`：**高危与严重 0 条，剩 4 条 moderate**，均来自同一条公告 minimatch globparts 放大（`GHSA-g3hv-75wg-m249`）。
4. `npm run build -w @cms/web` 通过（vite 6.4.5），`@cms/web` 与 `@cms/api` lint exit 0，API 单测 275/275，web 单测全绿。
5. 新哈希 `ad1ca6a5624ad15edcb12c1476c8650ba7b97a95e549cf87f52388e64a139642`，已写入 `scripts/validate-source-bundle-completeness.mjs`，`source-bundle` 门禁转 PASS。

**剩下的 4 条 moderate 为何没清掉**：受影响的是 `readdir-glob@3.0.0` 里的 `minimatch@10.2.6`（链路 `exceljs-hardened → archiver → readdir-glob`）。10.x 线没有修复版本（最新就是 10.2.6），要修必须升到 11.0.4。尝试过两条路都不采用：

- `overrides: { "minimatch": "^11.0.4" }`：npm 对已存在的锁不会重新解析，强制 `npm install --force` 也不生效，实际树里仍是 10.2.6。
- 删锁重生：生成的锁从 11757 行降到 10462 行、删掉 2747 行，变化集中在其他平台的 optional 二进制包（esbuild / rollup / oxide），会直接弄坏 Linux CI 的安装。

风险评估：该公告是恶意 glob 触发 DoS，而 `readdir-glob` 在本仓只用于导出时遍历我们自己生成的临时文件名，不接受外部 glob；`glob@14`（静态资源）已经跑在 11.0.4 上。待 `archiver` 或 `readdir-glob` 升到 minimatch 11 后再跟进，届时重新重封。

PR #17 与 #18 的两组工作流均包含成功的主 job 和辅助 job：`assistant-runtime`、`pi-durable-poc`、`prisma7-migration`、`legacy-data-migration-upgrade`。主干 `551d154` 在 PR #19 的文档变更后触发的 Assistant runtime workflow 也通过。Prisma 7 migration workflow 配置为 PR 事件和指定迁移分支 push 事件；上述证据对应 PR #17/#18 的精确头提交，不假称它在后续每个文档提交上重新运行。

这些证据证明相应构建、自动化测试和隔离 PostgreSQL/合成迁移验证工作流通过。它们不等于全业务流程均有路由级覆盖，也不等于真实浏览器、真实模型供应商或生产部署已验收。

## 3. 当前开发阶段仍应推进的验证

1. **业主最终结算负差额的路由级 PostgreSQL 回归：** 现有修复与 helper 级回归测试已合并；继续补齐真实路由事务测试，验证负向应收/过账、审计原子提交与重新读取后的余额。

4. **报表和 UI：** 本轮已完成主要路由的视觉/axe/窄屏回归和交互 token 收口；继续验证复杂模板、多个重复区域、预览与 XLSX 一致性、打印分页与中文输入。报表工作室的 Univer 画布内部皮肤已决定不做（2026-11-05），属长期豁免；外壳仍随台账规范走，边界见 `组件不变量.md` §11。

## 4. 仅在预投产/投产条件具备后执行的门禁

这些事项仍然重要，但应在对应数据、拓扑或验收参与方实际具备后执行，而不是当作当前仓库开发无法继续的理由。

- **真实历史数据迁移/对账：** 只有在确有待迁移的用户历史台账或正式脱敏快照时，才核对原合同基线、有效外部变更、业主结算/应收及收退款、分供结算/应付及付款/退款、发票分配、实际成本和主体关联，并保留差异解释。
- **Windows 目标部署：** 在选定部署环境验证服务账号 NTFS ACL、`apps/api/.env`、附件/日志/备份目录权限、密钥配置和启动/停止。
- **备份与恢复：** 有了目标部署拓扑后，演练 PostgreSQL 与附件/凭证一起恢复，检查登录、项目授权、合同、成本、报表和 AI 开关状态，并记录实际 RPO/RTO。CI 中的合成 `pg_dump/pg_restore` 仅证明脚本可工作。
- **正式业务/财务/审计验收：** 在可运行的代表性业务环境和相应验收材料准备好之后，由项目实际责任方执行；没有真实数据或尚未进入该阶段时，不应制造虚假的签认状态。
- **真实 AI 供应商准入：** 由授权人员在受控环境设置凭据，测试超时、重试、取消、用量计数、成本/隐私控制和只读边界；不得通过聊天提交 API key。
