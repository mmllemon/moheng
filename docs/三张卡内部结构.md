## 一处重要的结构纠正

**「对话文件 / 工作室」不是两张卡，是同一张卡里的两个 stack item。**

```js
kY = {
  "session-files": { stackItemId: "workspace-session-files", cardDefinitionId: nR,
                     titleKey: "rightWorkspace.tabs.sessionFiles" },
  workspace:       { stackItemId: "desk", cardDefinitionId: tR,
                     titleKey: "rightWorkspace.tabs.workspace" },
}
CY = ["session-files", "workspace"]

function YY(state, tabState) {
  const active = MY(tabState.rendererState)
              ?? PY({ sessionFileCount: NY(state, state.currentSessionPath ?? null) });
  return CY.map((r) => {
    const s = _Y[r];
    return {
      stackItemId: s.stackItemId,          // ← stack item，不是 card
      definitionId: s.cardDefinitionId,
      title: localize(s.titleKey),
      active: r === active,
      kind: "builtin",
      sourceKind: "builtin",
      meta: null,
      ...r === "workspace" ? { studioView: XY(state, tabState) } : {},
    };
  });
}
```

默认 tab 决策：

```js
function PY(state) { return state.sessionFileCount > 0 ? "session-files" : "workspace"; }
function MY(rendererState) {
  const t = isObject(rendererState) ? rendererState.workspaceTab : null;
  return t === "session-files" || t === "workspace" ? t : null;
}
```

**有会话文件就默认 `session-files`，否则 `workspace`；用户选过的优先。**

moheng 现在的实现（两个标签切换）位置是对的，但它是**卡内 tab**，Hana 是**卡内 stack item**，两者语义不同：

```
Hana 的 stackItems  →  同一张卡的多个「内容层」，一次显示一个
moheng 的 tab       →  同一张卡的多个内容，一次显示一个
```

行为一致，实现层不同。这个差异可以接受。

## 三张卡的分工（总结）

| 卡 | 内容 | 数据源 |
|---|---|---|
| 文件（主卡） | stackItems：对话文件 / 工作室 | 会话产物 / 工作室挂载点 |
| 文件（主卡）内 | 预览标签栏（多文件） | 打开的文件标签 |
| 预览（次卡） | PDF / Markdown / 媒体渲染器 | 当前选中文件 |

**「对话文件 / 工作室」是主卡内的 stack item 切换，「预览标签栏」是预览卡内的多文件切换。**
