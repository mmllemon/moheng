## 二、排序分组：只做两种

### 修正前

照抄 hana 的 `obe = ["today", "thisWeek", "earlier"]`，分「今天 / 本周 / 更早」。

**这是会话场景的时间粒度，工程项目不适用。**

### 修正后

```ts
sort === 'time'   → 本年 / 去年 / 更早      （按 startDate 的年份）
sort === 'status' → 在建 / 待结算 / 暂停 / 已结算  （在建排最前）
sort === 'recent' → 不分组，平铺
```

状态顺序常量：

```ts
const ORDER: ProjectStatus[] = ['CONSTRUCTION', 'SETTLEMENT_PENDING', 'PAUSED', 'SETTLED'];
```

### 实测

```
按时间:  [本年] 滨江综合服务中心项目 / 金融城5号配电工程
按状态:  [在建] 滨江综合服务中心项目
         [已结算] 金融城5号配电工程
         在建排首位 ✓
```

### 排序菜单

```
排序：按时间 / 按状态 / 按最近
显示：双行 / 单行
```

`SortMode` 类型：`'time' | 'status' | 'recent'`

## 五、过程中的两个真实故障

### 故障一：CSS 嵌套注释导致 500

注释块里写了 `font-size: var(--fs-caption);       /* 12.48px */`，**内层 `/*` 提前闭合了外层注释**，Vite 报 `Missing opening {`，整个页面 500。

**这是第四次踩同一个坑。** 已修，并在脚本里加了自动检测。

**规则**：块注释内不能出现 `/*` 序列。写注释时用 `←` 代替。

### 故障二：PostgreSQL 容器退出

`moheng-pg` 状态 `Exited (255)`，登录接口 500（`P1001 Can't reach database server`）。

已 `docker start moheng-pg` 恢复。

**这是环境问题，不是代码问题。** 但排查时容易误判为代码故障，因为现象都是「页面打不开 + 500」。
