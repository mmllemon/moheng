## 1. 本轮实现

- 新增账号跨项目只读数据范围及管理 UI，既有用户默认仍限于项目成员范围；授权变更审计并撤销旧会话。
- 项目角色权限策略由服务端 `canAccessProject` 执行，只能在源码权限上限内收紧。
- 变更签证内部审批读取发布流程定义，保留自审批禁止及外部确认/金额规则隔离。其他业务工作流仍未接入。
- `CONTRACT_EXPIRY_WARNING_DAYS` 与 `TARGET_COST_OVERRUN_DANGER_PERCENT` 进入待办/预警实际计算，项目级覆盖全局值，无效/缺失值使用默认值。
- 数据库与 PostgreSQL 全局角色/配置归档双加密保存；恢复演练验证数据库归档并在隔离库创建/清理临时库。全局 SQL 不自动应用。
- HTTPS 集成连接测试与 JSON 投递支持 allowlist、DNS 公网地址校验、幂等键和后台重试；特定 ERP/存储适配尚未打通。
- 巡检按钮常态透明、hover 中性色、focus-visible 中性色轮廓。

## 3. 必须执行的发布 Gate

1. Node.js 24+ 且锁文件依赖已安装：`npm run lint`、`npm test`、`npm run build` 和 `npm run validate:release-candidate`。
2. `npm run db:generate -w @cms/api`，然后在隔离 PostgreSQL 中执行 `npm run db:deploy -w @cms/api`；确认全部历史迁移、两条新迁移、枚举/字段/外键/索引均正确。
3. 用普通账号验证默认只限已分配项目；显式授予跨项目只读后只能读取允许范围；直接请求所有写 API、审批 API、成员 API 和操作审计均应按规则拒绝。
4. 发布/回滚项目权限规则与变更审批规则；验证草稿不生效、发布版本号、并发发布、无效规则 fail-closed，以及提交人不得审批本人提交的变更。
5. 发布两个业务可读参数，验证全局默认/项目覆盖、越界值拒绝、草稿不生效、ADMIN_ONLY 不被业务消费者读取。
6. 配置独立 `BACKUP_GLOBALS_DATABASE_URL` 和加密密钥环，生成双归档，篡改密文应校验失败；在不同 PostgreSQL system identifier 的隔离实例做恢复。全局角色 SQL 要通过人工受控步骤恢复并复核，不能对生产/共享集群试验。
7. 对允许名单外域名、内网 DNS、IPv4/IPv6 字面量、重定向、超时、429/5xx、幂等重试进行集成测试，并用实际外部服务验证投递。
8. 浏览器检查巡检按钮在四主题、hover/focus/disabled/缩放情况下没有紫色填充；测试系统管理二级导航在常用分辨率下不溢出、不遮挡内容。
9. Windows 安装、备份目录 NTFS ACL、密钥轮换恢复与日志脱敏验收。

## 4. 验收结论

当前版本继续保持 `2.14.0-rc.1`。只有上述 Gate 有可复核证据且没有未解决高风险问题后，才可以评估正式发布。
