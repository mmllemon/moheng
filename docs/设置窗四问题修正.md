## 问题 1：纸纹没有了

### 我的错

上一轮我把 `settings-window::before/::after` 的纸纹规则整个删掉了，理由是「hana 的 SettingsModalShell 里没有 paper-texture 声明」。

**这个理由只对了一半。** 查证结果：

```
SettingsModalShell-m7fTbt85.css 里 paper 相关只有 7 处：
  6 处是 ._theme-card_a8612[data-theme=warm-paper] 的主题预览卡
  1 处是 --paper-texture-surface: var(--bg)      ← 这个才是关键
```

`--paper-texture-surface: var(--bg)` 意味着**设置窗声明自己是一张纸**，纸纹由外部组件渲染。

### hana 的纸纹是独立 DOM 组件

```js
// CapabilitiesPanel-La2h94hS.js
const Od = "_layer_0d743", $d = "_hi_12639", Bd = "_lo_28564",
      Hn = { layer: Od, hi: $d, lo: Bd };

function Hd({ scope } = {}) {
  return jsxs("div", {
    className: Hn.layer,
    "aria-hidden": "true",
    "data-paper-texture-layer": "",
    "data-paper-scope": scope,
    children: [jsx("div", { className: Hn.hi }), jsx("div", { className: Hn.lo })]
  });
}
```

```css
._layer_0d743 {
  position: absolute;
  inset: 0;
  z-index: var(--z-under);     /* = -1 */
  pointer-events: none;
  border-radius: inherit;
  display: none;
}

html[data-paper-texture] ._layer_0d743:not([data-paper-scope]) { display: block; }

._hi_12639, ._lo_28564 {
  position: absolute;
  inset: 0;
  mask-repeat: repeat;
  mask-composite: add;
  mask-size: var(--paper-texture-mottle-tile),
             var(--paper-texture-fiber-tile),
             var(--paper-texture-grain-tile);
}

._hi_12639 {
  background: oklch(from var(--paper-texture-surface)
                    calc(l + var(--paper-texture-peak) * var(--paper-texture-strength, 1)) c h);
}

._lo_28564 {
  background: oklch(from var(--paper-texture-surface)
                    calc(l - var(--paper-texture-peak) * var(--paper-texture-strength, 1)) c h);
}
```

### 关键：`z-index: -1`，不是 0

`--z-under: -1`。纸纹在内容**下方**。

我第一次恢复时写成 `z-index: 0`，结果纸纹与内容同级、盖住内容，视觉上是「砂纸」。

### 修正

```css
.settings-window {
  --paper-texture-surface: var(--bg);
  isolation: isolate;          /* 建立层叠上下文，让 -1 不外泄 */
}

.settings-window::before,
.settings-window::after {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;                 /* 关键：对齐 --z-under */
  pointer-events: none;
  display: none;
  border-radius: inherit;
  mask-repeat: repeat;
  mask-composite: add;
  mask-size: var(--paper-texture-tile-size);
}

html[data-paper-texture] .settings-window::before,
html[data-paper-texture] .settings-window::after { display: block; }

.settings-window::before {
  background: oklch(from var(--bg) calc(l + var(--paper-texture-peak) * var(--paper-texture-strength, 1)) c h);
  mask-image: var(--paper-texture-mask-hi);
}

.settings-window::after {
  background: oklch(from var(--bg) calc(l - var(--paper-texture-peak) * var(--paper-texture-strength, 1)) c h);
  mask-image: var(--paper-texture-mask-lo);
}
```

实测：`content="" display=block z=-1 mask=true`，`window isolation=isolate`。

## 问题 2：标题栏太高 / 可能有两个 / 与页面边缘距离不对

### 三个子问题，逐一核查

**① 「两个标题栏」的真相**

实测层级：

```
app-titlebar     z=50   y=6   h=44   底部 50
settings-overlay z=8000 y=0   h=900
settings-window  y=30
```

`elementFromPoint` 在 app-titlebar 位置返回 `settings-overlay`，**顶栏确实被遮住了**。

但**设置窗从 y=30 开始，而 app-titlebar 在 y=6~50**，所以窗口上方那 30px 空白区里，顶栏的模糊残影仍可见。

这不是「两个标题栏」，是**overlay 的 scrim 太淡 + blur 太弱**。

hana 的真值：

```css
._overlay_652af._open_aab08 {
  background: radial-gradient(circle at 50% 42%, #f8f5ed1a, #14120e29 62%, #14120e3d), #14120e33;
  backdrop-filter: blur(8px);
}
```

moheng 原来：

```
blur(6px) + rgba(20,18,14,0.16)   ← 都更弱
```

已改为 hana 的 `blur(8px)` + `#14120e33`（≈20%）。

**② 标题栏高度 52px 是对的**

hana `._titlebar_7cee1 { min-height: 52px }`。实测 moheng `titlebar: y=31 h=52`，**完全一致**。

**③ 内边距的真实问题：content 的 padding 被旧规则覆盖**

CDP 查到 `.settings-content` 命中两条 padding：

```
[.settings-content]  padding: 0 var(--settings-content-inset, 40px) 40px   ← 我改的（正确）
[.settings-content]  padding: 24px 40px 32px                              ← 旧规则，后加载，赢
```

已删除旧规则。实测现在是 `0px 40px 40px`，与 hana `._main_e2ed0` 一致。

**④ 导航搜索框与边缘的距离**

实测：`nav padding=8px`，`searchWrap x=249`，`nav x=241` → **内缩 8px**。

hana `._nav_cb688 { padding: var(--space-8) }` = 8px。**已一致，无需改。**

## 问题 3：侧栏按钮圆角不一致

### 根因：被 `.button` 系列的 `!important` 压住

CDP 查到 `.settings-nav-link` 命中两条：

```
[.settings-nav-link]
  border-radius: calc(var(--radius-input) * var(--corner-radius-scale, 1))
  corner-shape: squircle

[.button, .button-primary, ..., .panel-heading ...]
  border-radius: calc(var(--radius-action) * var(--corner-radius-scale, 1)) !important
  corner-shape: round !important
```

**后者的 `!important` 赢了**，所以实际是 `5px × 1.8409 = 9.20448px` + `round`。

hana 的 `._item_c6fac`：

```css
border-radius: calc(var(--radius-input) * var(--corner-radius-scale, 1));   /* 6 × 1.8409 = 11.0454px */
corner-shape: squircle;
```

### 修正

```css
html .settings-nav .settings-nav-link {
  border-radius: calc(var(--radius-input) * var(--corner-radius-scale, 1)) !important;
  corner-shape: squircle !important;
}
```

实测：`radius=11.0454px  corner=superellipse(2)` ✓

## 问题 4：滑动条组件完全不对

### 两件事要分清

用户说的「很细很短、在页面最边缘、卡片最边缘」，指的是**两个不同的东西**：

| | 组件 | 位置 |
|---|---|---|
| 设置项里的滑块 | `input[type=range]` | 卡片内部 |
| 页面的滚动条 | `::-webkit-scrollbar` | 卡片最右缘 |

### 4a. 滑块：moheng 是「分段轨道」，hana 是「连续轨道 + 圆滑块」

moheng 原实现：

```
.settings-step-rail { display: flex; gap: 4px; height: 4px; }
.settings-step-rail span { flex: 1; height: 4px; border-radius: 99px; }
.settings-step-rail span.is-on { background: var(--accent); }
```

**4 个 49px 的独立 span 拼接，靠 `.is-on` 上色，形成阶梯感。**

hana 真值：

```css
/* 轨道 */
._barTrack_85f7c {
  width: 100%; height: 6px; overflow: hidden;
  background: var(--bg-main, #faf8f5);
  border-radius: 3px; corner-shape: round;
}

/* 滑块 */
._input_143b0 {
  --step-slider-thumb: 14px;
  --step-slider-track: calc(var(--step-slider-thumb) / 3.5);     /* 4px */
  --step-slider-rail-height: calc(var(--step-slider-thumb) + var(--space-8));  /* 22px */
  width: 100%; height: var(--step-slider-rail-height);
  margin: 0; padding: 0; appearance: none; background: transparent;
}

._input_143b0::-webkit-slider-thumb {
  appearance: none;
  width: var(--step-slider-thumb);      /* 14px */
  height: var(--step-slider-thumb);
  margin-top: calc((var(--step-slider-track) - var(--step-slider-thumb)) / 2);
  border: 2px solid var(--bg-card);     /* 白色描边 */
  border-radius: 999px; corner-shape: round;
  background: var(--accent);
  box-shadow: var(--shadow-xs);
}

._input_143b0:hover::-webkit-slider-thumb {
  transform: scale(1.08);
  box-shadow: var(--shadow-xs), 0 0 0 4px color-mix(in srgb, var(--accent) 16%, transparent);
}
```

**已完整重写。**

### 4b. 滑块 input 被全局 input 规范压住

CDP 查到三层覆盖：

```
① html .settings-step-slider input { height: 32px; min-height: 32px; padding: 0 10px }
② input:not([type=checkbox]):not([type=radio]) { min-height: 34px; padding: 6px 9px;
   border: 1px solid var(--line-2); border-radius: 3px; background: #fffdf7 }
③ .settings-step-slider > input { height: var(--step-slider-rail-height) }
```

结果：input 是 **34px 白底带边框的方块**，完全不像滑块。

修正：

```css
html .settings-step-slider > input {
  height: var(--step-slider-rail-height) !important;   /* 22px */
  min-height: 0 !important;
  padding: 0 !important;
  border: none !important;
  border-radius: 0 !important;
  background: transparent !important;
  box-shadow: none !important;
}
```

实测：`input 22px / bg=transparent / appearance=none` ✓

### 4c. 滚动条：moheng 用 `thin`（约 8px）且常驻可见

hana 的真值：

```css
/* mobile-kfy_1ie4.css */
*::-webkit-scrollbar { width: 4px; height: 4px; }

  background: #80808040;
```

**默认完全透明，悬停或滚动中才显色。**

修正：

```css
* {
  scrollbar-width: auto;
  scrollbar-color: transparent transparent;
}

::-webkit-scrollbar { width: 4px; height: 4px; }
::-webkit-scrollbar-track { background: transparent; }
::-webkit-scrollbar-thumb {
  background: transparent;
  border-radius: 99px;
  corner-shape: round;
  transition: background var(--duration-slow) ease-out;

:hover::-webkit-scrollbar-thumb { background: #80808040; }
::-webkit-scrollbar-thumb:hover { background: #80808066; }
```

### 4d. 自定义滚动条组件是死代码

CDP 查到 `.settings-scrollbar` 是 `display: none` 且 `0×0` —— **JS 从未初始化它**。

而且它定位在 `position: absolute; right: 2px`（相对窗口），不是内容区右缘。

已改为：

```css
.settings-scrollbar,
.settings-scrollbar span { display: none !important; }
```

统一走原生 `::-webkit-scrollbar`。

## 这一轮的方法教训

**四个问题里有三个是「我以为改对了，其实被更高优先级规则压住」。**

| 问题 | 我改的 | 实际生效的 |
|---|---|---|
| 导航项圆角 | `.settings-nav-link`（0,1,0） | `.button` 系列 `!important` |
| 滑块 input | `.settings-step-slider > input`（0,1,1） | `input:not()×2`（0,2,1）+ `html` 前缀（0,2,1） |
| content padding | 新规则（0,1,0） | 旧重复规则（0,1,0，后加载） |

**共同点：只改了「应该改的那条规则」，没验证「它是否真的赢了」。**

正确做法：**每次改完 CSS，用 `CSS.getMatchedStylesForNode` 确认最终生效的是哪一条**，而不是看 computed value 符合预期就认为自己的规则生效了 —— 因为巧合也能算出同样的值。
