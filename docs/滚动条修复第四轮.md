# 滚动条修复（第四轮：两个 bug + 找到 hana 真实写法）

日期：2026-10-23

用户报告：
1. 设置窗滚动条有了，但有时候页面刷新后，滚动时看不到滚动条
2. 主页面滚动时没看到滚动条

---

## 一、两个 bug 的根因

### bug 1：主内容区从未接入

`useScrollIndicator` 只挂在设置窗：

```ts
useScrollIndicator(settingsContentRef, { selector: '.route-transition' });
```

主内容区的滚动容器（`.app-content > .route-transition`，第 760 行）**根本没有接入**。

### bug 2：刷新后失效（时序问题）

```ts
useScrollIndicator(ref, { ... })

useEffect(() => {
  const host = ref.current;
  if (!host) return;          // ← 这里 return 后就永久失效
  ...
}, [ref, className, delay, selector]);   // ← ref 是稳定引用，effect 只跑一次
```

`ref` 对象在整个组件生命周期内是同一个引用，所以 effect **只在首次挂载时执行一次**。

而首次挂载时如果不在设置区，设置窗根本没渲染，`ref.current` 是 `null` → 直接 `return` → **永不重试**。

表现：直接进设置页时正常，刷新后（或从主页进设置）失效。

---

## 二、修法：改挂 document 捕获阶段

```ts
export function useScrollIndicator({ className = 'is-scrolling', delay = 800 } = {}) {
  useEffect(() => {
    const onScroll = (event) => {
      const node = event.target;
      if (!(node instanceof HTMLElement)) return;
      if (!isScrollable(node)) return;
      node.classList.add(className);
      ...
    };
    document.addEventListener('scroll', onScroll, { passive: true, capture: true });
    ...
  }, [className, delay]);
}
```

关键点：

| 做法 | 效果 |
|---|---|
| 挂 `document` 捕获阶段 | `scroll` 不冒泡，但捕获阶段能从 document 收到所有后代滚动 |
| 不依赖 ref | 路由切换、窗口开关、刷新都自动覆盖 |
| 判 `scrollHeight > clientHeight` | 只处理真正在滚的元素 |

---

## 三、但最终发现：这套机制在 Chrome 里没用

修好两个 bug 后，实测三态：

```
① 静默     cls="route-transition"              R=247
② 滚动中   cls="route-transition is-scrolling" R=206   ← 显现
③ 1.2s 后  cls="route-transition"              R=206   ← 类已移除，但仍显色
```

**类移除后滚动条不会变回透明。** 做了四组对照：

| 尝试 | 结果 |
|---|---|
| 改视口尺寸 | 仍 206 |
| 滚回顶部 | 仍 206 |
| 强制 reflow | 仍 206 |
| 去掉 `transition` | 仍 206 |

**结论：Chrome 对 `::-webkit-scrollbar-thumb` 的 background 变化只在滚动/重绘时生效，一旦显色就不会再变回透明。**

所以「默认 `transparent` + 滚动时显色」这条路在经典滚动条模式下走不通，反而会留下一条永远显色的线。

## 四、hana 的真实写法

回到 `styles.css` 第 267-273 行，也就是「基础重置」章节：

```css
*, *::before, *::after {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
    scrollbar-width: thin;
    scrollbar-color: rgba(128, 128, 128, 0.2) transparent;
}
```

**thumb 默认就是 20% 灰，不是透明的。** 然后再按平台追加伪元素细化：

```css
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar {
    width: 4px; height: 4px;
}
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar-thumb {
    background: rgba(128, 128, 128, 0.2);
    border-radius: 2px; corner-shape: round;
}
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar-thumb:hover {
    background: rgba(128, 128, 128, 0.4);
}
```

**hana 的滚动条是常态可见的 20% 灰，不是隐藏的。**

那用户看到的「平常不显示、滚动才显示」从哪来？

**Electron 的 OverlayScrollbar。** 实测：

| 启动参数 | 滚动条占位 |
|---|---|
| 普通 Chrome 默认 | **17px** |
| `--enable-features=OverlayScrollbar` | **2px** |

Electron 默认开启该特性。所以 hana 在 Windows 上看到的是系统 overlay 滚动条：静默自动隐藏、滚动淡入、约 6px 宽。

**这是平台行为，不是 CSS。**

---

## 五、最终实现

两条路实测对比：

| 方案 | 占位宽 | 能否到 4px |
|---|---|---|
| `scrollbar-width: thin` | 10px | ✗（标准属性最小值） |
| `::-webkit-scrollbar` | 4px | ✓ |

取后者，因为 hana 的视觉特征就是「细」：

```css
*::-webkit-scrollbar {
  width: 4px;
  height: 4px;
}

*::-webkit-scrollbar-track {
  background: transparent;
}

*::-webkit-scrollbar-thumb {
  background: rgba(128, 128, 128, 0.2);
  border-radius: 2px;
  corner-shape: round;
}

*::-webkit-scrollbar-thumb:hover {
  background: rgba(128, 128, 128, 0.4);
}
```

**关键：thumb 不能设 `transparent`。** 设了就会踩上「显色后不消失」的问题。

**注意：不能同时声明 `scrollbar-width` 和 `::-webkit-scrollbar`。** 一旦声明前者，Chrome 就改用标准滚动条并忽略伪元素宽度。

## 八、顺带修复：我误删了正式脚本

清理临时文件时用了 `Remove-Item scripts\_t*.mjs`，把正式的 `scripts/_targets.mjs` 一起删了（双 target 启动器），导致 `ui-visual-regression.mjs` 报 `ERR_MODULE_NOT_FOUND`。

已重建，补齐三个接口：

```js
export const CORNER_SHAPE_MIN_CHROMIUM = 139;
export function chromiumMajor(ua) { ... }
export async function assertApiUp() { ... }       // 端点是 /health，不是 /api/health
export async function launchTarget(kind) {
  return { kind, page, pageErrors, open, newMobilePage, close };
}
```

实测恢复：`routes=26 failures=0`。

**教训：`Remove-Item _t*.mjs` 这种通配符会命中正式文件。清理前必须列出待删清单核对。**

## 十、这一轮的方法教训

**用户描述的观感，可能来自平台而非代码。**

| 用户说的 | 我一开始以为 | 实际来源 |
|---|---|---|
| 「平常不显示，滚动才显示」 | CSS 控制显隐 | Electron OverlayScrollbar 的系统行为 |
| 「很细很短」 | 4px 宽度设定 | overlay 滚动条 + 4px 伪元素宽度的叠加 |

如果一开始就去查「hana 在 Windows 上跑在什么容器里」，能省掉三轮试错。

**另一个教训：不要用 CSS 实现浏览器明确不支持的行为。**

我花了很多轮试图让 thumb「显色后再变透明」，甚至测了改视口、强制 reflow、去 transition 三种强制重绘手段，全部无效。这时候应该立刻判断「这是浏览器限制」并改方案，而不是继续找 CSS 技巧。
