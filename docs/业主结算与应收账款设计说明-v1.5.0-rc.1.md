# 业主侧竣工结算与应收账款模型设计说明

- 系统：筑衡｜施工单位成本管理系统
- 版本：MVP 1.5.0-rc.1 验证候选
- 范围：业主侧竣工结算、合同结算调整、应收账款、应收分期、到账/退款、业主预付款、质保金释放，以及与进度款历史账本的衔接。

## 1. 核心业务原则

1. 主合同、进度款、结算确认金额、应收账款、实际到账、退款、预付款、质保金和实际成本属于不同的业务事实，不得用某一个金额替代其他口径。
2. 结算清单明细可选。没有工程量清单、预算清单或合同明细编码的合同，仍可以用结算单头金额完成完整确认与过账流程；有可选行时，明细合计必须与报审金额一致。
3. 阶段进度款核定形成独立应收；最终结算的确认金额代表主合同最终累计结算金额。过账时只记本次增量 `delta = finalCumulative - previousRecognizedCumulative`，不得把最终累计值再次累加。
4. 调整结算可以是正数或负数。已过账记录不得原位改写，应创建可追溯的调整单。
5. 正式应收只由进度款核定、结算过账、质保金释放或有授权的人工调整形成。预付款到账单独进入预付款账本，不自动伪造成应收核销。
6. 实际到账必须核销到一个正向应收单；退款必须关联原到账，并按原分配关系反向恢复核销。
7. 收款金额必须同时受所选应收单余额和主合同层面的净应收余额控制。负向调整不被隐藏，而是单独展示为待返还/抵销；它会减少合同层面还可继续收取的净余额。
8. 进度款页面的旧到账入口在最终结算过账后停止新增到账，统一引导到“竣工结算与应收”按应收单收款，避免绕过最终结算后的合同净余额校验。
9. 质保金留置、释放和核销是独立流水。释放产生应收，不等于实际到账；释放必须满足最终结算及余额条件。
10. 业主预付款单独记录到账和结算扣回，发票/税额与到账及实际成本分别核对，不自动生成成本。

## 2. 核心模型

- `OwnerContractSettlement`：阶段/最终结算或调整单，记录报审金额、外部确认金额、流程状态、凭证、扣回/留置/扣款及过账数值。
- `OwnerSettlementLine`：可选结算说明行；不依赖合同清单或预算清单。
- `OwnerSettlementPosting`：不可覆盖的累计前值、本次增减和累计后值快照，单据 ID 唯一，防止重复过账。
- `OwnerReceivable`：正式应收单，来自进度款、最终结算、调整或质保金释放。
- `OwnerReceivableSchedule`：可选到期期次。分期设置前必须未发生到账核销，分期金额合计必须与该应收单净额一致。
- `OwnerReceipt`：实际到账、退款或预付款收款流水。
- `OwnerReceiptAllocation`：到账到应收单/期次的分配；退款用负向分配引用原分配记录。
- `OwnerRetentionMovement`：质保金留置、释放、核销流水。
- `OwnerAdvanceMovement`：业主预付款到账、扣回和退回流水。
- `DocumentSequence`：按项目、业务类型和业务日期年份生成并发安全的业务编号。

## 3. 最终结算算法

设历史已过账进度款核定金额和结算调整金额的有符号累计值为 `P`，最终累计确认金额为 `F`：

`本次最终结算增量 = F - P`

例如，阶段确认 300 万与 200 万后，历史累计为 500 万；最终确认 470 万时，仅过账 -30 万。系统保留原两笔阶段应收与最终负向调整记录，不覆盖历史数据。

正向应收净额：

`应收净额 = 本次正向结算增量 - 预付款扣回 - 质保金留置 - 已批准其他扣款`

负向调整不能重复填写扣回/留置/扣款，以防双重扣减。所有金额采用 Decimal 金额存储，业务计算按分转换为整数分处理。

## 4. 应收与到账口径

- 单笔未收/待返还余额 = 应收净额 - 分配到该应收单的到账核销净额。
- 主合同净应收敞口 = 同一主合同所有应收单未收/待返还余额的有符号合计。
- 可登记普通到账 = 不超过所选正向应收单的未收余额，且不超过主合同净应收敞口。
- 因而存在负向最终调整时，不能继续按照旧进度款原核定金额收满款项。负向调整与正向应收会在明细中分别展示，跨应付/应收的正式自动抵销流程尚待企业确定后进一步细化。
- 退款保留原到账和退款两笔流水，并反向恢复原分配的应收及期次余额。针对进度款来源的退款同步形成 `ProgressPayment` 负向历史行，确保旧进度款页不再只显示退款前的到账金额。
- 已有历史进度款的应收回填仅在可以可靠关联主合同并获得有效金额基线时执行。无法建立可靠关联的旧记录不会被伪造应收，应列入人工核对。

## 5. 状态与权限

结算状态：`DRAFT → SUBMITTED → INTERNAL_APPROVED → COUNTERPARTY_CONFIRMED → POSTED`。驳回返回可编辑状态；已过账单据不可原位修改。

写入操作按项目权限执行，并限制提交人自审。金额统计的 API 和 UI 都须遵守同一项目权限范围。业务编号不是数据库主键；数据库 `id` 为内部稳定关联键。
