# 阶段验收记录：v1.2.2-rc.3（集成验收前静态检查）

## 1. 本轮范围

本候选版本继续以 Windows 原生部署为优先路径，重点核对合同基准不可覆盖、旧数据库基准修复、外部确认金额差异复核快照，以及 Prisma schema 与迁移文件的一致性。

## 2. 本轮处理

1. 正式主合同建立后，不允许通过项目资料编辑或主合同接口改写原始合同金额；合同变更只能登记为变更签证并按外部确认生效规则计入。
2. 保持已交付迁移 `20261013020000_contract_change_external_confirmation` 原文件不变。新增 `20261013030000_reconcile_original_contract_amount`，在正式主合同存在时优先采用主合同台账金额作为原始基准，重算当前有效合同额，并在 `ContractBaselineMigrationReconciliation` 保存修复前后基准金额和有效合同额。重算结果为负数或超过 `DECIMAL(18,2)` 上限时，迁移会报错并中止，要求先核对数据。
3. `20261013040000_internal_amount_review` 新增金额差异复核字段，并为历史已生效但内部参考金额与外部确认金额不同的记录自动建立待复核状态，不覆盖外部确认金额，也不撤销原生效状态。
4. 金额差异复核保存触发当时的内部参考金额、外部确认金额快照；复核界面和审计动作使用这组快照，防止内部金额后续变化后显示出与触发原因不一致的差异。
5. 新增 `npm run validate:release-candidate` 静态检查，核对候选版本、已交付迁移文件哈希、迁移顺序、schema、API 规则和差异复核动作。

## 4. 在 Windows 测试环境执行

在隔离测试数据库上先做完整备份，然后从项目根目录执行：

```powershell
node --version   # 应为 Node.js 24 LTS
npm --version
npm install
npm run validate:release-candidate
npm run db:generate
npm run lint
npm run build
npm test
npm run db:deploy
npm run db:seed
```

随后启动 API，并请求 `http://localhost:3001/health`。本轮并未运行以上 Windows 命令；必须保存实际执行输出，不得仅凭本报告认定这些步骤已通过。

## 5. 数据库迁移核对

迁移前先备份数据库。在测试数据库迁移后核对有发生变化的项目：

```sql
SELECT
  "projectId", "previousOriginalAmount", "mainContractAmount",
  "reconciledOriginalAmount", "previousEffectiveAmount",
  "reconciledEffectiveAmount", "reason", "createdAt"
FROM "ContractBaselineMigrationReconciliation"
ORDER BY "id";
```

该台账仅记录基准或有效合同额被修正的项目；结果不为零时，应与正式主合同及已生效外部确认清单逐项核对。若迁移因负数或金额上限而失败，应停止升级并先解决异常项目，不能跳过迁移或手工把有效合同额改成外部确认金额以外的数字。

历史差异待办可用下列 SQL 核对：

```sql
SELECT "projectId", "code", "externalConfirmedAmount",
       "internalAmountReviewReferenceAmount", "internalAmountReviewExternalAmount",
       "internalAmountReviewStatus"
FROM "Change"
WHERE "externalConfirmationStatus" = 'EFFECTIVE'
  AND "internalAmountReviewStatus" = 'PENDING'
ORDER BY "projectId", "code";
```
