# 墨衡下一阶段开发计划与实施记录

- 基线：`v1.8.0-rc.1`
- 依据：用户提供的《施工单位成本管理系统完整设计方案 v1.0》（2026-10-12）
- 本轮目标版本：`v1.9.0-rc.1`
- 原则：保留现有业务流程、数据模型、接口和财务口径；只补齐可安全叠加的能力。文档中的目标设计不是已实现功能的证明。

## 1. 当前完成度与对齐度判断

以下是对当前源码形态的定性评估，不是通过自动化测试计算的百分比：

| 维度 | 当前判断 | 已有基础与主要缺口 |
|---|---|---|
| 施工经营核心业务 | 中高 | 项目、主合同、目标成本、进度款、变更签证、实际成本、成本分析、业主竣工结算/应收，以及分供合同、结算/应付、付款退款、质保金、预付款、发票核验已有页面和接口。材料库存/价格、完整报表中心仍缺失。 |
| 合同与财务规则 | 已有较多专门规则 | 已区分原始与有效合同金额，变更内部审批与外部确认分离；分供与业主结算、应收/应付、退款冲回、质保金和预付款有独立模型及测试。不能用设计稿中的简化 Project/合同字段替代这些模型。 |
| 全局导航与视觉设计 | 中高 | 已有跨项目经营总览、项目工作台、四套主题、自绘下拉/日期控件、密度设置、命令面板和受控动效。TanStack Table、Radix 并非当前依赖；不为对齐技术名词重写现有可用表格/控件。 |
| 审计与追溯 | 后端部分已有、面向用户的查询不足 | `AuditLog` 模型和多条业务写入路径已经存在；经营总览只展示少量摘要，缺少可筛选的完整记录、变更快照详情及导出入口。此项作为本轮实施内容。 |
| Excel 数据交换 | 部分 | 目标成本有 CSV 导入；缺少统一导入预览/字段映射/逐行错误反馈，以及多个关键台账的导出。原生 `.xlsx` 并未实现，不能将 CSV 能力写成完整 Excel 工作簿能力。 |
| 项目权限管理 | 数据与 API 有基础，管理体验不完整 | `ProjectMember` 和项目角色/访问校验已存在；项目成员管理与权限矩阵的完整用户界面需单独补齐。 |
| 平台运营能力 | 较低/待规划 | 通知规则、完整报表中心、异步报表任务、字典管理、备份恢复工作流和离线写入尚未完整实现。它们依赖额外业务口径或基础设施，不能只加按钮。 |
| 生产验收 | 未完成 | 当前执行环境 Node.js 22，项目包要求 Node.js 24+；完整依赖安装、类型检查、前后端生产构建、Prisma/真实 PostgreSQL 联测、浏览器 E2E 与 Windows 实机验收仍需执行。 |

**总体结论：** 主要施工经营主线已成型，界面与关键业务规则有较强对齐；但 v1.0 文档覆盖面明显大于当前 MVP，不能称为全量实现。当前最明确且不冲突的缺口之一，是把已有审计数据变成用户真正能检索和导出的业务工具。

## 2. 需要尊重的项目现状与不直接照搬项

1. **运行时版本**：设计稿写 Node.js 20，当前仓库 `engines` 明确要求 Node.js 24+。本轮不降低运行时要求；降级必须单独做依赖、Prisma、构建与 Windows 部署兼容验证。
2. **既有账务模型**：当前模型比方案文档中的简化示例更细，尤其合同原始金额/有效金额、变更外部确认、业主结算过账、分供应付/付款分配、预付款、质保金和退款冲销。后续不通过“重做 Schema”来追求字段表面一致。
3. **基础设施**：文档列举 Redis、MinIO/OSS、BullMQ；当前 Windows 原生路径有意不依赖这些服务。尚未证明确有容量或任务处理瓶颈前，不新增强制基础设施。
4. **UI 组件框架**：文档提到 Radix UI、TanStack Table；当前项目使用自绘且可主题化的 `SelectField`/`DatePicker` 与现有表格。先补行为和测试，不为依赖对齐进行大面积组件替换。
5. **离线写入**：合同、财务状态和审计需要一致性、幂等及冲突处理。未建立同步协议前，不启用可离线提交财务写操作的 PWA，避免重复记账或冲突覆盖。
6. **预测指标**：当前实际成本/合同金额等快照不能自动等同于工程实物进度、完工预测或正式利润预测。未建立可靠数据口径前，界面继续显示“暂无基线/—”，不造数。

## 3. 下一阶段路线图（按风险和依赖排序）

### WP1 — 操作追溯查询与导出（本轮实施）

**目的**：让已记录的审计数据对项目管理者和业务人员可见，同时不触碰业务状态机。

- 新增只读查询 API，按当前用户项目访问权限自动限域；支持项目、业务对象、关键字、日期筛选和分页。
- 新增全局“操作追溯”页面，展示操作者、项目、业务对象、动作、时间和变更摘要；可展开只读 JSON 变更快照。
- 支持 UTF-8 BOM CSV 导出，兼容常用表格工具；对公式型单元格做注入中和，每次最多导出最新 5,000 条匹配记录。
- 经营总览的最近操作区域增加“查看全部”入口。
- 不新增数据表/迁移；不写入、不编辑或删除审计记录。

**依赖**：当前 `AuditLog` 模型和既有写入点。

**机械验收**：权限过滤在服务端执行；非管理员不能查询未授权项目 ID；日期格式和范围错误返回 400；跨项目默认结果只包含可访问项目；CSV 通过引号/逗号/换行处理和公式注入测试；展示与导出会递归隐藏凭证类敏感键；分页稳定按时间倒序；新增页面有加载、错误、空态；无 schema/migration 变更。

### WP2 — 关键台账导出先行，再建设标准导入

- 首批：目标成本、实际成本、进度款、变更签证、业主应收/收款、分供结算/应付分别输出字段说明和导出列集。
- 先提供带 UTF-8 BOM、明确金额精度和日期格式的 CSV 导出；明确它是 Excel 可打开的 CSV，不宣传为原生 `.xlsx`。
- 每类导出要遵守当前项目权限及筛选范围；敏感字段按最小必要原则选择。
- 之后再统一导入流程：模板下载 → 文件预检 → 列映射确认 → 逐行错误列表 → 用户确认后一次事务导入 → 结果摘要/审计记录。不得把“直接导入 CSV”扩写成已有导入预览能力。

**Gate**：无预览/映射/错误行报告的导入不得进入正式主数据或金额台账；CSV 导出需验证中文、日期、负数金额、特殊字符和公式注入。

### WP3 — 项目成员与角色管理 UI

- 利用当前 `ProjectMember` API 和项目角色，增加按项目查看/添加成员、角色更新与权限说明。
- 服务端继续做权限校验；UI 仅隐藏按钮不视为权限控制。
- 验收包括同一用户不同项目角色可不同、越权修改返回 403、重复添加不会产生重复成员、审批/确认的既有自审批限制不变。

### WP4 — 审计覆盖率补齐与业务可追溯性测试

- 依据所有 API 的 create/update/status/post/refund/archive 路径逐项审计：金额变更前值/后值、执行人、时间、关联业务编号是否足够。
- 对尚未写审计的操作追加与业务修改同事务的审计记录；已过账/退款等不可逆操作应保留快照，不修改旧记录。
- 为合同金额、业主应收、分供应付、退款分配建立可重复的集成测试清单。

**Gate**：高风险财务写操作必须有成功审计；失败的业务事务不得留下“成功修改”审计记录；原始记录不可物理删除。

### WP5 — 经营预警与通知中心

- 先冻结事件定义：应收逾期、进度款申报周期、合同到期、待内部审批、外部确认待补件、目标成本超支阈值。
- 首阶段做系统内待办列表与可点击钻取；明确时区、重复提醒、已处理状态和权限。
- 邮件/即时消息、定时后台任务等外部推送晚于站内待办，避免为了通知先引入队列/Redis。

### WP6 — 报表中心与异步生成（按需）

- 先以可重复的同步 CSV 报表定义字段/汇总口径；为生成耗时或大文件设置实测阈值。
- 只有在真实报表耗时/容量证明需要后，再选择 PostgreSQL 任务表、BullMQ 或其他队列；不要将新增 Redis 作为当前部署前提。

### WP7 — PWA/离线录入（延后）

- 先建立本地草稿与只读缓存的范围定义；财务正式提交仍要求在线。
- 要进入离线写入必须先设计幂等键、冲突检测、版本号、同步重试和人工合并 UI，并验证重复同步不会双记账。

### WP8 — 正式验收与部署门禁

- Node.js 24+ 锁依赖、全量类型检查、前后端 production build。
- Prisma validate/generate + 空库迁移 + 备份恢复演练。
- 浏览器 E2E：权限、合同金额、业主/分供结算、退款冲销、日期/下拉控件与命令面板。
- Windows 实机：凭证路径 ACL、启动/停止脚本、会话刷新、数据库断连恢复和日志。

## 4. 本轮实际实施记录

已实施 WP1 的第一版：

- `GET /api/audit-logs`：管理员可检索全局/项目日志；普通用户的查询被限制到自己有成员关系的项目。可筛选项目、业务对象、关键字和日期，并分页排序。
- `AuditLogsPage.tsx`：新增左侧导航入口，提供摘要指标、筛选、详情快照展开、分页、加载/错误/空态和 CSV 导出。
- 经营总览“最近操作”增加“查看全部”。
- CSV 导出使用 BOM、标准 CSV 双引号转义，对公式开头的单元格加前缀中和；API 响应与导出快照递归隐藏密码、令牌、密钥、Cookie、Authorization 等敏感键；限制每次导出最多 5,000 条。
- 新增 CSV 单元测试和静态候选检查；没有 Prisma Schema 或 migration 改动。

## 5. 未在本轮宣称完成的事项

- 审计写入点虽已覆盖多条财务/台账写路径，但本轮没有对所有操作逐个证明完整；WP4 仍需要路线级覆盖清单。
- CSV 不是原生 Excel `.xlsx`；统一导入预览/映射和全部关键模块导出仍属于 WP2。
- 本轮静态/纯函数测试不能替代 Node.js 24+ 完整类型检查、生产构建、PostgreSQL 权限集成测试及浏览器 E2E。
