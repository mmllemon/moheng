# 阶段验收记录（v2.12.0-rc.1）

## 结论

本轮完成统一基础字典和版本化参数配置的增量源码实现，当前为发布候选（RC）。静态契约检查与 TypeScript/TSX 语法解析通过不等同于完整类型检查、Prisma 迁移或生产环境验收。由于开发环境为 Node.js 22.16.0（项目要求 Node.js >=24）且未安装工作区依赖，本轮未声称完整 build/lint/test/Prisma/PostgreSQL/E2E 通过。

## 本轮落地

| 范围 | 已落地实现 | 边界 |
|---|---|---|
| 数据模型与迁移 | `SystemDictionary`、`SystemDictionaryItem`、`SystemParameterRevision`；作用域一致性 CHECK、版本唯一约束和单范围单发布版索引 | 必须在隔离 PostgreSQL 测试库执行迁移并生成 Prisma Client |
| 基础字典 | 内置种子、自定义分类/条目、固定编码、排序、启停、停用不删除；实际成本计量单位字段已读取 `MEASURE_UNIT` 提示选项，仍允许手动输入 | 现有核心财务枚举未被自动替换 |
| 参数配置 | STRING/NUMBER/BOOLEAN/JSON 类型校验；全局/项目范围；草稿/发布/归档；历史版本；回滚创建新草稿 | 不会自动改写合同金额或结算算法 |
| 生效解析 | 项目参数覆盖同键全局值；仅已发布版本参加解析；字典读取已在计量单位非核心输入字段落地 | 其他消费模块仍需按功能单独接入并补测试 |
| 权限 | 管理页面和写 API admin-only；业务只读 API 要求登录，项目值检查成员权限 | 浏览器/真实 JWT/项目越权 E2E 未执行 |
| 审计 | 字典增改、参数草稿、发布、回滚草稿均记录 AuditLog；参数真实值不复制到变更摘要 | 需要在 PostgreSQL 中实测事务与审计一致性 |
| 前端 | 系统管理概览、侧栏导航、基础字典页、参数版本管理页 | 浏览器视觉/交互实测未执行 |

## 静态验收项目

- 源码静态契约检查覆盖 schema/migration、路由注册、管理 UI 和导航、公共读取端点、权限边界、配置版本与发布状态、项目覆盖优先级、审计和 README/开发指南。
- TypeScript/TSX 将使用可用的 TypeScript transpile parser 做语法检查；它不是完整的类型检查。
- `git diff --check` 和针对性 Node 静态检查需在交付前执行，并将结果附于验证日志。

## 未执行 / 阻塞的验收

1. Node.js 24+ 的 `npm ci`、Prisma schema validate/client generate、API/Web `lint`、完整测试和生产 build。
2. PostgreSQL 16 空库和已有业务数据迁移；复核约束、索引、外键、内置字典种子及 migration deploy 回滚预案。
3. 管理员/普通用户、项目成员/非成员的真实认证 API 测试；发布并发、版本递增、回滚和 AuditLog 的数据库事务测试。
4. 浏览器端的表单错误、表格排序、键盘可达性、路由守卫及项目覆盖展示实测。
5. 其他业务模块的逐个接入。计量单位字段已试点接入字典只读 API；核心合同、变更、结算、付款与退款规则仍未被动态参数控制。

## 上线前 Gate

- Gate A：Node.js 24+ 严格 lint/build/test 与 Prisma validate/generate 全部通过。
- Gate B：隔离 PostgreSQL 执行迁移；基线数据、用户、项目、合同、收付与变更记录数量/关键金额对比无非预期变化。
- Gate C：验证同一范围同键最多一个发布版本、项目值覆盖全局值、草稿不生效、回滚创建新版本、并发冲突返回 409。
- Gate D：测试非管理员写入拒绝、非成员项目参数读取拒绝、ADMIN_ONLY 参数不出现在公共读取接口、停用字典不出现在公共读取接口、敏感参数键拒绝、审计日志不包含参数原值。
- Gate E：浏览器、Windows 部署、备份与恢复演练完成后再决定 RC 是否转正式版本。
