# 墨衡阶段验收记录 v2.8.0-rc.1

## 本轮交付范围

- 将“项目工作台”正式命名为“成本工作台”，核心前端布局组件改名为 `CostWorkspaceLayout`，新规范路由为 `/cost/*`。
- 增加 `/system`“系统管理工作台”首页，把项目档案、项目成员与权限、系统账号管理作为独立管理入口。
- 将项目成员管理从成本工作台页签中移除；项目成员和项目角色只在 `/system/members` 页面维护。
- 将 `/system/accounts` 定为公司级系统账号创建与列表的规范路由，不再重复提供项目角色分配；旧 `/settings/users` 保留兼容跳转。
- 为旧 `/workspace/*` 链接保留集中兼容重定向；旧 `/workspace/members` 转到 `/system/members`，旧 `/settings/users` 转到 `/system/accounts`，兼容重定向保留 query、hash 与 router state。
- 本轮未修改 Prisma Schema、数据库 migration、合同金额规则、成本/结算计算逻辑和既有服务端授权策略。

## 环境与尚未完成的验收

- 当前运行时为 Node.js `v22.16.0`，仓库声明要求 Node.js `>=24.0.0`。当前根目录不存在 `node_modules`。
- 实际尝试 `npm run lint` 和 `npm run build`，API TypeScript 编译因缺少 `@types/node`（`TS2688: Cannot find type definition file for node`）而失败；`npm run test` 因缺少 `tsx` 可执行文件而失败。这些是依赖/环境阻塞，不应记录为代码检查通过。
- 未完成可复现的依赖安装、Prisma Client 生成、数据库迁移、浏览器交互和 Windows 原生验收。
- 以上静态契约检查只能证明源码中预期的结构和规则存在，不能替代实际构建及端到端验证。因此版本继续保持 `2.8.0-rc.1`，不得标记为生产验收通过。

## 本轮权限边界回归要点

- `/system/members` 仍读取当前选中项目，并复用既有成员 API、角色可分配范围、最后一名项目负责人保护和审计记录逻辑。
- `/system/accounts` 仍在页面与侧栏受 ADMIN 约束，且不显示项目选择器；底层 API 授权不依赖隐藏菜单。旧 `/settings/users` 仅作兼容跳转。
- 系统账号创建不自动授予项目访问权限；项目成员管理与账号身份管理分离。
- 旧工作台地址跳转到规范路由，不产生独立的旧页面或重复业务实现。
