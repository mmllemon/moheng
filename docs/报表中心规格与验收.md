# 报表中心规格与验收

## 0. 实现边界

Web 设计器使用已锁定版本的 Univer 开源表格组件；服务端 XLSX 输出适配器使用 ExcelJS（仓库以 hardened alias 锁定依赖），共享服务端渲染层以保证预览与导出采用一致的数据/样式来源。工作区要求 Node.js 24+；具体依赖版本以根/API/Web 的 package.json 与锁文件为准。

## 1. 产品结构

报表中心按数据范围组织，不把项目级和公司级汇总混为一个视图：

- **项目级综合报表：** 当前选定项目的项目摘要、业主主合同、有效变更、目标成本、实际成本、进度款/应收/收退款、分供合同/结算/应付，以及与分供合同关联的付款/退款流水。
- **公司级经营报表：** 公司摘要、可访问项目清单、公司级业主收款/退款流水（保留原始收款关联）、跨项目分供合同/应付/实际付款与退款流水/成本/变更列表。服务端必须先按用户权限缩小项目集合。
- **往来单位经营档案：** 按统一往来单位 ID 汇总关联主合同、分供合同、结算、付款、发票和成本；未核验身份需要显著提示。
- 往来单位报表的进度款、收款流水、变更计数，以及分供合同的结算、付款、应付分配、成本和发票指标，应优先采用数据库聚合，避免为概览计算而将完整明细历史嵌套加载到应用内存。
- 聚合查询必须在数据库侧沿用当前用户的项目访问范围和单位归属条件；避免构造超过 PostgreSQL 参数上限的全量项目 ID 列表来计算汇总。
- 公司级与项目级数据查询应使用带权限条件的关系过滤，不应将全部可访问项目 ID 展开到每条明细查询的参数列表；项目级报表仍需限定到唯一指定项目。
- 项目级报表只读取指定项目及其必需字段；公司级项目概览只取汇总需要的项目字段，不加载各项目主合同明细；只有实际生成项目主合同源时才读取其所需字段。
- 公司汇总按项目组装时，应将有界明细一次性按项目 ID 分组后再遍历项目，避免在每个项目循环内重复扫描同一批明细数组。
- 往来单位关联项目与独立成本项目分布各自有 10,000 条输出上限；金额/记录总数必须通过独立完整聚合取得，不能用截断后的分组结果累加。无法确认全量项目/主合同数或相关汇总时，字段置空并明确提示。
- 付款口径必须保留底层流水符号规则：业主兼容进度款账中的退款以负数存储并直接净额相加；分供退款作为单独正数流水存储，必须从付款合计中扣除。

不是每份报表都必须包含全部数据源。模板决定要显示哪些字段；报表说明需揭示当前模板所用的数据范围、生成时间和限制。

## 2. 设计器能力

- 多工作表、可编辑单元格及工作表顺序。
- 集合字段按稳定主键/确定性顺序输出；同一项目、合同或流水的相关列必须来自同一条记录。
- 将来源字段绑定到任意单元格；单值数据源与集合数据源明确区分。
- 每个集合来源默认最多读取/渲染 10,000 行（由服务端设置的上限为准），预览可以采用更小的有界行数。超过上限必须明确提示，不得把部分数据伪装成完整汇总。
- 截断状态同时追踪受影响的集合来源和派生汇总字段；例如实际成本明细超限只影响实际成本合计，不应误标只使用累计收款的自定义报表。
- 模板未引用的截断集合不应污染本次报表的完整性状态或提示；模板绑定了被影响的集合，或绑定了具体不完整的汇总字段时，预览和 XLSX 总览页必须一致地提示。
- 重复区域可按其自己的数据集扩展；同一重复区域里的字段必须来自同一条记录；独立重复区域不能按数组下标错误拼接。
- 保留合并单元格、行高、列宽、字体、字号、粗体/斜体/删除线/下划线、文字与填充颜色、对齐、边框、数字/金额/日期格式、冻结窗格和打印页面配置。
- 模板有明确的 schema version；模板范围分为 PERSONAL（个人）、PROJECT（项目）和 SYSTEM（系统共享），且模板编辑/发布权限必须由服务端验证；模板与发布版本须可区分；报告导出不可绕过当前用户权限。
- 预览使用有界行数并提示截断；导出限制必须在工作簿中再次说明。

## 3. 财务数据源口径

- `downstreamPayables` / `companyDownstreamPayables` 是已过账应付台账，表达应付债权，不代表已经支付的现金。
- `ownerReceipts` / `companyOwnerReceipts` 是业主实际收款/退款原始流水；公司级默认模板保留项目编号、流水编号、类型、金额、到账日期、参考号和原始收款编号，不能将登记净收款汇总误认为未收余额。
- `companyDownstreamContracts` 是按可访问项目汇总的分供合同清单，包含原始合同额与当前有效合同额；默认模板与分供付款/退款流水分开展示。
- `downstreamPayments` / `companyDownstreamPayments` 是实际分供付款与退款流水，保留流水类型、日期、参考号及退款原付款参考号；付款与退款不得与应付台账或实际成本混算，也不得把付款总额直接当作实际成本。
- 所有分供付款数据必须先通过可访问项目范围过滤；明细达到服务端上限时明确提示截断，不允许把部分付款数据标记为完整清单。

## 4. XLSX 导出规范

标准台账 XLSX（`buildReportWorkbook`）与报表工作室 XLSX（`buildReportStudioWorkbook`）都必须使用首张总览页；两条导出路径都需有对应的真实 XLSX buffer 自动化测试，避免只有其中一类导出具备预览页。

导出工作簿至少包含：

1. **报表预览/总览页（首张工作表）：** 报表名、报表类型、模板名/版本、生成时间、数据范围、业务写入声明、工作表目录、截断/警告状态和阅读说明。
2. **用户设计的报表工作表：** 与服务端确定的渲染结果一致；保留用户工作表名和布局（名称无效或重复时须稳定清理/去重）。
3. **可选报表说明页：** 模板、数据范围、生成时点、注意事项和警告。

金额默认保留两位小数；超过 Excel 安全精度的金额以十进制文本保留，不可静默变动。避免将用户文本导出为 Excel 公式；打印设置、分页、冻结窗格与合并单元格须与模板定义一致。达到上限的截断说明必须包含在打印区域中，不能只在屏幕或工作簿中非打印的单元格显示。

## 5. 自动化验收

- 用 ExcelJS 加载真实 XLSX buffer，检查实际工作表顺序、名称、绑定值、字体/填充/边框/垂直与水平对齐、合并、冻结窗格、打印布局、说明页和金额精度；预览与导出的单元格样式映射须一致。
- 同样本对比预览和 XLSX 关键字段；两种呈现必须共享服务端 render 层。
- 测试 0 条、1 条、多条和达到上限的集合；多个独立重复区域（包括分供付款/退款）、多工作表、无效/重复工作表名、超长文本、公式前缀文本和大额小数。
- 覆盖字段级截断依赖：同一汇总源中被截断字段与正常字段并存时，只绑定正常字段的模板应保持完整；绑定受影响字段的模板必须在预览和 XLSX 总览页中显示警告。
- 在真实浏览器验收设计器编辑/保存、预览/返回、失败重试、导出下载与中文输入。
- 对公司级和往来单位报表测试不同角色/项目范围；越权字段不能出现在预览或导出中。
- 项目级、公司级和往来单位三份内置默认模板都必须调用服务端 `validateReportStudioDefinition` 做实际 schema/字段白名单校验；该回归测试纳入发布候选 Gate，不能只依赖静态字符串检查。
- Prisma 7 CI 使用隔离 PostgreSQL 创建两个项目、只授权其中一个给普通账号，并在另一个项目写入实际成本；测试须同时断言公司报表的项目清单、财务汇总均不泄漏越权项目数据，且直接预览越权项目返回 `PROJECT_ACCESS_DENIED`。

## 6. 当前状态

当前产品分支包含标准报表与报表工作室两个独立 XLSX 导出器的首张总览页，并通过 ExcelJS 读取真实 buffer 断言工作表顺序、基本元数据和截断警告。当前提交仍须通过 CI；还需在真实浏览器对复杂模板、分页/打印和多重复区域进行视觉验收。

源码已有 `ReportCenterPage`、`ReportDesignerPage`、`ReportStudioPage`、`ReportPreviewPage`，服务端有 report studio data/render/XLSX 模块及单元测试。上述源码存在不等于整个报表中心达到最终验收。新增/改动报告必须在 CI 和脱敏业务样本中检查，视觉版面最终由产品负责人确认。
