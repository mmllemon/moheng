# 编号规则与登录身份安全说明

- 系统：墨衡｜施工单位成本管理系统
- 版本：MVP 1.5.0-rc.1 验证候选

## 1. 编号设计原则

采用“数据库内部 ID + 用户可读业务编号”双编号机制：数据库主外键仍使用稳定、不带业务语义的内部 ID；业务编号用于合同打印、台账检索和人工沟通。

建议模式为：

`项目编号-业务类型-年份-流水号`

例如：`XM-2026-000014`（项目编号）、`XM-2026-000014-HT-2026-0001`（主合同）、`XM-2026-000014-FGHT-2026-0003`（分供合同）、`XM-2026-000014-FGJS-2026-0002`（分供结算）、`XM-2026-000014-YJJS-2026-0001`（业主结算）、`XM-2026-000014-YS-2026-0004`（应收）、`XM-2026-000014-SK-2026-0002`（到账）。具体样式以生成时项目编号为准。

项目编号采用全局的 `XM-YYYY-序号`。项目内编号的流水键由项目 ID、业务类型和业务日期的年份组成；使用数据库序列表与原子递增，避免前端本地时间或多用户同时创建引发碰撞。

## 2. 何时自动生成、何时允许手工输入

- 项目编号、内部单据编号和系统生成的流水号默认自动生成。
- 合同编号有时受外部合同号、纸面归档规则或已有编号约束，因此保留可选手工录入；留空时系统生成。系统生成编号一旦保存不得因更名或修改签署日期自动重新编号。
- 对已生成编号不得复用或回收。删除/作废业务记录时保留审计和编号占用记录，避免历史凭证指向产生歧义。
- 编号不是身份标识，所有关联仍使用数据库内部 ID。修改项目名称不应改变项目 ID 或已发出合同编号。
- 对年份切换使用业务日期的 UTC 年份确定序列分区，避免客户端所在时区导致同一单据生成不同年份键。若企业需要按合同签署日期、结算确认日期或财务期间生成，须在对应业务定义中统一，不可不同模块各自猜测。
- 外部法定/归档编号应保留原号字段；系统内部业务编号和外部合同号可能并存，不应强行覆盖。

## 3. 登录记住账号与密码

登录页提供“记住账号”，仅将用户主动选择保存的邮箱写入浏览器 localStorage；用户取消选择时删除这两项本地键值。

密码不写入应用 localStorage、sessionStorage、普通配置文件或服务端明文数据库。密码输入框使用标准 `autocomplete="current-password"`，账号输入框使用 `autocomplete="username"`，让用户使用浏览器或操作系统密码管理器的加密保存与自动填充能力。浏览器是否弹出保存提示由浏览器自身策略决定，应用不读取其密码库内容。

共用设备应关闭“记住账号”并避免让浏览器保存密码。生产环境还应使用 HTTPS/受控内网、强密码散列、登录限速、会话到期与退出清理；不要共享管理员账号。

## 4. 生产验收清单

1. 多用户并发创建同一项目同一业务类型单据，编号不重复。
2. 手工合同编号重复时由数据库唯一约束拒绝，界面展示可理解错误。
3. 修改合同名称、单位名称或项目显示名不会改写旧编号。
4. 作废单据后不会将其编号分配给新单据。
5. 未勾选记住账号时退出/刷新后不保留邮箱；已勾选时只保留邮箱。
6. 检查浏览器存储中不包含登录密码、明文凭证或长期访问令牌。
7. 使用浏览器密码管理器验证保存/自动填充；该行为不应由应用明文存储密码替代。
