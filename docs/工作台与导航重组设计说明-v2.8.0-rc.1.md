# 墨衡成本工作台与系统管理工作台重组设计说明 v2.8.0-rc.1

## 1. 本轮产品决定

- 原“项目工作台”正式改名为“成本工作台”，以项目成本管理人员的日常工作为主要导航组织逻辑。
- 项目成员与权限不属于成本业务模块，迁入独立的“系统管理工作台”。
- 先建立系统管理工作台入口和首页，复用现有项目档案、成员角色和系统账号功能；暂不虚构尚未实现的组织架构、可配置审批、角色权限矩阵或基础资料模块。

## 2. 当前导航与路由

| 入口 | 路由 | 作用 |
|---|---|---|
| 成本工作台 | `/cost` | 项目驾驶舱、业主主合同、目标成本、进度款、变更签证、竣工结算与应收、分供合同与结算、实际成本、成本分析 |
| 系统管理工作台 | `/system` | 管理功能目录与权限边界说明 |
| 项目管理 | `/projects` | 现有项目档案列表与项目创建/维护入口 |
| 项目成员与权限 | `/projects/members` | 针对当前选中项目，按既有规则管理成员和项目角色 |
| 系统账号管理 | `/system/accounts` | 仅负责公司级系统账号创建与列表；仅系统管理员可创建账号，项目角色由成员管理页面维护 |

`/workspace/*` 保留为旧版兼容路径，普通成本业务 URL 重定向到对应 `/cost/*`，旧 `/workspace/members` 重定向至 `/projects/members`，旧 `/settings/users` 重定向至 `/system/accounts`。路由迁移保留 query、hash 和 history state，避免历史书签/返回链路因命名调整失效。所有新前端链接使用 `/cost/*`。

## 3. 权限与数据边界

- 工作台是导航和交互分区，不是独立系统、服务或数据库。继续使用模块化单体、统一 PostgreSQL 和现有 API。
- 项目成员角色（OWNER/MANAGER/ESTIMATOR/VIEWER）只在对应项目生效，不等同于公司级 ADMIN。
- 项目负责人和项目经理仍只能在既有权限矩阵范围内分配角色；最后一名项目负责人保护与审计写入逻辑保持不变。
- 公司级账号创建仍受服务端 ADMIN 校验，前端隐藏菜单不作为安全边界。
- 本轮不改变财务金额计算、合同有效金额、变更生效、结算/应收应付状态机或数据库 Schema/migration。

## 4. 系统管理工作台当前及后续范围

当前可用：项目档案、项目成员与权限、系统账号管理（系统管理员）。系统管理首页按登录身份显示现有功能，不将未实现功能显示为可点击入口。系统账号页只处理账号身份；项目成员页只处理项目成员和项目角色，避免同一授权操作在两个页面重复实现。

后续可按实际岗位和公司治理需求评估：角色与数据范围配置、审批流程配置、基础资料与字典、集成管理、备份与运行状态。是否建设应由真实工作流和权限需求驱动；不因此拆分微服务。

## 5. 验收边界

本轮应通过版本/源码静态契约、旧 URL 重定向、成员路由分离、导航命名和 `git diff --check`。完整 TypeScript lint、生产构建、API 测试与浏览器/Windows 实测需在 Node.js 24+ 且依赖完整的环境中继续执行。
