# 分供合同与成本归集设计说明

版本：v1.2.3-rc.1  
适用范围：施工单位成本管理系统当前 MVP 实现

## 1. 本轮架构判断

原系统已有业主侧主合同、进度款申报、变更签证和项目成本录入，但缺少分供合同主数据与付款台账，且成本记录没有可靠的合同来源关系。这会造成一个直接问题：系统能看到项目发生了多少成本，却不能回答这些成本来自哪份采购、分包、租赁或服务合同；也不能将合同义务、成本发生和现金付款分别核对。

本轮新增分供合同及付款台账，并补齐业主收入记录与主合同的关系，同时将实际成本关联至可选的分供合同。没有依据的历史成本不自动按供应商、名称或金额猜测匹配。

## 2. 必须区分的金额概念

| 指标 | 当前定义 | 当前是否完整 |
|---|---|---|
| 分供合同当前金额 | 原始签约金额 + 已记录的有效补充协议增加额 − 减少额 | 本轮实现 |
| 执行中/完工待结算合同额 | 状态为 `ACTIVE` 或 `COMPLETED` 的分供合同当前金额合计 | 本轮实现；是合同金额汇总，不是精确的未履约义务 |
| 已承诺但未履约金额 | 原合同义务扣除已履约/验收/计量部分，并考虑变更、扣款、税额等后的剩余承诺 | 尚未完整实现；缺少合同清单量、累计验收量和累计结算量模型 |
| 实际发生成本 | 已按业务规则发生并录入的 `CostEntry`，按 `deletedAt IS NULL` 汇总 | 本轮沿用并新增合同可选关联 |
| 实际现金付款/退款 | `DownstreamContractPayment` 的付款和退款流水；净付款 = 付款合计 − 退款合计 | 本轮实现；不自动形成或冲减成本 |
| 付款计划 | 计划中的现金流节点 | 本轮实现；不属于实际付款或实际成本 |
| 预计完工成本（EAC） | 截止目前实际成本 + 完工尚需成本预测 | 本轮未实现专业 EAC；现有分析仍以目标成本作为简化基线（不存在时回退至实际成本） |

因此，**分供合同当前金额不是预计成本，也不能直接称为准确的“未履约承诺成本”**。它是已签约合同的价款基准。只有建有履约/验收/计量与累计结算数据后，才可以严谨计算尚未履约义务；预计成本则需要另设剩余成本预测模型。

当前界面中的“合同额减已关联实际成本（预警差额）”仅是两个数的算术差额，不等于未履约承诺、待付款余额或预计成本，不应用作财务结算依据。

## 3. 数据关系

```text
Project
├── MainContract（当前每个项目最多一份）
│   ├── ProgressBill（业主进度款申报，必须关联主合同）
│   └── Change（业主变更/签证，必须关联主合同）
├── CostEntry（实际成本；可选关联一份分供合同）
└── DownstreamContract（采购/劳务/专业分包/租赁/服务）
    ├── DownstreamContractAdjustment（已生效补充协议，追加保存）
    ├── DownstreamPaymentPlan（预计付款）
    └── DownstreamContractPayment（付款/退款现金流流水）
        └── REFUND 必须引用被退回的原始付款，并继承原始付款计划
```

项目是归集与访问控制边界；业主侧数据通过 `mainContractId` 关联主合同，并继续保留 `projectId`；成本通过 `downstreamContractId` 关联分供合同，并继续保留 `projectId`。API 校验关联合同属于同一项目。

## 4. 金额计算与禁止的自动化

### 4.1 分供合同金额

\[
C_{current}=C_{original}+\sum A_{increase}-\sum A_{decrease}
\]

补充协议必须登记编号、金额、方向、生效日期和已签署文件定位。原始金额在合同激活后锁定。减少协议不能导致合同当前金额为负数，不能把当前合同额降到合同净已付款以下，也不能低于已经设置的付款计划总额。

### 4.2 付款及退款

\[
P_{net}=P_{gross}-R_{total}
\]

付款和退款都以正数流水保存，退款用 `type=REFUND` 明确表示，并强制引用原始的非退款付款。单笔及累计退款不得超过该笔原始付款金额；如原付款属于付款计划，退款自动关联同一计划。系统同时检查合同净已付款与付款计划净已付款上限。通过新增退款流水冲回现金流，不修改原付款记录。

### 4.3 实际成本

只有 `CostEntry` 才参加实际成本汇总。登记付款不自动创建成本；供应商退款也不自动冲减已确认的成本。若退款实质代表退货、价格折让、冲销已入账成本等情况，应另外执行有凭证的成本更正/冲销流程；该类成本冲销在本轮尚未实现。

### 4.4 历史数据

- 迁移会把已有 `ProgressBill` 和 `Change` 记录按当前项目现有的 `MainContract` 回填 `mainContractId`。
- 如果先有进度款/变更记录、后补建主合同，保存主合同时会只补齐空的主合同关联并记录审计，不覆盖已有非空关联。
- 已有 `CostEntry` 的 `downstreamContractId` 默认保持空值；维护人员/经办人员必须依据合同、发票、验收或结算资料逐笔人工补关联。关联动作只修改来源关系，不改金额、不创建付款流水。

## 5. 本轮新增能力

1. 分供合同草稿、激活、完工待结算、已结算/终止状态流转。
2. 追加式补充协议与当前合同额重算，原始金额激活后锁定。
3. 付款计划、付款流水和退款流水，含合同级、原始付款级和付款计划级退款限制。
4. 实际成本新录入时选择分供合同，或对已有成本执行审计留痕的手工补关联。
5. 进度款与变更签证创建时要求关联项目主合同；历史记录保留并按规则补链。
6. 分析页面分别展示合同额、关联合同成本、净付款和退款；不会把付款简单相加进成本。

## 6. 当前仍未覆盖的关键后续模型

- 分供合同清单明细、合同计量、供货验收、劳务/分包已完工程量、累计报量与审核量。
- 供应商发票、入库单/验收单、分包结算单与付款核销。
- 计量/验收金额、应付金额、已付金额、质保金与预付款扣回之间的正式应付账款模型。
- 将已履约部分从未履约承诺中扣除的可靠计算，以及分包合同未履约成本预测。
- 按合同类别维护的业务字段、合同条款风险、变更/结算审批链配置。
- 已确认实际成本的规范冲销、退货及成本红字流程。

这些功能不应通过把付款额当成本、把合同金额当预计成本、或按供应商名称自动匹配的方式替代。

## 7. 本轮验收重点

- 分供合同当前金额等于原始金额加有效补充协议净额，原始金额不能在激活后被覆盖。
- 付款计划总额不超过当前合同额，付款净额不超过合同额。
- 退款关联一笔原始非退款付款，累计退款不能超过该笔原付款金额，退款自动继承原始付款计划，净付款减少且原付款流水仍保留。
- 付款/退款只改变现金流统计，不自动创建/冲减 `CostEntry`。
- 新成本只能关联同项目的非草稿且非终止合同；历史成本允许人工补关联并审计。
- 业主进度款及变更签证都关联主合同，旧记录按迁移/补建主合同时的补链规则处理。
- 旧版已经交付的迁移文件不修改；新增模型通过新迁移部署。真实 PostgreSQL 迁移需在 Windows 测试环境执行后才算通过。
