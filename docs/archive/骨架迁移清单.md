## 待决策：侧栏定位方式

这是第 1 期唯一需要判断的地方。

### hana 的做法

```css
.app  { display: flex; flex-direction: row; }
.sidebar { position: relative; width: var(--sidebar-width); flex-shrink: 0; }
.main-content { flex: 1; display: flex; flex-direction: column; }
```

侧栏和主区在同一个 flex 流里。侧栏天然占位，主区自动填满。

### moheng 现在的做法

```css
.app-shell  { display: block; height: 100vh; overflow: hidden; }
.app-sidebar {
  position: fixed;
  top: 6px; bottom: 6px; left: 6px;   /* 浮动卡片 */
  width: 240px;
  z-index: 60;
  background: var(--sidebar-bg);
  border: 1px solid var(--overlay-medium);
}
.app-main { margin-left: 246px; }   /* 240 + 6 左偏移 = 246 */
```

侧栏是**浮在页面上的卡片**，四周留 6px 缝隙，带边框和圆角。主区用 `margin-left: 246px` 让位。

### 两者的视觉差异

| | hana | moheng |
| --- | --- | --- |
| 侧栏形态 | 贴边，与页面同高 | **浮动卡片，四周留 6px** |
| 与主区分隔 | `border-right` 1px | 卡片边框 + 间隙 |
| 让位机制 | flex 自动 | `margin-left` 硬算 |

**这不是 bug，是视觉意图不同。** moheng 的「浮纸片」是册页意象的一部分。

### 技术债评估

`margin-left: 246px` 这个硬编码有两个真实问题：

1. **侧栏宽度改变时必须同步改两处**（`--sidebar` 和 `margin-left`）
2. **滚动条出现时**，`100vw` 与 `240+6` 的关系会让右侧多出约 6px 空隙

但 `position: fixed` 本身在 moheng 里是**合理的**：因为它要浮在页面上留缝隙，fixed 才能脱离流。

### 三个选项

**选项 A：完全改成 hana 的 flex 骨架**

```css
.app-shell { display: flex; flex-direction: row; }
.app-sidebar { position: relative; top:auto; bottom:auto; left:auto; flex-shrink: 0; }
.app-main { margin-left: 0; flex: 1; }
```

- 收益：让位逻辑消失，宽度改一处即生效
- 代价：**失去浮纸片效果**，侧栏变成贴边，册页意象削弱

**选项 B：保留浮动外观，修正让位机制**

```css
.app-shell { display: flex; flex-direction: row; }
.app-sidebar { position: fixed; top:6px; bottom:6px; left:6px; width:240px; }
.app-main { margin-left: 246px; }  /* 保留 */
```

- 收益：视觉完全不变
- 代价：**技术债一点没解决**，还是硬编码

**选项 C：浮动外观 + CSS 变量推导让位**

```css
:root { --sidebar-gap: 6px; --sidebar-width: 240px; }
.app-main { margin-left: calc(var(--sidebar-width) + var(--sidebar-gap)); }
```

- 收益：改宽度只改一处，视觉不变
- 代价：仍是 fixed，但不影响视觉

---

## 我的建议：C

理由：**第 1 期是修技术债，不是改视觉。**

你说的「三者结合」里，机制层我理解为「用 hana 更干净的机制」，而不是「把 hana 的外观照搬」。moheng 的浮动侧栏是设计资产，第 1 期不该动它。

C 用一行 `calc()` 就解决了 A 想解决的硬编码问题，同时保住浮纸片。

如果将来要做「更接近 hana 的观感」，那属于第 3 期排版/形态层，届时可以整体重新评估要不要放弃浮动。

## 不做（明确排除）

| 项 | 原因 |
| --- | --- |
| 顶栏 `sticky` 改 `relative` | 管理系统长页面滚动需要固定顶栏，hana 是对话应用不需要 |
| `.page-wrap` max-width 1440px 移除 | hana 无此限制，但管理系统需要限制阅读宽度 |
| 侧栏 `z-index: 60` → `10` | moheng 有移动端抽屉需求，需要高层级 |
