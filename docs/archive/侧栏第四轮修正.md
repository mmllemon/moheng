## 一、搜索框：两条线的真相

### 1.1 我之前的错误

我照搬了 `._sessionSearchBox` 的**通用样式**：

```css
._sessionSearchBox_afbfa {
  margin: 15px var(--space-8) var(--space-6);
}
._sessionSearchBox_afbfa::before {
  content: "";
  top: -10px;
  width: 72%;
  height: 1px;
  background: color-mix(in srgb, var(--text-muted) 18%, transparent);
}
```

结果侧栏里出现了两条线：`sidebar-projects` 的 `border-top` + `::before` 线。

### 1.2 hana 的真实做法：侧栏内覆盖

```css
/* 侧栏内：::before 分隔线被隐藏 */
._fpSidebarHost_09f83 [class*=sessionSearchBox]:before {
  display: none;
}

/* 侧栏内：margin-top 从 15px 改成 6px */
._fpSidebarHost_09f83 [class*=sessionSearchBox] {
  margin-top: var(--space-6);
}
```

**侧栏里的搜索框根本没有那条线，也没有 15px margin。**

那条 `::before` 线只在其他场景（搜索结果面板）使用。

### 1.3 修正

```css
.sidebar-project-search {
  margin: var(--space-6) var(--space-8) var(--space-6);   /* 6px，不是 15px */
}

.sidebar-project-search::before {
  display: none;    /* hana 明确隐藏 */
}

.sidebar-projects {
  margin: 0;
  padding: 0;
  border: none;     /* 去掉旧的 border-top */
}
```

实测：

```
margin: 6px 8px
::before: display=none content=none
搜索框上方线条: 0 条  ✓
```

## 三、左对齐：两个原因

### 3.1 原因一：多余的 lead 把标题推开

hana 的会话行标题行：

```jsx
<div className={sessionItemHeader}>
  {agentId && <AgentBadge />}     {/* lead 只在有 agent 时才渲染 */}
  <div className={sessionItemTitle}>{title}</div>
</div>
```

```css
._sessionItemHeader_9c21e {
  display: flex;
  align-items: center;
  gap: .35rem;
  width: 100%;
  min-width: 0;
  overflow: hidden;
}
._sessionItemHeader_9c21e > ._sessionItemTitle_be584 {
  flex: 1 1 auto;
}
```

**lead 是可选的。没有 agent 时，标题从左边开始。**

moheng 项目没有 agent 概念，我却无条件渲染了 lead（首字母方块），把标题推到 x=82。

已删除 lead。

### 3.2 原因二：`align-items: center` 导致子元素居中

这是更隐蔽的一个。

`.sidebar-project` 是 `flex-direction: column`，如果 `align-items: center`，**子元素会水平居中而不是左对齐**。

实测症状：

```
标题 x=23 w=206   ← 看起来正常（因为标题 flex:1 撑满了）
编码 x=83 w=86    ← 被居中了！应该在 x=23
```

修正：

```css
.sidebar-project-row .sidebar-project {
  display: flex;
  flex-direction: column;
  align-items: stretch;    /* 不是 center */
}
```

实测：

```
标题 x=23  编码 x=23  ✓ 都左对齐
```

## 四、内缩核对：为什么 8px 和 16px 都对

修正过程中出现过「搜索框 16px 太远」「行 0px 太近」的反复。最终核对如下：

### 4.1 hana 的累加结构

```
侧栏 border:      1px
scroller padding: 0px      ← ._sessionListScroller 无 padding
list padding:     8px      ← ._sessionList padding: 0 8px
item padding:     8px      ← ._sessionItem padding: 6px 8px
─────────────────────
标题实际内缩:     17px
```

### 4.2 moheng 对应

```
侧栏 border:      1px（计入 innerLeft 基准）
scroll padding:   0px
list padding:     8px
btn padding:      8px
─────────────────────
标题实际内缩:     16px（不含 border 基准）
```

**一致。**

### 4.3 搜索框为什么是 8px

搜索框**不在 list 内**，只有自己的 `margin: 6px 8px`：

```
搜索框左内缩: 8px  ✓
```

hana 同样：`._sessionSearchBox` margin 8px，不在 `._sessionList` 内。

### 4.4 最终测量表

| 元素 | 左内缩 | hana 对应 |
|---|---|---|
| 搜索框 | 8px | `margin 8px` ✓ |
| 分组标题（文字） | 8px | `padding 8px` ✓ |
| 项目行 | 8px | `list padding 8px` ✓ |
| 项目标题（文字） | 16px | `list 8 + item 8` ✓ |

## 六、这四轮的方法教训（重要）

我连续四轮在同一个地方犯错，根本原因是**同一个**：

> **照搬组件的通用样式，不看它的上下文覆盖规则。**

hana 的 CSS 有明显的分层：

```
① 组件通用样式      ._sessionSearchBox { margin: 15px; ::before { ... } }
② 场景覆盖样式      ._fpSidebarHost [class*=sessionSearchBox] { margin-top: 6px }
                    ._fpSidebarHost [class*=sessionSearchBox]:before { display: none }
```

**只读 ① 会得出错误结论。**

### 正确做法

做任何组件前，先搜：

1. `组件名` 的所有规则（不只第一条）
2. 含 `[class*=` 的后代选择器（场景覆盖）
3. 含 `data-*` 的属性选择器（状态变体）

命令示例：

```js
// 搜某个组件的所有规则（含后代覆盖）
const re = /([^{}]*sessionSearchBox[^{}]*)\{([^}]*)\}/g;
```

这样能一次拿到通用 + 覆盖两层，不会漏。
