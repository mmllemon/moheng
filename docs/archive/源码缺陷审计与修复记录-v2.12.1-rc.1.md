# 墨衡 v2.12.1-rc.1 源码缺陷审计与修复记录

- 基线：`v2.12.0-rc.1`，提交 `0901bc5`
- 缺陷清单：用户提供的《源码缺陷清单-v2.12.0-rc.1.md`
- 修复候选：`v2.12.1-rc.1`
- 审查方式：逐条对照当前源码与 Prisma 模型/事务行为；修复确认缺陷；把设计选择、预期行为和未验证假设单独归类。
- 重要边界：未声称完成 Node.js 24+ 全量构建、真实 PostgreSQL 迁移/并发验证或浏览器 E2E。

## 结论摘要

原清单的 39 条不能全部认定为真实缺陷。存在明确代码错误、可复现的状态同步/显示问题，也有对 PostgreSQL 原子更新、参数跨作用域定义约束、最大重试次数语义的误判，以及未来扩展建议。本轮修复确认的缺陷，并对若干边界问题做了防御性加固；未为误报引入会破坏现有安全/保留策略的行为变化。

## 逐条裁定

| 编号 | 裁定 | 本轮处理与理由 |
|---|---|---|
| BUG-01 | 真实 | 部门重命名时 `DepartmentRow` 未同步外部数据；增加 prop 变化同步。 |
| BUG-02 | 真实 | 用户部门/岗位归属未随查询刷新同步；增加 prop 变化同步。 |
| BUG-03 | 真实 | 默认规则状态缺少徽标映射；新增“内置默认”状态。 |
| BUG-04 | 真实 | 备份 `RUNNING` 被错误映射到待验收；改为“执行中”。 |
| BUG-05 | 真实 | 后台任务状态应按真实状态显示；增加“已取消”并直接传入真实状态。 |
| BUG-06 | 防御性加固 | 当前 Prisma `AuthSession.user` 是非空外键关系，正常数据库约束下不会为 null，原报告的损坏关系情形不可由常规 API 产生。UI 仍增加空值兜底，避免渲染脆弱。 |
| BUG-07 | 防御性加固 | 表单当前仅在 `selected` 存在时渲染，报告的常规路径不成立；仍移除非空断言并显式守卫，便于未来改动保持安全。 |
| BUG-08 | 真实 | 字典项表格输入缺少可访问名称；增加 `aria-label`。 |
| BUG-09 | 真实 | 多处参数校验失败仅返回 body 错误或丢掉 params 详情；现分别返回 `params` / `body` 校验明细。 |
| BUG-10 | 部分成立，已加固 | 同一键的类型与可见性在设计中本来就是跨全局/项目作用域统一的约束，所以“必须按 scope 过滤”不符合设计。原 `findFirst` 选择任意历史行不够确定；改为直接查询是否存在定义冲突。 |
| BUG-11 | 真实 | 发布审计把“旧发布版已退休”硬编码为 true；现记录实际退休行数和布尔值。 |
| BUG-12 | 部分成立 | 审计刻意不保存参数原值是保密设计，不应改为记录原始 `value`。补充安全的 `name` / `description` 元数据，保留原值不入审计的约束。 |
| BUG-13 | 真实 | 项目归档校验原在事务外，存在竞态；草稿创建事务内再次校验项目可用性。 |
| BUG-14 | 真实 | 回滚说明会静默截断；改为超长时返回明确 400，不再丢失用户输入。 |
| BUG-15 | 未确认，不按缺陷处理 | 版本计算在 `Serializable` 事务内，唯一约束保护 `(key, scopeKey, version)`，并发冲突 `P2002/P2034` 已统一映射为 409。当前证据不足以认定其会静默破坏版本。 |
| BUG-16 | 不是当前结果缺陷，已明确化 | 未带 `projectId` 时，PROJECT 行的 `projectId` 不会等于 `undefined`，因此原代码不会把项目参数加入全局结果；现加显式条件，避免以后 WHERE 扩大时产生歧义。 |
| BUG-17 | 真实 | 子进程超时只终止直接子进程；现使用 POSIX 进程组终止，Windows 使用 `taskkill /T /F` 终止进程树，并避免对已超时退出事件重复结算。目标平台仍需实机验证。 |
| BUG-18 | 不认定为缺陷 | 保留策略允许按期限删除过期备份文件，同时保留备份/恢复演练的审计元数据；成功演练的 `fileName` / SHA-256 是历史证据，并不是可下载备份的承诺。至少两个最新成功备份仍受保护。 |
| BUG-19 | 真实 | 先删文件再写数据库可能造成 DB 指针悬空；现先在事务内退休文件元数据并记审计，再删除文件。删除失败最多留下孤儿文件，不再让数据库指向已删除文件。 |
| BUG-20 | 当前设计下不是缺陷 | 运维工作台和环境说明把恢复目标定义为预先创建、可覆盖的专用持久化 `restore_test` 数据库，用 `pg_restore --clean` 重置内容；不 DROP 该数据库是有意设计，便于检查演练结果。它不是临时建库/自动销毁设计。 |
| BUG-21 | 真实 | 下载端文件名校验宽于创建/恢复校验；现统一采用严格的 `moheng-... .dump` 文件名规则。 |
| BUG-22 | 真实的防护缺口 | DNS/IP 不重合不能证明是不同 PostgreSQL 集群；现额外查询生产与恢复目标的 `pg_control_system().system_identifier`，相同集群拒绝恢复，无法核验也拒绝执行。运维连接账号需要只读 `pg_monitor` 权限。 |
| BUG-23 | 未来兼容性建议，不认定为当前故障 | 当前 Prisma schema 与迁移使用默认模型表名，没有 `@@map`；`User`、`Project`、`MainContract` 表名在当前版本一致。若以后更改映射，需要同步调整恢复校验。 |
| BUG-24 | 部署威胁模型提示，不是新增源代码泄漏 | `PGPASSWORD` 未进入命令行或应用日志，但同 OS 用户/root 仍可能检查进程环境，这是环境变量凭据的一般限制。部署应为 API 使用专用 OS 身份并收紧主机访问；当前保留既有不将凭据写入 argv/log 的做法。 |
| BUG-25 | 真实 | 登录限流桶 HMAC 原依赖 `JWT_SECRET`，轮换 JWT 密钥会改变限流 hash；新增独立 `LOGIN_ATTEMPT_HMAC_KEY`。公网模式启动时要求它是独立有效的 32 字节十六进制密钥；JWT 轮换不再重置已有桶。 |
| BUG-26 | 不成立 | 同一 PostgreSQL `INSERT .. ON CONFLICT DO UPDATE` 的各表达式基于更新前行值计算。重置窗口时失败数设为 1 且清除封禁；未过窗口时以旧 `failures + 1` 判断是否达到阈值，与同条语句的新计数一致。未发现报告所述的 CASE 分支偏移。 |
| BUG-27 | 真实 | 刷新令牌签发热路径每次触发三张表的清理；现移入后台 worker 的周期性保留清理，并对每张表独立记录失败，避免每次登录/刷新扫描历史数据。 |
| BUG-28 | 真实 | MFA 密文各段仅检查段数，空/非法十六进制段可能引发底层 opaque 错误；现先校验 IV、tag 与 ciphertext 的长度/字符集，再进入 AES-GCM 解密。 |
| BUG-29 | 不成立 | TOTP 步进更新是一条带 `mfaLastUsedStep < acceptedStep` 条件的原子 SQL UPDATE。并发请求更新同一行时 PostgreSQL 会在行锁后对更新行重新检查 WHERE；同一步进第二次更新不能仅因并发而继续匹配。 |
| BUG-30 | 原报告路径不可复现，仍加防御性条件 | `/refresh` 首先用 `UPDATE ... WHERE consumedAt IS NULL ... RETURNING` 原子消费旧令牌；同一令牌的竞争请求拿不到 `current`，不会同时进入 legacy promotion 分支。仍把后续链接改为 `updateMany` 条件更新并核对 count，以明确一次性迁移约束。 |
| BUG-31 | 不成立为功能缺陷 | 格式合法但不存在/已用的恢复码在事务中由 `consumed.count !== 1` 拒绝，并映射为 401；不会绕过 MFA，也不会被接受。多一次失败尝试仍受安全接口的认证/限流约束。当前不为避免一次事务而增加存在性探测查询。 |
| BUG-32 | 真实 | 强制改密路径在受限 token 校验后仍无事务内乐观锁；现重新读取 `authVersion`，并在事务内要求账号仍启用、仍需强制改密且 `authVersion` 未变化，失败返回 409。 |
| BUG-33 | UX 改进，不是安全错误 | 每次开始 MFA enrollment 会替换尚未确认的 pending secret，这是重新开始设置时使旧二维码失效的行为；路由有速率限制。操作人需使用最近一次返回的二维码，不将其改为累积多个 pending secret。 |
| BUG-34 | 不成立 | 若确认时接受 `current-1` 步进并存储它，下一次接受 `current` 时仍满足 `storedStep < acceptedStep`，不会按报告描述被拒绝。 |
| BUG-35 | 产品能力建议，不是当前 API 隐瞒历史 | 接口与 UI 明确限定展示最近 200 条；安全中心页面也明示该限制。管理员查看 IP/UA 是该受限安全审计页的既定用途。可在后续需求中加游标分页与脱敏策略，但不列为当前正确性缺陷。 |
| BUG-36 | 不成立，符合 maxAttempts 合约 | `attempts` 在领取任务时递增；达到 `maxAttempts` 后租约过期会进入 FAILED，不应再被当作可重试任务。否则就会突破明确的最大尝试次数。 |
| BUG-37 | 部分加固 | 更新失败状态的数据库写入失败时，原异常会冒泡到轮询层；当仍有尝试次数时租约到期可重新领取，达到最大次数则按策略终止。现为该回写失败增加独立错误日志，避免丢失诊断信息；不能在数据库不可用时保证立即更新状态。 |
| BUG-38 | 真实的重试压力问题 | 清理失败会让下一轮立即再次执行清理查询；现失败后至少冷却 60 秒再重试，同时保留后台任务轮询。数据库不可用时不能安全判断孤儿文件引用关系，因此不在数据库失联时贸然删除文件。 |
| BUG-39 | 未来扩展建议，不是当前已支持产物缺陷 | 当前后台任务存储由报表导出子系统独占，产物名与接口均为 `.xlsx`；数据库备份 `.dump` 使用独立备份目录与清理逻辑。不能为未来假设扩大孤儿文件删除匹配范围。 |

## 本轮源码改动摘要

- 前端状态、标签与可访问性：BUG-01 至 05、08；对 BUG-06/07 额外增加空值/选择守卫。
- 参数配置 API：BUG-09、10、11、12、13、14、16。
- 运维与备份：BUG-17、19、21、22。
- 认证与保留清理：BUG-25、27、28、32。
- 后台 worker：BUG-37 日志加固，BUG-38 清理失败冷却。
- 新增认证单元测试：限流 hash 在 JWT key 轮换时保持稳定；MFA 密文错误分段会在 AES-GCM 前被拒绝。
