## 四、一处设计决策的推翻

### 「外观页独立模式」被移除

moheng 原本有一个 `is-appearance-only` 模式：外观页隐藏 208px 导航，变成单列弹窗（内容 max-width 760px 居中）。

**hana 没有这个模式。** 它的所有设置页都是「208px 导航 + 内容列」的三栏结构。

按用户「重叠部分按 hana 来」的原则，已改为：

```css
/* 修正前 */
.settings-window.is-appearance-only .settings-nav { display: none; }
.settings-window.is-appearance-only .settings-content { max-width: 760px; }

/* 修正后：只收紧内容宽度，导航保留 */
.settings-window.is-appearance-only .settings-content > .route-transition {
  max-width: 760px;
  margin: 0 auto;
}
```

对应门禁断言同步更新：

```diff
- check('appearance is independent from system settings nav', ...)
+ check('appearance page keeps the settings nav (hana three-column structure)', ...)
```

**这是一次真实的行为变更，不是修断言。** 原来的断言验证的是「隐藏导航」，现在验证「保留导航」。

## 五、过程中的三个真实故障

### 故障一：`z-index` 写成 0 导致内容被纸纹遮住

我把 `settings-body` 的 `z-index` 从 1 改成 0（误以为对齐 hana 的 `z-index: 0`），结果内容区发灰。

**hana 的 `._body_f2f15` 是 `z-index: 0`，但它和窗口的纸纹伪元素不在同一层叠上下文里。** moheng 的 `.settings-window::before` 是 `z-index: 0`，两者同级，纸纹在后 → 遮住内容。

已改回 `z-index: 1`，并在注释里写明原因。

### 故障二：CSS 删除脚本破坏花括号

第一次删除 `settings-window` 纸纹时，脚本用「找最近的 `/*` 注释起点」定位，误把 `.settings-header,` 的选择器一起删掉，花括号 2083/2082 不平衡。

**已用行号精确修复**（3275-3294 → 替换为干净的注释块）。

**教训**：CSS 里交错的选择器列表不能用「注释起点」做边界。

### 故障三：搜索框白块追了四轮

```
第 1 轮：以为 input 需要背景 → 加了，但被全局 !important 清空
第 2 轮：以为容器有背景 → 去掉了，但 input 还是 #fcfaf5
第 3 轮：改用 rgba → 仍是 #fcfaf5
第 4 轮：CDP 查到 .settings-nav .settings-search:focus-within { background: var(--bg-card) }
```

**真相：不是 bug，是焦点态。** input 获得焦点时容器变 `--bg-card`（白色），这是 hana 的设计（`_item_c6fac:focus-visible` 同理）。

不聚焦时实测：容器透明、input `rgba(42,38,34,0.03)`，**完全正确**。

**教训**：查视觉问题时必须先确认「当前是否处于某个状态」，否则会把状态样式当成缺陷。
