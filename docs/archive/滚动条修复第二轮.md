# 滚动条修复（第二轮）

日期：2026-10-23

用户指出：滚动条确实透明了，但**滚动的时候也看不到滚动条**。

上一轮我只验证了 `is-scrolling` 类名加上了，没验证滚动条是否真的可见。这一轮做了像素级验证。

---

## 一、根因：三个问题叠加

### 问题 1：滚动容器不在卡片边缘

实测：

```
窗口右缘                    1200
.settings-content 右缘      1199
.settings-content > .route-transition 右缘   1159   ← 滚动条画在这里
```

那 41px 是 `.settings-content` 的 `padding-right: 40px`。滚动条画在 padding 内侧，不在卡片边缘。

**hana 的 `_sessionPanel_73d9c` 是 `position: absolute; inset: 0`，滚动条贴在卡片最右缘。**

**修正**：把水平内缩从滚动容器移到内部内容层。

```css
/* 改前：滚动容器带 padding */
.settings-content {
  overflow-y: auto;
  padding: 0 var(--settings-content-inset) var(--space-40);
}

/* 改后：滚动容器无 padding，内缩交给内容层 */
.settings-content {
  overflow-y: auto;
  padding: 0;
}
.settings-content > .route-transition {
  padding: 0 var(--settings-content-inset) var(--space-40);
  box-sizing: border-box;
}
```

实测：`.route-transition` 右缘从 1159 → **1199**，距窗口边缘仅 1px（边框）。

### 问题 2：`::-webkit-scrollbar` 规则用了裸选择器

我之前写的是：

```css
::-webkit-scrollbar { width: 4px; height: 4px; }
::-webkit-scrollbar-thumb { background: #80808033; }
```

**hana 用的是 `*` 前缀**：

```css
/* mobile-kfy_1ie4.css（无平台限定，Windows 也生效） */
*::-webkit-scrollbar { width: 4px; height: 4px; }
*::-webkit-scrollbar-track { background: transparent; }
*::-webkit-scrollbar-thumb { background: #80808033; border-radius: 2px; corner-shape: round; }
*::-webkit-scrollbar-thumb:hover { background: #80808066; }
```

已改为 `*` 前缀。

### 问题 3：无头浏览器测不出真实滚动条宽度

这是**我上一轮最大的误判来源**。

| 模式 | `scrollbar-width: auto` | `thin` | `::-webkit-scrollbar 4px` |
|---|---|---|---|
| headless | 2px | 2px | 2px |
| **headed（真实桌面）** | **17px** | **12px** | **6px** |

**无头模式下三种写法都是 2px，完全测不出差异。** 我用无头模式测了十几轮，一直得到 `offsetWidth - clientWidth = 0`，误以为是 CSS 没生效。

实际上有头模式下 `::-webkit-scrollbar { width: 4px }` 得到 **6px**（4px 内容 + 2px 边距），是生效的。

---

## 二、`scrollbar-width` 是个陷阱

有头模式实测：

```
scrollbar-width: auto   → 17px
scrollbar-width: thin   → 12px
::-webkit-scrollbar 4px →  6px
```

**一旦声明 `scrollbar-width`，Chrome 就改用标准滚动条并忽略 `::-webkit-scrollbar`。**

所以：

- 想要 4px 细线 → **只能靠 `::-webkit-scrollbar`，不能声明 `scrollbar-width`**
- 想要「细但由系统控制」→ `scrollbar-width: thin`（12px，比 17px 细但比 4px 粗）

hana 的选择是前者：只用 `::-webkit-scrollbar`，不声明 `scrollbar-width`。

**已移除我之前加的 `scrollbar-width: thin`。**

---

## 三、滚动时变淡：overlay 重绘的副作用

### 实测数据（像素采样，x=1192..1199）

```
静默态           R 值: [246,241,241,204,208,207,207,225]   平均 222
滚动中           R 值: [246,241,241,241,247,246,246,225]   平均 242
```

**滚动时 thumb 反而消失了**（242 接近背景 246）。

原因：滚动时 Chrome 用系统 overlay 滚动条重绘，忽略 `::-webkit-scrollbar` 的所有样式。加 `.is-scrolling` 的 `!important` 虽然规则命中（CDP 可见），但 overlay 重绘时颜色由系统接管。

### 处理

**改成「静态可见」策略**：

```css
/* hana 真值是 #80808033（20% 灰），但实测在暖纸底上几乎不可见 */
*::-webkit-scrollbar-thumb {
  background: #80808055;   /* 33% 灰，可见度下限 */
}
*::-webkit-scrollbar-thumb:hover {
  background: #80808080;   /* 50% 灰 */
}
```

并**移除 `.is-scrolling` 的加深规则**（因为它反而让 thumb 变淡）。

`useScrollIndicator` hook 保留 —— 在未来支持占位式滚动条的环境里仍然需要它。

## 五、方法教训

**这一轮最大的教训是：无头浏览器不能用来验证滚动条。**

| 我做的 | 结果 |
|---|---|
| 用 headless 测 `offsetWidth - clientWidth` | 永远 0，误判「CSS 没生效」 |
| 用 headless 测 `scrollbar-width: auto/thin/none` | 全部 2px，看不出差异 |
| 用 headless 截图 | 滚动条不绘制，看不到 |

**正确做法：涉及浏览器原生 UI（滚动条、窗口装饰、系统字体）的验证，必须用有头模式。**

用有头模式后，一个问题在 5 分钟内就定位了（17px / 12px / 6px 三档立刻区分开），而前面十几轮无头测试全是无效信息。

另一个教训：**上一轮我说「已修复」时，只验证了类名加上，没有验证像素。** 类名加上不等于视觉可见。验证应该到「用户能看见」这一层。
