# 墨衡历史阶段记录摘要

本文件合并原先按每个 RC 重复保存的阶段验收/验证记录。具体版本变更仍以仓库根目录 `CHANGELOG.md` 为准；本文件是历史导航，不替代当前产品状态、业务规则和开发阶段验证/后续投产门禁。

## 历史演进主线

- **核心台账阶段（v1.x）**：项目、主合同、目标成本、实际成本、变更签证、进度款及分供合同等基础账务流程逐步建立；随后补充往来单位主数据、项目授权和关键业务审计。
- **结算与财务台账阶段（v1.x–v2.x）**：逐步建立分供结算/应付/付款核销、业主结算/应收/收款退款分配、预付款和质保金等分开建模；历史金额与现金流水不得互相代替。
- **工作台与系统管理阶段（v2.x）**：导航聚焦成本工作台并区分项目管理、公司系统管理；补充基础字典/参数配置、权限治理、账号安全、公网接入、加密备份/恢复及数据质量检查能力。
- **报表阶段（v2.1–v2.8）**：从标准 XLSX/CSV 台账导出发展为模板设计器和报表工作室，逐步加入项目、公司和往来单位范围、单元格绑定、独立重复区域、样式/打印与预览导航。
- **AI 助手阶段（v2.14–v2.19）**：形成只读业务工具、LangGraph 适配、PostgreSQL checkpoint、会话 API、后台运行事件/SSE 与第一版助手 UI；仍处于 RC，不代表真实模型 E2E 和生产准入已完成。
- **Prisma 7 迁移候选（v2.19.0-rc.2）**：迁移到 Prisma 7.10.1、显式 PostgreSQL driver adapter，并加入历史数据回填、备份恢复及 STG-shaped 合成夹具的 CI 验证。真实脱敏预发布快照核验和实际部署拓扑验收是后续投产门禁；仅在对应真实数据和目标环境具备时执行，不是当前开发推进的前置条件。

## 历史验收文件处理原则

每个 RC 的阶段验收、静态结果和本机日志不再作为主目录内单独的“当前状态”。这些记录可能使用旧版本号、旧依赖、旧环境限制或旧实现说明；当前应以如下文件为准：

- `../产品范围与当前状态.md` — 当前源码能力与未完成范围
- `../后续四阶段开发路线图.md` — 产品开发主线
- `../架构与核心业务规则.md` — 当前架构与财务业务不变量
- `../报表中心规格与验收.md` — 报表设计/预览/XLSX 规范
- `../AI助手实施与准入.md` — AI 接入和安全边界
- `../发布与迁移验收.md` — 开发阶段 CI 证据、当前开发待办与后续投产门禁

历史详细缺陷复核另见 `源码缺陷审计与修复记录-v2.12.1-rc.1.md`。不得仅因为旧验收记录上有 PASS，就将当前源码或生产环境标记为通过。
