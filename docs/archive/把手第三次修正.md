# 把手第三次修正：命中区 + pointerId 校验

日期：2026-10-25

前两次都没解决，这次找到了真正的原因。

## hana 的做法

`contributed-keybindings-BWxnaFR2.js` 里，pointerdown **挂在容器（layout group）上**，不是挂在把手上：

```js
const B = (y) => {
  if (d || (y.pointerType === 'mouse' && y.button > 0) || ac(y.target)) return;
  const j = du(y, c, L.chalkboardLayoutDocument);      // 坐标命中检测
  if (!j) return;
  y.preventDefault(); y.stopPropagation(); y.stopImmediatePropagation();
  L.setChalkboardUserResizeActive(true);
  d = ji({ axis, capture: true, commitOnPointerCancel: true, context: F, event: y, target: c, onMove: … });
};
```

命中函数 `cu`：

```js
function cu(event, container) {
  const target = event.target;
  if (target instanceof Node && container.contains(target)) {
    if (target instanceof Element) {
      const hit = Kn(target);                    // 先看 target 祖先链上有没有 separator
      if (hit) return hit;
    }
  }
  const tolerance = grabTolerance() / 2;         // 容差 = 热区一半
  let best = null;
  for (const sep of container.querySelectorAll('[data-layout-separator-node-id][data-layout-separator-index]')) {
    const r = sep.getBoundingClientRect();
    if (!hitTest(r, event.clientX, event.clientY, tolerance)) continue;
    const d = Math.hypot(event.clientX - (r.left + r.width / 2), event.clientY - (r.top + r.height / 2));
    if (!best || d < best.distance) best = { distance: d, hit: Kn(sep) };
  }
  return best?.hit ?? null;
}
```

**关键：不要求指针精确落在 6px 的把手上，坐标在「把手矩形 ± 容差」内就算命中。**

`ji({ capture: true, commitOnPointerCancel: true })` 是统一的拖动控制器：捕获指针、pointercancel 也要提交。

## 我之前漏掉的三点

**一、命中区太窄。** 把手只有 6px 高，用户很难精确点中。hana 靠容差扩展命中区。

修法：加一层 `::before` 撑到 ±6px（总 18px）：

```css
.card-split-handle::before {
  content: "";
  position: absolute;
  left: 0; right: 0;
  top: -6px; bottom: -6px;
  z-index: -1;
}
```

**二、没校验 pointerId。** 用 `window` 监听 `pointermove` / `pointerup` 时，多个指针（触屏、手写笔）会互相干扰，导致 `dragging` 卡住。加指针校验：

```js
const pointerId = event.pointerId;
const move = (e) => { if (e.pointerId !== pointerId) return; … };
const finish = (e) => { if (e.pointerId !== pointerId) return; … };
```

**三、松手后把手换位置，`hold` 状态没兜住。** grid 重排后 handle 从 y=447 跳到 y=514，指针还在 447，`:hover` 立刻失效。

修法：`data-hold` 属性保持 600ms：

```js
finish: () => {
  setDragging(false);
  holdTimer.current = window.setTimeout(() => setHold(false), 600);
}
```

```css
.card-split-handle[data-hold]::after { opacity: 0.35; transform: … scaleX(1); }
```

顺带清空 `document.body.style.cursor`（之前会残留 `row-resize`）。

## 这次实测

严格测四种情况：

| 场景 | 结果 |
|---|---|
| 慢拖 +70px | card1 441 → 508，松手 opacity 0.35，再悬停 0.35 |
| 反向拖 -70px | 441 → 441，正常 |
| **拖到面板外松手** | `dragging` 正确复位、cursor 清空、opacity 保持 |
| 再拖 -70px | 441 → 374，正常 |


## 为什么前两次没修好

第一次加了 `setPointerCapture`，但没解决「命中区只有 6px、指针容易掉出去」这个根本问题。

第二次加了 700ms 的 `data-revealed`，只解决了松手后的可见性，没解决命中。

**两次都在改「松手之后」，而真正的问题在「按下之前」——用户根本点不到那 6px。**

hana 的 `cu()` 用容差扩大命中区，这才是正解。
