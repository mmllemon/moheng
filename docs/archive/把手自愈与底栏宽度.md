# 把手悬停自愈 + 底栏宽度对齐

日期：2026-10-25

## 一、把手：拖动后消失

### 根因（不是 hover 失效，是指针与 handle 脱节）

`move` 里调 `onChange`，触发 React 重渲染，grid 的 `gridTemplateRows` 变了，handle 所在的 grid 行位置跟着移动（实测 y `447 → 540`）。而指针还停在旧的 y 上。

于是松手瞬间：

```
handle 已移到 y=540
指针还在 y=447
→ :hover 不成立
→ ::after opacity 0
→ 看起来「把手不见了」
```

真实用户拖动时指针一路跟随，不会遇到；但只要有一次指针停在原处（或快速拖动后松手），就会出现。

### 修法：松手后短暂保持揭示态

```js
const finish = () => {
  setDragging(false);
  handle.removeEventListener('pointermove', move);
  handle.removeEventListener('pointerup', finish);
  handle.removeEventListener('pointercancel', finish);
  if (handle.hasPointerCapture(event.pointerId)) handle.releasePointerCapture(event.pointerId);

  /* 松手后 grid 已重排，handle 换到了新的 y，而指针还停在旧位置：
     此时 :hover 会立刻消失，看起来像「把手不见了」。
     用 capture 补一个 700ms 的揭示态，等用户下次移动鼠标再自然退出。 */
  setJustReleased(true);
  window.clearTimeout(releaseTimer.current);
  releaseTimer.current = window.setTimeout(() => setJustReleased(false), 700);
};
```

```css
.card-split-handle[data-revealed]::after {
  opacity: 0.35;
  transform: translate(-50%, -50%) scaleX(1);
}
```

### 实测

```
第1次  悬停 0.35 → 松手150ms 仍 0.35（revealed）→ 1s 后 0（自然淡出）
第2次  悬停 0.35 → 松手 0.35 → 1s 后仍 0.35（指针恰好在 handle 上）
第3次  同第1次
```

三次拖动都正常，松手瞬间看得到把手。

## 二、底栏宽度

### 真值

```css
--chat-column-width: 720px;                          /* 对话列宽 */
--chat-input-column-extra: 1.25rem;                  /* 20px */
--chat-input-column-width: calc(720px + 20px);       /* 740px，输入框宽度 */
```

`.input-area > *` 用 `max-width: var(--chat-input-column-width)`，而胶囊 `_input-wrapper` 自己的 `padding` 是额外的。

### 修法

之前 `box-sizing: border-box`，740 包含 padding，内容被压到 736。改成 `content-box`：

```css
.cost-workspace-tabs {
  box-sizing: content-box;
  max-width: calc(720px + 1.25rem);   /* 740px 内容宽 */
  padding: var(--space-2, 2px);        /* 向外再加 4 */
  border: 1px solid var(--overlay-light);
}
```

实测 `visibleW: 746` = 740 内容 + 4 padding + 2 border，比对话列宽（720）宽 26px，符合「稍微宽一点」。
