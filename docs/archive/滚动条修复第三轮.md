# 滚动条修复（第三轮，最终）

日期：2026-10-23

用户指出：还是和 hana 不太一样。hana 的滚动条平常不显示，滚动时才显示，而且更细。

这一轮查清了 hana 的真实机制，发现之前的理解有根本性错误。

---

## 一、之前两轮的错误

### 错误 1：把 mobile 端的规则当成桌面端的

我引用的是 `mobile-kfy_1ie4.css` 里的：

```css
*::-webkit-scrollbar { width: 4px; height: 4px; }
*::-webkit-scrollbar-thumb { background: #80808033; }
```

**但 `mobile-kfy_1ie4.css` 只被 `mobile.html` 加载，桌面端 `index.html` 不加载它。**

核实方式：逐个 html 提取 `<link href="*.css">`：

```
index.html      → styles.css, themes/warm-paper.css, 24 个组件 css
mobile.html     → 只有 mobile-kfy_1ie4.css
```

### 错误 2：漏掉了 `:where(html:not([data-platform="win32"]))` 前缀

桌面端真正的全局滚动条规则在 `styles.css` 里：

```css
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar {
  width: 4px; height: 4px;
}
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar-track {
  background: transparent;
}
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar-thumb {
  background: rgba(128, 128, 128, 0.2);
  border-radius: 2px; corner-shape: round;
}
:where(html:not([data-platform="win32"])) *::-webkit-scrollbar-thumb:hover {
  background: rgba(128, 128, 128, 0.4);
}
```

**关键：全部包在 `:where(html:not([data-platform="win32"]))` 里 —— Windows 上完全不做定制。**

`data-platform` 的来源（`app-host-view`）：

```js
const n = await window.platform?.getPlatform?.();
(n === "darwin" || n === "win32" || n === "linux")
  && document.documentElement.setAttribute("data-platform", n);
```

## 二、真相：hana 在 Windows 上用的是 Electron 的 overlay 滚动条

### 为什么「不定制」反而得到细且自动隐藏的滚动条

实测对比（有头 Chrome，`offsetWidth - clientWidth`）：

| 启动参数 | 滚动条占位 |
|---|---|
| 默认（普通 Chrome） | **17px** |
| `--enable-features=OverlayScrollbar` | **2px** |

**Electron 默认启用 OverlayScrollbar，普通 Chrome 没有。**

所以 hana 的「不定制」在 Electron 里等于「得到系统 overlay 滚动条」：
- 平常完全隐藏
- 滚动时淡入
- 约 6px 宽
- 圆角胶囊
- 松手后自动淡出

**这正是用户看到的观感，而且完全不是 CSS 控制的。**

### moheng 的平台差异

moheng 跑在普通 Chrome 里，默认是经典滚动条（15-17px 占位、常显、带箭头按钮）。

如果照抄 hana 的「不定制」，moheng 会得到一个又粗又常显的滚动条 —— **与 hana 观感完全相反**。

## 三、最终方案：用 CSS 模拟 overlay 观感

```css
/* 宽度：4px（hana 值） */
*::-webkit-scrollbar {
  width: 4px;
  height: 4px;
}

*::-webkit-scrollbar-track {
  background: transparent;
}

/* 默认透明：复刻「平常不显示」 */
*::-webkit-scrollbar-thumb {
  background: transparent;
  border-radius: 2px;
  corner-shape: round;
  transition: background var(--duration-slow) ease-out;
}

/* 悬停容器或滚动中显现：复刻「滚动时才显示」 */
html .is-scrolling::-webkit-scrollbar-thumb,
html [data-scrolling]::-webkit-scrollbar-thumb,
html .settings-content::-webkit-scrollbar-thumb,
html .settings-content > .route-transition:hover::-webkit-scrollbar-thumb {
  background: rgba(128, 128, 128, 0.35);
}

/* 滑块自身悬停再深一档（hana: 0.4） */
*::-webkit-scrollbar-thumb:hover {
  background: rgba(128, 128, 128, 0.5);
}
```

### 一个真实的选择器坑

我第一版写的是：

```css
*:hover::-webkit-scrollbar-thumb { background: ...; }
```

**这个不生效。** `:hover` 必须作用在具体元素上，通配符 `*` 匹配不到伪元素的宿主。

必须写成具体容器：

```css
html .settings-content > .route-transition:hover::-webkit-scrollbar-thumb { ... }
```

## 四、实测（有头模式，x=1195..1198 像素采样）

```
① 初始          cls="route-transition"                R=247   ← 透明，不可见
② 手动加类      cls="route-transition is-scrolling"   R=206   ← 显现
③ 滚动（hook）  cls="route-transition is-scrolling"   R=206   ← 显现
④ 1.2s 后      cls="route-transition"                R=247   ← 自动隐藏
```

背景纸色 R≈248。**247 ≈ 不可见，206 明显可见。** 完全符合 hana 的「平常隐藏、滚动显现、800ms 后消失」。

滚动条位置：x=1195-1198（4px 宽），紧贴内容区右缘 1199。

## 六、这一轮最重要的教训

**「照抄 CSS 值」和「理解 CSS 为什么这么写」是两件事。**

| 项 | 表面 | 实质 |
|---|---|---|
| `:where(html:not([data-platform="win32"]))` 前缀 | 一个平台限定 | **Windows 上放弃定制，交给 Electron 的 overlay** |
| `mobile-kfy_1ie4.css` 里的 `*::-webkit-scrollbar` | 全局规则 | **只服务 mobile.html，桌面端不加载** |
| `#80808033`（20% 灰） | 一个颜色值 | 在 overlay 模式下由系统叠加，实际观感比数值深 |

我前两轮都在「找值、抄值」，但没有问「这个值在什么环境下生效、生效后得到什么」。

**正确做法：先确认规则在目标环境是否加载、是否生效，再确认数值。** 否则会把 mobile 的规则套到桌面，把 macOS 的规则套到 Windows。
