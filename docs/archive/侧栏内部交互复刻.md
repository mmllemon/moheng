### 2.6 一个精巧的设计：`@property --session-actions-fade`

```css
@property --session-actions-fade {
  syntax: "<color>";
  inherits: true;
  initial-value: transparent;
}
```

注册成**可动画的 color 属性**。行的背景变化时，操作按钮的「渐隐遮罩」也跟着过渡，而不是突然出现。

`moheng` 用背景色渐变替代，效果等价且更简单（不需要 `@property`）。

```js

async function reorderProjects(folderId, projectIds) {
  const res = await fetch('/api/session-projects/projects/reorder', {
```

### 3.4 排序逻辑（关键的插入位置规则）

```ts
const current = [...pinned.map(p => p.id), ...rest.map(p => p.id)];
const from = current.indexOf(draggedId);
const to = current.indexOf(targetId);

const without = current.filter(id => id !== draggedId);
const targetAt = without.indexOf(targetId);
// 向下拖 → 插到目标之后；向上拖 → 插到目标之前
const insertAt = from < to ? targetAt + 1 : targetAt;
without.splice(insertAt, 0, draggedId);
```

**这个 `from < to` 判断是必须的。** 第一版没有它，导致「把 B 拖到 C」变成「插到 C 前面」，顺序没变。

纯逻辑验证 5/5：

```
✓ B 拖到 C（向下）→ [A,C,B,D]
✓ C 拖到 B（向上）→ [A,C,B,D]
✓ A 拖到 D（向下）→ [B,C,D,A]
✓ D 拖到 A（向上）→ [D,A,B,C]
✓ B 拖到 D（向下）→ [A,C,D,B]
```

## 四、过程中修掉的问题

### 问题一：状态分离导致拖拽失效

第一版把 `draggingProjectId` 放在 `Layout`，但 `ProjectList` 内部也有自己的拖拽 state。两个状态互不相通，`handleProjectDrop` 读到的永远是 `null`。

**修法**：让 `onReorder(draggedId, targetId)` 直接接收两个 ID，Layout 只负责重算顺序。

### 问题二：输入框高度 32px 压不下来

这是本次最费时的一个。追踪过程：

```
第 1 次：以为 v6.css 的 min-height:34px
        加 .sidebar-project-search 前缀（0,2,0）→ 仍失败

第 2 次：加 .app-sidebar 前缀（0,3,0）→ 仍失败

第 3 次：用 CDP getMatchedStylesForNode 精确定位
        发现真凶是 hana.css:1684
        html input:not([type=checkbox]):not([type=radio]):not([type=file])
                  :not([type=range]):not([type=hidden]) { height:32px; min-height:32px }
        特异性 0,6,1
```

**这条是全局输入框规范（统一 32px 点击热区），不应该被单点覆盖。**

最终用 `!important` 明确豁免，并在注释里写清理由：

```css
/* 侧栏搜索是唯一的「容器内嵌输入」，不参与表单布局。
   全局 32px 规范是为了表单控件的点击热区，嵌入控件不需要。
   不用 !important 的话，要么改全局规范（影响所有表单），
   要么堆到 0,7,1 的特异性（维护成本高）。 */
```

### 问题三：页脚「系统管理员」重复显示

种子账号的 `name` 字段就是「系统管理员」，所以 `<strong>{name}</strong><span>{role}</span>` 会显示两次。

```tsx
<strong>{user?.name ?? '用户'}</strong>
{user?.name !== roleLabel && <span>{roleLabel}</span>}
```

### 问题四：注释里的 `/* 1px */` 破坏块注释

这是第三次踩同一个坑：

```ts
/*  ... margin-bottom: var(--session-row-gap)  /* 1px */  ... */
```

内层 `/*` 提前闭合了外层注释，导致 12 个 TS 语法错误。

**教训：块注释里不能出现 `/*` 序列，写 `← 1px` 或 `= 1px`。**

## 五、与 Hana 的差异（诚实登记）

| 项 | Hana | moheng | 原因 |
|---|---|---|---|
| 数据形态 | 会话（有标题、时间、摘要、agent） | 项目（名称 + 编码） | 业务不同 |
| 行的第二行 | 元信息（agent · 目录 · 时间） | 项目编码 | 同上 |
| 置顶持久化 | 服务端 `POST /reorder` | `localStorage` | moheng 项目排序是个人偏好，不需要跨设备同步；且不改后端 |
| 悬停按钮 | 置顶 + 更多操作 | 只有置顶 | moheng 项目没有「重命名/删除」等操作 |
| 搜索范围 | 标题 + 摘要 + 状态 | 名称 + 编码 | 字段不同 |
| 排序方式 | 按时间分组（今天/昨天/更早） | 置顶 + 自定义顺序 | moheng 项目没有时间维度 |
| `--session-actions-fade` | `@property` 注册的动画 color | 背景色直接过渡 | 效果等价，少一个 `@property` |
| 行高 | 单行 20px / 双行自适应 | 双行约 49px | 内容不同 |

**这些都是「产品差异」，不是「复刻不完整」。** 交互范式（搜索、悬停、置顶、拖拽、焦点）已经对齐。

## 六、第 1 项「贴纸显隐」为什么没做

你提的第 1 项是「贴纸的显隐」。

Hana 的贴纸（`_fpPrimaryAgentSticker_1a144`）是**主 agent 的身份标识**：

```css
._fpPrimaryAgentRow_18788 {
  --fp-primary-agent-avatar-size: 30px;
  --fp-primary-agent-name-size: 1.125rem;   /* 18px */
}
._fpPrimaryAgentName_ec0fa {
  font-family: var(--font-serif, serif);     /* 宋体 */
  font-size: 1.125rem;
  font-weight: 600;
}
```

它由一个 store 开关控制：

```js
chalkboardShowPrimaryAgentHeader: n,
setChalkboardShowPrimaryAgentHeader: (v) => set({ ... })
```

而且这个开关同时控制两件事：

```jsx
identity={showHeader && <PrimaryAgentRow />}      // 贴纸行
activityBars={fullPanel ? false : <ActivityBars />}  // 功能按钮区
```

**moheng 没有「agent」这个概念**，侧栏顶部是「墨衡 / 工程经营管理」的品牌标识，语义不同。

所以这里有两件事需要你决定：

**选项 A：把品牌区当成贴纸，加显隐开关**
在设置里加一个「显示侧栏品牌区」的开关。但品牌标识通常不该隐藏。

**选项 B：不做**
moheng 的品牌区是固定的，不需要显隐。

我倾向 B。但如果你的意图是「侧栏顶部那块应该能收起，腾出空间」，那是另一个功能（紧凑模式），可以做。
