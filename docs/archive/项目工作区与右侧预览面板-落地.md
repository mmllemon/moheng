# 项目工作区与右侧预览面板（落地记录）

日期：2026-10-23

把 Hana 的「会话工作目录 + 右侧文件树 + 预览」移植为 moheng 的「项目工作目录 + 右侧文件树 + 预览」。

---

## 一、与 Hana 的结构对应

| Hana | moheng | 说明 |
|---|---|---|
| 会话绑定工作目录 | `Project.workspaceRoot` | 相对路径，不存绝对路径 |
| `_previewPanel` 580px 面板 | `.workspace-panel` | 宽度、border-left、纸纹一致 |
| `_rightWorkspaceSection` 树区 | `.workspace-search` + `.workspace-tree` | search 30 / toolbar 25 / tree |
| `_treeItem` 三列网格 | `.tree-item` | 缩进 12px/层、28px 高、squircle |
| `_previewPanelBody` 预览 | `.workspace-preview` | PDF / 图片 / 文本分流 |

**一处结构修正**：Hana 不是「两个浮层」，而是**一个面板内上下分区**。做成两个浮层会争宽度，屏幕放不下。

**另一处偏离**：Hana 的树占满高度、预览是覆盖式；moheng 用 flex 上下分区（树 54%、预览 46%），因为 moheng 的文件名更长，树需要更多纵向空间。

---

## 二、后端

### 2.1 数据模型

```prisma
model Project {
  workspaceRoot String?   // 相对 WORKSPACE_STORAGE_DIR/projects
}
```

**只存相对路径**。绝对路径在多实例部署、容器迁移时会失效。根目录由 `WORKSPACE_STORAGE_DIR` 决定。

### 2.2 文件布局

直接用文件系统目录树，**不建数据库表**：

```
{WORKSPACE_STORAGE_DIR}/projects/{projectId}/
  合同/
    主合同.pdf
  凭证/
    发票-001.pdf
```

理由：
- 目录就是树，不需要维护 parentId/path/depth 三份冗余
- 用户可以用资源管理器直接看、直接改
- 删库不丢文件

代价是没有文件元数据（谁传的、什么时候）。需要时加旁挂表，以相对路径为主键。第一版没做。

### 2.3 API

```
GET    /api/projects/:id/workspace/tree?path=     列一层（懒加载）
GET    /api/projects/:id/workspace/file?path=     读内容（限 2MB）
GET    /api/projects/:id/workspace/raw?path=      流式下载 / PDF 内嵌
POST   /api/projects/:id/workspace/file           上传（base64）
POST   /api/projects/:id/workspace/dir            新建目录
DELETE /api/projects/:id/workspace/entry?path=    删除
```

**懒加载**：`tree` 只 `readdir` 一层，展开子目录时再请求。文件多也不会卡。

`hasChildren` 用 `for await` 读第一个 entry 就 `return true`，不做全量扫描。

### 2.4 安全

复用 `evidence-storage.ts` 的范式，四道防线：

| 防线 | 实现 |
|---|---|
| 路径穿越 | `resolve` 后必须仍在项目根内（Windows 统一 `toLowerCase` 比较） |
| 符号链接 | `readdir` 的 `Dirent.isSymbolicLink()` 一律跳过 |
| 扩展名白名单 | 允许 pdf/xlsx/png/docx/zip 等；拒绝 exe/bat/ps1/js/dll |
| 大小上限 | 单文件 50MB，预览 2MB |

**一个踩过的坑**：`resolveEntry` 最初把 `C:/Windows/system32` 规范化成相对路径，绕过了检查。必须在剥离前导斜杠**之前**判 `isAbsolute`。

### 2.5 token 鉴权

`authRequired` 只认 `Authorization: Bearer` 头。但 `<iframe>` / `<img>` / `<a download>` 无法自定义请求头。

所以 `raw` 端点额外接受 `?token=` 查询参数，其余端点不变。

**风险**：token 会进入访问日志和浏览器历史。只用于预览和下载，不改状态。文本预览仍走 Authorization 头，不用 URL token。

## 三、前端

### 3.1 组件

```
WorkspacePanel.tsx
  ├─ workspace-head      操作区（上传/刷新/关闭）
  ├─ workspace-search    搜索框 30px
  ├─ workspace-tree      懒加载目录树
  │    └─ TreeNode       三列网格行（递归）
  └─ WorkspacePreview    PDF / 图片 / 文本分流
```

### 3.2 三列网格（关键）

```css
.tree-item {
  --tree-indent-step: 12px;
  display: grid;
  grid-template-columns:
    calc(var(--tree-leading-inset) + (var(--tree-depth, 0) * var(--tree-indent-step)))
    22px
    minmax(0, 1fr);
  height: 28px;
  border-radius: calc(4px * var(--corner-radius-scale));  /* 7.36px */
  corner-shape: squircle;
}
```

**为什么不用 `padding-left`**：padding 会挤掉内容宽度，深层目录的文件名会过早出现省略号。三列网格里缩进是独立轨道，名称列始终有空间。

缩进由 `--tree-depth` 内联样式控制，组件只传数字。

### 3.3 实测值

```
面板      626 × 382      （嵌入档案区，不是独立 580px）
树高      306
搜索框    30
树项      28px 高，7.36px 圆角，superellipse(2)，三列网格，图标 22px
悬停操作  opacity 0 → 1
选中态    accent 10%，悬停 14%
```

### 3.4 接入位置

`ProjectsPage` 的右侧档案区加了标签：

```
项目档案 | 工作区
```

**为什么不并排**：档案区本身已经是一列，再加一个 580px 面板会让右侧出现两栏，宽度不够。

## 四、踩过的坑

### 坑一：`createReadStream('', { fd })` 拖垮整个 API

```ts
// 错误：空路径 + 外部 fd
createReadStream('', { fd: opened.handle.fd, autoClose: true })
```

症状：请求 `/workspace/file` 后 API 进程直接崩溃：

```
[Error: EBADF: Closing file descriptor 3 on garbage collection failed, close]
```

原因：stream 和 FileHandle 都认为自己对 fd 有所有权，GC 时重复关闭。

修法：用 `FileHandle` 自己的方法：

```ts
opened.handle.createReadStream({ autoClose: true })
```

**这个坑很隐蔽**：单元测试和 API 直测都通过（因为测试没走 raw 端点），只有浏览器预览时才触发。

### 坑二：`projects-dossier` 是块级，树被压成 8px

初始 `.workspace-tree` 高度只有 8px。原因：`.projects-dossier` 没有 `display: flex`，子项的高度由内容决定，`flex: 1` 无效。

修法：切到工作区标签时用 `:has()` 改布局：

```css
.projects-dashboard .projects-dossier:has(.workspace-panel) {
  display: flex;
  flex-direction: column;
  min-height: 520px;
  max-height: calc(100dvh - 260px);
}
```

### 坑三：预览区固定 42% 让 PDF 挤成一条

`flex: 0 0 42%` 在总高 382px 时只有 160px，PDF 页面被压扁。改成 `flex: 0 0 46%` + `min-height: 240px`。

### 坑四：API 反复被回收

用 `exec_command` 启动的 `tsx watch` 会随命令结束被回收。`Start-Process -WindowStyle Hidden` 也会。

唯一稳定的方式：

```powershell
Start-Process -FilePath 'cmd.exe' `
  -ArgumentList '/c','cd /d <repo> && npm run dev > service.log 2>&1' `
  -WindowStyle Hidden
```

**验证脚本必须自带 API 健康检查 + 自动重启**，否则会浪费大量时间在"页面打不开"上。

### 坑五：`<iframe>` 无法带 Authorization 头

`<img>` 和 `<iframe>` 的请求由浏览器发起，无法注入自定义头。必须让 URL 自带凭据，或者后端接受 cookie。

moheng 的 `authRequired` 只认头，所以给 `raw` 端点加了 `?token=` 支持。
