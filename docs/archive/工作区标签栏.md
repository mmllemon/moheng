```jsx
function Uet({ tabs, activeTab, onSelect, ariaLabelKey = 'rightWorkspace.tabs.label', className }) {

    '--right-workspace-active-tab-index': `${idx}`,
    '--right-workspace-tab-slider-offset': idx === 0 ? '0px' : 'calc(100% + 2px)',
  };
  return (
    <div className={wh.tabs} role="tablist" style={style}>
      <div className={wh.tabSlider} aria-hidden="true" />

        <button
          type="button"
          role="tab"
          aria-selected={activeTab === c.id}
          className={`${wh.tab}${activeTab === c.id ? ` ${wh.tabActive}` : ''}`}
          onClick={() => onSelect(c.id)}

          {label}
          {c.marked && <span className={wh.tabMarker} aria-hidden="true" />}
        </button>
      ))}
    </div>
  );
}
```

## 二、moheng 实现

### 2.1 实测

```

滑块位移     0 → 46.8125px（calc(100% + 2px)）
aria-selected 正确切换
```

与 Hana 逐项一致。

### 2.2 一处调整

**图标列 22px → 26px。**

Hana 的 `_treeItem` 第二列是 22px，因为它的 chevron 和文件图标**叠放**在同一格。moheng 是**并排**（chevron 12px + 图标 14px = 26px），所以加宽。

不加宽的后果：SVG 被 `inline-flex` 压缩，实测从 14px 缩到 **10.77px**，看起来像方块。

修法是双保险：
```css
.tree-icon svg { flex: 0 0 auto; width: 14px; height: 14px; }
grid-template-columns: ... 26px minmax(0, 1fr);
```

## 三、两个标签的职责

| 标签 | Hana | moheng |
|---|---|---|
| 对话文件 | 会话产物文件列表 | 项目目录树 |
| 工作室 | 工作区目录树（desk） | **暂时同一棵目录树** |

**为什么暂时一样**：Hana 的 `session-files` 和 `workspace` 是两个不同数据源（会话产物 vs 工作区目录），moheng 只有项目目录一套。

代码里写明了这一点：

```tsx
{/* 标签页目前共用同一棵目录树 ——
    hana 的 session-files 与 workspace 是两个不同数据源（会话文件 / 工作区目录），
    moheng 只有项目目录，所以两个标签暂时展示同一棵树。
    待接入「项目产物」后，工作室标签再切到产物视图。 */}
```

**这是诚实的做法**：不假装有两个数据源。等 moheng 有了「报表产物」或「凭证归档」这类独立产物，工作室标签再接上去。

## 四、踩的坑

### 坑一：重复定义 `.workspace-search`

CSS 里有两条 `.workspace-search { ... }`，第二条把第一条的背景色覆盖了。

后果：搜索框底色从 `color-mix(bg-card 92%, text 8%)` 变回 `color-mix(sidebar-bg 97%, text 3%)`，与卡片底色几乎相同，视觉上看不出搜索框。

**发现方式**：CDP 查 computed `backgroundColor` 是 `rgb(238,235,229)`（浅灰），但截图看不到边界。

修法：删掉重复定义，保留一条并加 `inset 0 0 0 1px var(--overlay-light)` 内描边。

### 坑二：第二次删掉 `_targets.mjs`

我用 `Remove-Item scripts\_*.mjs` 清理临时脚本，把正式的 `_targets.mjs`（双 target 启动器）又删了。视觉回归报 `ERR_MODULE_NOT_FOUND`。

**这是第二次犯同样的错。** 上一次是 `_t*.mjs` 通配符命中了 `_targets.mjs`。

修法：改成精确匹配 `_n*.mjs`。

**规则**：清理前先 `Get-ChildItem -Filter '_xxx*.mjs'` 列出待删清单，确认不含正式文件再删。

## 六、与 Hana 的差异

| 项 | Hana | moheng |
|---|---|---|
| 图标列宽 | 22px（chevron 与图标叠放） | 26px（并排） |
| 标签数据源 | 两套（会话产物 / 工作区） | 一套（项目目录） |
| `tabMarker`（4×4 角标） | 有（标记有更新的标签） | 未做 |
| 滑块 `width` 过渡 | `cubic-bezier(.4,0,.2,1)` | 同 |

`tabMarker` 未做的原因：moheng 没有「标签有更新」这个概念。
