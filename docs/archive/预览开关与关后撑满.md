日期：2026-10-25

## 一、眼睛按钮的语义

hana 的真值（`CardShell-DVSoA_HL.js` 的 `xJe`）：

```js
function xJe({ tone = 'desk' }) {
  const pressed = useStore((s) => s.uiSurfaceMode === 'infinity' ? Fy(s) : s.previewOpen);
  const label = t('preview.toggle');
  const onToggle = () => {
    const s = getState();
    if (s.uiSurfaceMode === 'infinity') {
      s.setChalkboardPreviewOpen(!Fy(s));   // ← 只切 previewOpen
      return;
    }
    Mne();
  };
  return tone === 'system'
    ? <Btn size="lg" onClick={onToggle} title={label} aria-label={label} pressed={pressed}><SC size={16} /></Btn>
    : <button className={`${sortBtn} ${iconBtn}`} onClick={onToggle} aria-pressed={pressed}><SC size={14} /></button>;
}
```

**它只切 `previewOpen` 一个布尔量**，不涉及 tab、不动列表。

我的实现：

```jsx
aria-label={showPreviewToggle ? '隐藏预览' : '显示预览'}
aria-pressed={showPreviewToggle}
onClick={() => setShowPreviewToggle((v) => !v)}
```

语义等价。实测 `pressed true → false`，label 在「隐藏预览 / 显示预览」间切换，工具提示正确。

**这一条本来是对的**，之前看起来「不一样」是因为下面那个 bug —— 关了预览但文件卡没撑满，视觉上像没关掉。

## 二、关预览后文件卡没撑满

### 根因

hana 的行模板由 `mu()` 按**实际卡片数**生成：

```js
function mu({ node, sizing, transitioningPanelIds, layoutOverride }) {
  const out = [];
  node.children.forEach((childId, i) => {
    if (i > 0) out.push("0px");                    // 分隔行，只在有第二个孩子时出现
    const weight = mt(sizing[i] ?? { kind: "fill" });
    const ratio = Number.isFinite(min) && min > 0 ? weight / min : 1;
    out.push(`minmax(0%, ${ratio}fr)`);
  });
  return out.join(" ");
}
```

**卡片少一个，`children` 就少一项，行模板自动变成单行 `minmax(0%, 1fr)`。** 不存在「预留 50%」这回事。

我的实现是写死的三段：

```jsx
gridTemplateRows: `minmax(0, ${ratio * 100}%) 6px minmax(0, ${(1 - ratio) * 100}%)`
```

关预览后 `card2` 不渲染了，但模板还是三段，文件卡只占 50%。

### 修法

按 `showPreview` 切换模板：

```jsx
gridTemplateRows: showPreview
  ? `minmax(0, ${cardSplitRatio * 100}%) 6px minmax(0, ${(1 - cardSplitRatio) * 100}%)`
  : '100%',
```

### 实测

```

关预览    rows "100%"                                    card1 888（撑满）  card2 null
重新打开  rows 回到 50% / 6px / 50%                      card1 441  card2 441
```

## 三、这次是同一个错误的变体

上一轮刚总结过「抄一条 CSS 规则要读完配套」。这次是同一个问题落在 JS 上：

**我抄了 `mu()` 的「按比例分」这个结论，没抄它「按实际子元素数量生成行」这个结构。**

hana 的分栏是数据驱动的（`node.children.map`），我写成了常量。所以只要子元素数量变化，模板就跟不上。

判据：**凡是「卡片可能有 1 张也可能有 N 张」的地方，模板、间距、分隔条都必须由数组长度推导，不能写死。**
