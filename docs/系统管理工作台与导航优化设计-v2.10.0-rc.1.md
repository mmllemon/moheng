# 墨衡系统管理工作台与导航优化设计 v2.10.0-rc.1

日期：2026-10-15
基线：本地 Git Bundle 中的 `v2.9.0-rc.1`（HEAD `f2eafeb`）。本轮只在本地仓库演进，不从 GitHub `main` 拉取或覆盖代码，也不推送远程仓库。

## 1. 六项讨论结论与本轮落实

### 1.1 项目管理与系统管理分工

项目档案和项目成员/项目角色是项目生命周期的业务管理，统一归入“项目管理”；公司级账号身份、登录安全、会话控制、系统级操作追溯归入“系统管理”。项目角色和公司级 `ADMIN/USER` 身份仍是两套权限概念，菜单迁移不改变服务端授权规则。

| 一级分组 | 页面/功能 | 路由 |
|---|---|---|
| 经营中心 | 经营总览 | `/` |
| 经营中心 | 报表中心 | `/reports` |
| 经营中心 | 待办与预警 | `/notifications` |
| 经营中心 | 往来单位库 | `/parties` |
| 工作台 | 成本工作台 | `/cost` |
| 项目管理 | 项目档案 | `/projects` |
| 项目管理 | 项目成员与权限 | `/projects/members` |
| 系统管理 | 系统管理概览 | `/system` |
| 系统管理 | 系统账号管理 | `/system/accounts` |
| 系统管理 | 登录安全中心 | `/system/security` |
| 系统管理 | 操作追溯 | `/audit-logs` |

旧 `/system/members` 与 `/workspace/members` 继续重定向至 `/projects/members`；历史 `/workspace/*`、`/settings/users` URL 兼容策略保留。

### 1.2 操作追溯位置

操作追溯是公司治理与责任追踪入口，移动到系统管理导航，系统管理导航仅对系统管理员显示。经营总览可保留当前账号项目授权范围内的“最近操作”摘要；普通成员不显示公司级“查看全部”按钮。既有 API 仍按服务端项目成员关系过滤普通用户可见的数据，UI 隐藏不能替代 API 访问控制。

### 1.3 异地登录状态说明

v2.9 代码已具备公网模式安全配置闸门、会话与安全事件、管理员 TOTP MFA、Secure Cookie 和 HTTPS 反向代理样例。但 DNS、正式域名/TLS 证书、Windows 防火墙、实际公网连通性和浏览器端到端登录必须由部署方在目标环境实测。本版本的管理首页明确区分源码已有机制与等待真实公网验收的事项，不以“源码有功能”冒充“系统已公开可用”。

### 1.4 成员自主修改密码

新增个人中心入口 `/account/security` 及 `POST /api/auth/password/change-self`。流程：

1. 要求正常登录会话，验证当前密码；新密码不少于 12 位，不能等于当前密码。
2. 已启用 MFA 的账号必须提交新的 TOTP 时间步或一枚未使用恢复码；TOTP 时间步与恢复码消费在数据库事务中校验，防止重复使用。
3. 更新密码哈希和 `authVersion`，撤销该账号所有有效会话、使未消费刷新令牌失效，并记录操作审计与安全事件。
4. 密码更新后清除当前浏览器登录状态，提示用户重新登录。当前版本不包含基于邮件的自助找回密码流程；忘记密码应由管理员通过受控流程重置。

该接口与已有 `/api/auth/password/change`（首次/管理员重置后使用受限凭证强制改密）相互独立，避免弱化强制改密流程。

### 1.5 侧边导航与重复入口

原“工作台”分组更名为“经营中心”，原“成本业务”分组更名为“工作台”，并将项目管理独立成组。系统管理首页从重复入口卡片重构成管理概览，显示启用账号、有效会话、近期安全事件、待处理账号、风险事件摘要和治理状态；账号、会话与操作明细通过侧栏直接进入专门页面，首页不再复制项目档案或项目成员入口。

### 1.6 系统管理后续扩展

首页将扩展路线标明为规划项，而非假装可操作的菜单：

- **下一阶段：组织与权限治理**：部门/岗位、角色权限矩阵、跨项目数据范围、授权复核。
- **规划中：审批与规则配置**：流程、金额阈值、通知规则的版本化配置、变更审批和发布审计；不绕过既有合同/结算财务规则。
- **规划中：运维与灾备**：备份结果、恢复演练、磁盘空间、服务健康、后台任务、日志保留与版本升级状态。
- **规划中：数据治理与集成**：数据质量、归档保留、重要导出审计、集成状态和密钥轮换。

## 2. 安全边界

- 公司级系统管理员页面需有服务端管理员权限检查；仅仅隐藏菜单不构成授权。
- 普通账号只管理自己的密码；当前密码错误不修改任何状态；MFA 启用时必须再次验证。
- 自助改密成功后注销该账号所有旧会话，避免更改密码但其他设备仍保持访问。
- 新密码字段、当前密码、TOTP 和恢复码均纳入日志脱敏；审计记录不存明文密码或一次性恢复码。
- 系统首页的安全事件/会话数量来自当前 API 可见的最近 200 条记录，不应解释为全历史统计。
- 数据库、JWT 密钥和 MFA 加密密钥不因侧栏/页面改造而改变管理方式，不向浏览器回显真实秘密。

## 3. 本地实现范围与验收边界

本轮只演进本地 `main`，起点是 `v2.9.0-rc.1`，新版本为 `v2.10.0-rc.1`。不会从远程 `main` 取回旧版代码，也不修改远程仓库。

可在当前环境完成的验收：Git diff 格式、代码/路由/接口静态契约、版本一致性、既有发布候选回归脚本。

仍需在 Node.js 24+ 且依赖完整的环境进行实际 TypeScript build/lint、`prisma validate` 与 Client 生成、数据库迁移验证、认证 API 测试和浏览器 MFA/改密 E2E。真实公网验收另外要求正式域名、TLS、反向代理、公网 80/443 规则和数据库私网隔离。未通过上述 Gate 前继续标记为 RC，不能认为已经正式上线。
