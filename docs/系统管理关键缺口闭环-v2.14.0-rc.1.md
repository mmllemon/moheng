# 墨衡系统管理关键缺口闭环 v2.14.0-rc.1

- 日期：2026-10-16
- 基线：`v2.13.0-rc.1`
- 版本性质：发布候选，不是生产验收通过

## 1. 本轮目标与边界

本轮针对系统管理之前确认的四类问题作增量落地：组织/权限治理、审批及业务参数消费、备份/集成边界、数据质量按钮样式。保持模块化单体、PostgreSQL 和既有业务模型，不改合同金额生效算法、业主/分供结算、付款/退款核销及外部确认语义。

## 2. 权限治理与跨项目只读

### 已落地

- 新增 `UserProjectDataScope` 和 `User.dataScope`。既有账号迁移后默认 `ASSIGNED_PROJECTS`，不扩展任何现有账号的数据可见范围。
- 管理员可通过账号管理设置普通账号为 `ALL_PROJECTS_READONLY`。变更使用乐观并发条件，记入审计和安全事件，并增加 `authVersion`、撤销有效会话，令变更在重新登录后生效。
- 跨项目只读只可用于 `PROJECT_READ` 与 `REPORT_EXPORT`，不能当成项目成员，也不能授权写入、审批、外部确认、结算付款、成员管理或公司级安全日志读取。
- 项目授权策略通过统一 `canAccessProject` 辅助层在服务端执行。已发布策略只能收紧源码权限基线，不能增加未声明能力；非法已发布策略对受保护路由 fail-closed。
- 项目列表、经营总览、报表中心/报表工作室及往来单位档案在明确只读作用域内支持跨项目数据。项目成员身份信息和成员管理仍需要 `PROJECT_MANAGE`；动态待办/预警按显式只读作用域过滤，操作追溯仍遵循各自的管理员/项目成员授权边界。

### 未宣称实现

该工作不是所有实体的通用资源级 ABAC/RBAC。被授权全项目只读的用户可见范围扩大至可读项目数据，部署前需由业务所有者核准此授权的敏感数据影响；通知中心和操作审计等部分功能仍按其自身的成员/管理员边界处理。必须通过真实会话逐端点验证所有写 API 仍拒绝无权用户，不能只依赖静态检查。

## 3. 审批策略和业务参数

### 已落地

- 项目权限策略只在现有源码定义的角色和能力范围中生效，发布/回滚均保留规则版本和审计。
- 版本化内部审批工作流接入变更签证状态流转，读取当前发布版本；保留状态合法性、角色边界及提交人不得审批本人业务约束。流程策略不控制外部业主确认，不改变外部确认金额生效规则。
- 新增两个真实业务消费参数：
  - `CONTRACT_EXPIRY_WARNING_DAYS`：默认 30 天，允许范围 1–365。
  - `TARGET_COST_OVERRUN_DANGER_PERCENT`：默认 0%，允许范围 0–100，用于区分超支预警的 warning/danger 严重级别。
- 仅取 `PUBLISHED` + `BUSINESS_READABLE` + `NUMBER` 的配置；项目级值覆盖全局值。缺省、越界或类型错误时回退到安全默认值，不将配置错误传入金额结算算法。

### 未宣称实现

当前 `WORKFLOW` 版本化机制只开放 `CHANGE_INTERNAL_APPROVAL` 这一已接入消费方。它还不是能自由设计合同、进度款、结算、付款等所有业务的通用工作流引擎。字典和参数的其他业务字段仍需逐项接入、做默认值/历史兼容和消费方测试；不得宣称所有硬编码枚举已转为动态配置。

## 4. 运维灾备

- 业务库通过 `pg_dump --format=custom` 导出；数据库全局角色和全局配置通过 `pg_dumpall --globals-only` 单独归档。
- 两个归档都使用 AES-256-GCM 加密，带加密密钥 ID，下载提供加密文件，SHA-256 用于传输/存储完整性核验。
- 解密临时工作目录位于受限备份目录下，成功/失败路径尽可能清理临时明文；部署环境需为备份目录和明文临时文件设置仅 API 运行身份可读写的 ACL。
- 恢复演练会验证生产和目标 PostgreSQL 集群 system identifier 不同，并在隔离目标创建临时数据库，恢复并校验核心业务表，随后尝试删除临时库；失败会保留运维告警/审计信息。

### 明确限制

恢复演练不会自动把 `pg_dumpall` 导出的全局 SQL 应用到隔离集群，因为该脚本可以创建/改写集群角色，可能影响同集群其他数据库。当前演练验证业务数据库恢复及全局归档解密/完整性，不等于全局角色恢复演练。正式灾备演练必须在全新隔离集群中由授权 DBA 审核和应用 globals SQL，并核对角色、授权和密码策略。密钥环必须经部署密钥管理渠道保管；密钥遗失将使归档无法解密，旧密钥不得在相关备份过期前删除。

## 5. 外部集成

- 集成探测/投递仅使用 HTTPS，要求 `INTEGRATION_ALLOWED_HOSTS` 明确允许目标主机，拒绝用户信息/fragment/重定向，并验证 DNS 所有答案是公网地址；请求使用已验证的 DNS 地址以减少重绑定风险。
- 提供异步 JSON POST 投递，凭据仅从加密保险库解封到请求头，队列 payload 不保存秘密正文，投递使用稳定 idempotency key，使用既有后台任务队列重试并保留投递状态。
- 连接测试及投递状态写入集成记录和审计；响应体仅取受限片段，不能将它作为可信指令。

### 明确限制

目前是通用 REST/JSON 适配能力，不代表 ERP、Webhook、对象存储或财务系统具体协议已经接通；没有完成各外部服务的业务字段映射、签名规范、异步回调、死信管理界面或对端幂等语义验证。HTTPS 主机允许列表配置和真实对端连通性需由部署方逐个验证。

## 6. 数据质量巡检按钮

运行巡检按钮常态背景透明、无盒阴影；悬停用低对比中性色面，键盘焦点保留中性色 `outline`，执行中显示旋转状态图标。该 CSS 源码现在已覆盖正常/hover/focus/disabled 状态。尚需在目标主题、浏览器和不同缩放下做视觉核对，静态 CSS 检查不能证明所有级联样式和构建产物都无紫色底色。

## 7. 数据库迁移和部署

本轮追加迁移：

- `20261016040000_system_security_workflow_integration`
- `20261016050000_project_data_scope`

不修改既有 migration 内容。部署前先备份，并在隔离 PostgreSQL 测试库执行 `prisma migrate deploy` 和 Prisma Client 生成。需要配置 `BACKUP_ENCRYPTION_KEYS`、`BACKUP_ACTIVE_ENCRYPTION_KEY_ID`、`BACKUP_GLOBALS_DATABASE_URL`、绝对路径 `BACKUP_DIR`、`RESTORE_TEST_DATABASE_URL`、`INTEGRATION_ALLOWED_HOSTS`。`BACKUP_GLOBALS_DATABASE_URL` 必须使用具备 `pg_dumpall --globals-only` 所需权限的受控账号；恢复演练账号需能查询 `pg_control_system()`，通常需要只读 `pg_monitor` 权限。

## 8. 当前验收边界

当前开发容器为 Node.js 22.16.0，工作区依赖未安装；项目要求 Node.js 24+。静态源码契约和 TypeScript 语法解析之外，严格 TypeScript 检查、生产构建、完整依赖单测、Prisma schema validate/client generate、真实 PostgreSQL migration/并发、登录/授权 E2E、集成外部对端、备份恢复、Windows 安装和视觉验收尚待执行。没有通过这些 Gate 前不得移除 `-rc.1`。
