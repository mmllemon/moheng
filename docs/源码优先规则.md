# 源码优先规则（动手前必过）

日期：2026-10-25

## 规则

**改任何 UI 之前，必须先跑完「四件套」，缺一件不动手。**

### 一、完整渲染路径

不是搜到一个类名就开工。要把这个组件的 JSX **从 `return` 到闭合完整打印**，包括：

- 它的全部条件分支（`? :`、`&&`、`switch`）
- 每个分支下渲染什么
- 谁在它上面、谁在它下面（父子链，不是猜测）

做法：`js.indexOf('function XXX(')` 定位，然后找该函数内第一个 `return h.jsx`，向后截取到下一个 `\nfunction ` 之前。

### 二、它自己全部 CSS

同一个类名的**所有**规则，不是第一条：

```js
const re = new RegExp(`[^{}]*${key}[^{}]*\\{[^}]*\\}`, 'g');   // 全部匹配
```

特别注意：
- 通用规则 + `[class*=]` 后代覆盖 + `data-*` 状态变体 + 媒体查询
- 同名的**重复定义**（moheng 自己踩过两次：`.workspace-card` 有两条，旧的覆盖新的）
- 父容器的 padding / margin（子元素实际位置 = 父 padding + 子 margin）

### 三、父子链实测

改之前先量**当前状态**的几何：

```js
const chain = [];  let el = target;
while (el && depth < 8) {
  chain.push({ tag, cls, size, pos, bg, border, radius, shadow, padding, overflow });
  el = el.parentElement;
}
```

要回答：
- 这个元素外面有几层？每层是什么（容器 / 卡片 / 侧边栏）？
- 每层的圆角、阴影、背景各是什么？谁才是「纸」？
- 它与参照物（侧栏、窗口控制区、视口）的坐标差是多少？

### 四、参照物对齐

凡是「平齐」「居中」「间距」这类要求，必须**两边都量**：

- 参照物 A 的 y / x / 高度
- 目标 B 的 y / x / 高度
- 差值是 `padding` 造成的，还是 `margin`，还是父容器起点不同？

不量就写，等于猜。

## 执行检查清单

动手前逐条打勾：

- [ ] 打印了目标组件的完整 return（含全部分支）
- [ ] grep 了该类名的全部 CSS 规则（含重复定义）
- [ ] 量了当前 DOM 的父子链（每层 bg / border / radius / shadow / padding）
- [ ] 量了参照物与目标的坐标差
- [ ] 确认了「这个类属于哪个组件、在哪个条件分支、挂在谁下面」

缺任何一条，先补齐再改代码。
