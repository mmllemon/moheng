# 设置页固定栏问题与指标卡修正

日期：2026-10-23

用户指出「这里也有一个固定栏，原本这个刷新按钮是在标题栏的」。

---

## 一、根因：设置页存在第二层固定栏

### 实测

「登录安全」页同时出现了两个「栏」：

```
.settings-titlebar   y=31  h=52   「登录安全」          ← 设置窗标题栏（正确）
.page-header         y=63  h=66   「刷新」              ← 页面内粘性栏（多余）
```

`.page-header` 的规则：

```css
.settings-content .page-header {
  position: sticky;
  top: -20px;
  z-index: 8;
  isolation: isolate;
  margin: calc(-1 * var(--space-24)) calc(-1 * var(--space-40)) var(--space-24);
  padding: 20px 84px 14px 40px;
  background: var(--bg);
}
/* 外加 ::before/::after 两层纸纹 */
```

**这是一整套「粘性头部 + 纸纹」实现，共 34 行**，压在设置窗标题栏下面，形成第二层固定栏。

### hana 没有这个模式

查证结果：

```
hana 全库 page-header 类：0 个
hana 全库 position:sticky：只有 3 处
  ① ._channelNewMessagesBtn（「新消息」按钮，sticky bottom）
  ② ._previewPanelBody .preview-csv thead th（表格表头）
  ③ .cm-csv-table-widget th（表格表头）
```

**没有任何页面级粘性头部。**

hana 的 `._titlebar_7cee1`：

```css
display: flex;
align-items: center;
justify-content: space-between;
gap: var(--space-16);
min-height: 52px;
padding: var(--space-8) var(--settings-content-inset);
flex: 0 0 auto;
```

结构是 `[<h1>] [关闭按钮]` 两段。

### 修正

`.page-header` 退回普通块级流式布局：

```css
.settings-content .page-header {
  position: static;
  z-index: auto;
  margin: 0 0 var(--space-24);
  padding: 0;
  background: transparent;
}
```

页内 `h1` 降级为区块标题（`--fs-body`），因为页面标题已由 `.settings-titlebar` 承担。

## 二、刷新按钮回到标题栏

### 上一轮我做错了

上一轮我判断「hana 标题栏不承载页面级操作」，于是把刷新按钮移到了内容区的独立工具行。**这导致它又占了一行，正是用户说的「这里也有一个固定栏」。**

### 正确做法：标题栏三段结构

```jsx
<div className="settings-titlebar">
  <h1 className="settings-titlebar-title">{title}</h1>
  <div className="settings-titlebar-actions" id="settings-titlebar-actions" />
  <button className="settings-titlebar-close">×</button>
</div>
```

`justify-content: space-between` 天然支持三段：`[标题] [操作] [关闭]`。

### 页面如何注入按钮

用 portal，不让 Layout 知道哪个页面有什么按钮：

```tsx
// Ui.tsx
export function TitlebarActions({ children }: { children: ReactNode }) {
  const [host, setHost] = useState<HTMLElement | null>(null);
  useEffect(() => {
    setHost(document.getElementById('settings-titlebar-actions'));
  }, []);
  return host ? createPortal(children, host) : null;
}
```

```tsx
// SystemSecurityPage.tsx
<TitlebarActions>
  <Button variant="secondary" onClick={refetchAll}>
    <RefreshCcw size={15} />刷新
  </Button>
</TitlebarActions>
```

### 实测

```
.settings-titlebar          y=31  h=52  「登录安全刷新」
.settings-titlebar-title    y=46  h=22  「登录安全」
.settings-titlebar-actions  y=41  h=32  「刷新」
.settings-titlebar-close    y=41  h=32
```

三者同一行，`.page-header` 已完全消失。

## 三、指标卡：从「KPI 条」改为独立卡片

### 两个冲突的规范

moheng 有两条并存的指标卡规范：

**① `stat-metrics.css` 的「KPI 条」**

```css

  padding: var(--space-16) 0;
  border: 0;
  border-top: 1px solid ...;
  border-bottom: 1px solid ...;
  border-radius: 0;

html .settings-content .security-metrics > * {
```

卡片压成一条带分隔线的区域，靠竖线区分。

**② hana 的独立卡片**


### 修正

从 `stat-metrics.css` 的通用规则里排除 `.settings-content .security-metrics`，并重写：

```css
.settings-content .security-metric {
```

实测：三张卡各 `213×78`，`bg=rgb(252,250,245)`，`radius=14.7272px`，间距 16px。

## 五、表格斑马纹：那是 Markdown 预览的规格

### 我之前的判断错了

代码里有一句注释：

```css
/* 斑马纹：Hana 用 4.5% 墨色，几乎看不见但足以区分行 */
.data-table tbody tr:nth-child(even) td {
  background: color-mix(in srgb, var(--text) 4.5%, transparent);
}
```

**`4.5%` 这个值确实来自 hana，但用的是 `._previewPanelBody .preview-markdown tbody tr:nth-child(2n) td`** —— 那是 Markdown 文档预览的表格，不是业务台账表。

hana 的业务表是 `.cm-table-widget`：

```css
.cm-table-widget th,
.cm-table-widget td {
  border: 1px solid var(--border);
  padding: .3em .6em;
  text-align: left;
}
.cm-table-widget th {
  background: var(--overlay-light);
  font-weight: 600;
}
```

**靠格线区分单元格，不靠斑马纹。**

### 修正

```css
.data-table tbody tr:nth-child(even) td { background: transparent; }
.data-table th,
.data-table td { border: 1px solid var(--border); }
.data-table thead th { background: var(--overlay-light); font-weight: 600; }
```

## 六、滚动条：三个真实缺陷

### 6a. `@supports` 块让 Chrome 走系统滚动条

```css
@supports selector(::-webkit-scrollbar) {
  * { scrollbar-width: auto; }     ← 这行是关键
}
```

**一旦声明 `scrollbar-width`，Chrome 就用系统标准滚动条（30px 占位式），并完全忽略 `::-webkit-scrollbar` 的 width 设置。**

已移除。

### 6b. `scrollbar-gutter: stable` 预留 35px 空白

上一轮我加的。实测：

```
scrollbar-gutter: stable → 内容区右侧预留 35px 空白
```

在窗口右缘形成一条看起来像粗滚动条的灰带。已移除。

### 6c. `.settings-content` 的滚动条被完全隐藏

```css
.settings-content { scrollbar-width: none; -ms-overflow-style: none; }
.settings-content::-webkit-scrollbar { width: 0; height: 0; display: none; }
```

这是配合旧 JS 滚动条 `.settings-scrollbar` 的规则，而那个组件 `display: none` 且从未初始化。已移除。

### 环境事实：Chrome 156 + Windows 11 走 overlay 模式

纯净测试（最小 HTML，只写 `::-webkit-scrollbar { width: 4px }`）：

```
offsetWidth=302  clientWidth=300  → 滚动条占用 2px
```

**在 overlay 模式下，`::-webkit-scrollbar` 的 width 不完全生效（2px 而非 4px），且滚动条自动淡入淡出。**

这不是代码问题，是 Chrome 的平台行为。实际效果是「细且静默」，符合 hana 的视觉意图。

## 八、方法教训

**这一轮暴露了一个反复出现的问题：我把「值相似」当成「语义相同」。**

| 项 | 我看到的值 | 实际语义 |
|---|---|---|
| 表格斑马纹 `4.5%` | hana 里确实有 | 但那是 Markdown 预览，不是业务表 |
| `scrollbar-width: auto` | 以为是「用 auto 让伪元素接管」 | 实际是「让系统滚动条接管」 |
| 指标卡 `gap: 0` + 分隔线 | 以为是卡片布局 | 实际是「KPI 条」，与独立卡片是两种空间语言 |

**判断依据应该是「这个值服务于哪种界面形态」，不是「这个值在 hana 里存不存在」。**
