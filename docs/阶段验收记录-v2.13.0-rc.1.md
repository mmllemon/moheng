## 2. 静态验证

自动验证包括版本一致性、Prisma schema/migration 的源码契约、服务端 ADMIN guard、授权快照状态流、截断时的安全推断、UI 二级导航、编码推荐与手动编辑保留、巡检按钮样式。

`npm run validate:release-candidate` 在当前环境可执行，不依赖工作区安装包。该命令只验证静态源码约束，不等价于业务集成或浏览器 E2E。

## 3. 目标环境必做 Gate

1. Node.js 24+ 安装锁定依赖，执行 `npm run lint`、`npm test`、`npm run build`。
2. 执行 `npm run db:generate -w @cms/api` 与 `npm run db:deploy -w @cms/api`，在隔离 PostgreSQL 验证新增迁移及旧业务金额/表数据无非预期改变。
3. 管理员/普通用户、项目成员/非成员访问矩阵与快照 API；验证只有 ADMIN 可读完整授权快照。
4. 测试并发生成/完成授权复核、快照超过记录上限、截断时不误报无权限或无负责人。
5. 浏览器测试 1920/1366/1024/移动宽度的侧栏滚动、系统二级导航和键盘操作；检查深浅主题、窄屏布局和数据质量按钮视觉权重。
6. 对字典分类、字典项、参数键分别测试中文名、英文名、混合字符、未知汉字、长名称、重复编码和手动覆盖。
7. 完成 Windows 目标部署与备份恢复流程回归。

## 4. 环境限制

开发容器为 Node.js 22.16.0（项目要求 >=24）且缺少工作区依赖，因此本阶段不宣称严格类型检查、前后端生产构建、Prisma Client 生成、真实 PostgreSQL 迁移、浏览器 E2E 或 Windows 实机验收已通过。通过静态检查并不能替代这些 Gate。
