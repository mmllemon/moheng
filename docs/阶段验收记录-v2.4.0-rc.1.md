# 墨衡 v2.4.0-rc.1 阶段验收记录

- 基线：`v2.3.0-rc.1`
- 目标候选：`v2.4.0-rc.1`
- 日期：2026-10-15
- 验收性质：静态源码契约、纯渲染逻辑与语法转译；不是生产发布验收

## 1. 实施范围

1. 新增 `ReportStudioPage`，项目级和公司级工作室入口，采用固定版本 Univer Sheets Core 编辑工作簿。
2. 增加 schema v2 模板定义，支持指定单元格的白名单字段绑定、单元格样式留存、多个独立单行集合区域自动延伸。
3. 扩展项目和公司级数据源；公司级包括项目清单、跨项目分供合同、业主应收、收退款、实际成本、已生效变更、进度款和分供应付。
4. 新增纯报表渲染器与 ExcelJS 工作簿输出适配器，使屏幕预览与 XLSX 使用相同的模板绑定和行扩展规则。
5. 新增正式 `ReportPreviewPage`；标准台账 XLSX 与综合报表 XLSX 都从预览页面确认后进入 PostgreSQL 后台任务。
6. 旧式报表设计器的 XLSX 按钮也改为导航至正式预览页。
7. 下拉选择和普通日期选择继续统一使用 `SelectField` 与 `DatePicker`；静态扫描没有发现业务页面自行使用原生 `<select>` 或 `input type="date"`。
8. 综合报表工作室作为独立路由模块注册于 `/api/reports/studio`，模块目录扩充为 16 个 API 模块；未新增数据库迁移，继续使用已存在的模板、版本和 BackgroundJob 表。
9. 添加 `validate-report-studio-v2.mjs` 与项目级 E2E 发布检查清单。

## 3. 当前阻塞/未执行项

- 当前容器 Node.js 为 22.16.0，仓库 `engines` 要求 Node.js 24+。
- 仓库依赖没有完整安装，npm registry 无法访问；没有生成/提交 `package-lock.json`。直接依赖 Univer 版本是精确固定的，但传递依赖版本尚未被 lockfile 固化。
- 未运行后端 `npx tsc -p tsconfig.json --noEmit`、前端 `npx tsc -b --noEmit` 或工作区严格 TypeScript 检查。因此不能宣称用户先前列出的 74 条原始 `tsc` 错误已经在完整依赖环境中全量复验关闭；目前只通过了根因静态检查与 TS/TSX 语法转译。
- 未运行 Vite/TypeScript 生产构建、lint、完整 API 测试套件，未执行 Prisma validate/generate、真实 PostgreSQL 查询联测或浏览器 E2E。
- Univer 1.0.4 的真实浏览器编辑交互、复制粘贴、撤销重做、主题兼容、样式/多工作表保存复开尚未实测；Excel/WPS 文件打开、修复提示和打印分页尚未实测。
- 公司级大数据报表在数据源到达当前上限时会标记相关汇总不可用，不会自动切换为数据库端完整聚合。发布前必须在真实数据规模上核实上限是否够用。
- 预览和后台导出使用相同模板版本及数据源口径，但 Worker 在执行时重新查询业务数据。若预览后业务记录发生变化，最终文件可能与预览数值不同；当前没有冻结完整业务数据快照。

## 4. 发布 Gate

1. Node 24+ clean install，生成、审查、提交 `package-lock.json`，完整构建/lint/tsc 测试通过。
2. 使用测试数据库和脱敏业务数据验证项目、公司级所有数据源，特别是公司级权限限域与超限摘要不显示虚假的部分总额。
3. 验证模板创建、保存、发布、共享读取、只读副本、版本冲突、模板越权和绑定白名单。
4. 浏览器验证编辑、绑定、多个集合区域扩展后下方区域不覆盖、样式和多工作表保存复开；验证普通读者只取得已发布定义，且项目模板不能跨项目预览。
5. XLSX 在 Excel 与 WPS 打开无修复提示，样式、数值、日期、合并、打印设置和说明页正确。
6. 正式预览检查后再导出；记录并验证预览数据与 Worker 在导出时重新取数之间的时间差提示。
7. 完成 Windows 原生部署、备份恢复及关键合同/结算/应收应付回归后才考虑移除 RC 标记。
