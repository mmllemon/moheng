## 2. 测试执行方式说明

当前容器只有 Node.js `v22.16.0`；项目要求 Node.js `>=24.0.0`。项目依赖无法联网安装，`npm install` 请求 npm registry 时返回 `EAI_AGAIN` 后超时，故 `tsx`、Prisma CLI、Fastify、Vite 等本项目依赖不可用。为避免虚报，本轮没有声称官方 `npm test`、完整构建或类型检查已经通过。

11 项独立测试通过的具体方式是：将金额与凭证相关源文件和测试文件复制到临时目录，仅在临时副本中将测试的 `.js` 相对导入路径改为 `.ts`，再用 Node 22 的实验性 TypeScript type stripping 执行。生产源码及项目测试文件没有因此修改导入路径。

## 4. Windows 验收清单（发布前必须完成）

1. 在 Node.js 24 LTS + PostgreSQL 16 Windows 测试机复制项目，配置 `apps/api/.env` 中数据库连接、32 字符以上随机 `JWT_SECRET` 和管理员密码。
2. 运行 `npm install`、`npm run db:generate`、`npm run lint`、`npm run build`，逐项保存命令输出；任何失败都应阻止发布。
3. 对空数据库运行 `npm run db:deploy` 与 `npm run db:seed`，检查 `_prisma_migrations` 并确认管理员可登录。
4. 对 v1.1 的脱敏数据库副本执行升级，先备份；核对项目原始合同额、有效合同额和历史变更，不得自动把旧内部 `CONFIRMED` 状态当作外部生效。
5. 实测 A/B 凭证、C 类待核验、非提交人核验通过、提交人自核验被拒、核验驳回/争议、补充材料、重复确认阻止、附件内容篡改后下载被拒。
6. 验证 `INCREASE` / `DECREASE`、金额精度、有效合同额不能变为负数、并发确认不丢更新。
7. 为证据目录设置 NTFS ACL，仅授权 API 运行身份和备份管理员；验证附件与数据库一起备份恢复。
8. 验证 Windows 启停脚本、日志、可选开机任务及重启后的健康检查。
