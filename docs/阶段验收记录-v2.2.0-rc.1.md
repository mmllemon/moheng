# 墨衡 v2.2.0-rc.1 阶段验收记录

- 日期：2026-10-15
- 基线：`v2.1.0-rc.1`
- 本候选：`v2.2.0-rc.1`
- 验收性质：源码契约与静态检查；不是生产发布验收

## 1. 本轮范围

1. 新增 `apps/api/src/platform/app-info.ts`，集中维护应用版本和 API 主版本。
2. 新增 `apps/api/src/platform/module-registry.ts`，统一注册现有 15 组 Fastify 路由插件，并为集成目录提供稳定的模块 ID 与用途说明。
3. 新增 `GET /api/meta`，提供产品版本、API 主版本、API 基础路径、兼容策略和模块目录。
4. 新增 `/health/live` 纯存活探针和 `/health/ready` 数据库就绪探针；保留 `/health` 就绪别名兼容旧 Windows 启停脚本。
5. 所有响应附加 `x-request-id`；错误日志增加请求 ID，Pino 常见凭证字段配置脱敏。
6. 生产环境在未配置 `CORS_ORIGIN` 时不再预设 Vite 开发来源；开发模式仍允许本地 Vite 默认来源。
7. 版本号统一至 `2.2.0-rc.1`，增加 `scripts/validate-architecture.mjs` 并并入发布候选检查。
8. 补充框架演进方案，明确模块边界、API 兼容、外部适配器、技术升级原则和 Gate。

## 3. 数据库和业务安全边界

- 本轮没有修改 Prisma Schema。
- 本轮没有增加数据库迁移。
- 不修改已发布迁移内容。
- 不改变原始合同金额与当前有效合同额的区分、外部确认生效逻辑、内部审批、结算过账、应收应付、退款反向核销、预付款、质保金或单位主数据规则。
- 不新增 Redis、消息队列、独立服务、对象存储或其他必须常驻服务。
- `/api/meta` 不包含用户权限判断；真实接口必须继续在服务端检查认证与项目访问范围。

## 4. 尚未完成的发布门禁

当前执行环境报告 Node.js `22.16.0`，低于项目声明的 `>=24.0.0`，且项目依赖不能保证完整安装。因此本轮未声称以下工作通过：

1. 干净环境 `npm ci` 和已提交依赖锁文件验证；
2. API/Web 完整严格类型检查、lint 与生产构建；
3. Prisma validate/generate 与真实 PostgreSQL 历史迁移；
4. API 元信息、探针、CORS、日志脱敏在真实 Fastify 进程下的集成测试；
5. Windows 原生安装、启动、升级、回滚与备份恢复；
6. Edge/Chrome 浏览器 E2E 与 Excel/WPS XLSX 打开/打印验收。

## 5. 继续推进条件

在 Node.js 24 LTS + PostgreSQL 的可复现环境运行 `scripts/windows/verify-release-candidate.ps1` 以及 `npm run validate:release-candidate`；补齐失败项后再执行数据库副本迁移、关键财务流程联测、备份恢复与 Windows 浏览器 E2E。所有 Gate B 条件通过前，版本保持 `rc`。
