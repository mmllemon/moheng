# 侧栏悬停抽屉实现记录

> 按 Hana 的 `_fpOverlay` 机制，给 moheng 侧栏补上「收起后悬停滑出」的抽屉态。
> 日期：2026-10-23

---

## 一、改动前的事实核查（推翻了两个误判）

动手前先实测，发现两件事与我之前的判断不符：

### 误判一：动效 token 早就对齐了

我前几轮说「第一步改时长 10 分钟见效」，实测发现 moheng 早就是对的：

```css
--duration-space: 0.4s                          /* 与 Hana 的 .4s 一致 */
--ease-ios: cubic-bezier(0.22, 1, 0.36, 1)      /* 与 Hana 逐位一致 */
```

侧栏的 `transition` 也已经用了这两个 token：

```css
.app-sidebar {
  transition: width var(--duration-space) var(--ease-ios),
              margin var(--duration-space) var(--ease-ios),
              opacity var(--duration-space) var(--ease-ios),
              border-color var(--duration-space) var(--ease-ios),
              box-shadow var(--duration-space) var(--ease-ios);
}
```

**所以「改时长」这一步无事可做，那部分工作之前已经做完了。**

### 误判二：画布上的 `transition: all` 是假象

实测读到 `.app-content` 的 `transitionProperty: all`，我一度以为踩了「不要给画布加 transition」的坑。

进一步查：

```
computed transition: all
transitionDuration:  0s        ← 关键
内联样式:            (无)
匹配的 CSS 规则:     (无)
```

**`duration: 0s` 说明这是浏览器默认值（`transition: all 0s ease 0s`），不是真实过渡。** 画布没有问题。

### 真实差异：只有一处

| 项 | Hana | moheng（改动前） | 状态 |
|---|---|---|---|
| 宽度动画 | `.4s` + `ease-ios` | 同 | ✅ 已对齐 |
| 收起方式 | `width: 0` + `opacity: 0` | 同 | ✅ 已对齐 |
| 画布跟随 | flex 自然响应 | 同 | ✅ 已对齐 |
| **悬停抽屉** | `_fpOverlay` | **无** | ❌ **缺** |

**唯一缺的是抽屉。**

## 二、实现

### 2.1 状态与探测（Layout.tsx）

```tsx
const [sidebarDrawerOpen, setSidebarDrawerOpen] = useState(false);
const sidebarToggleRef = useRef<HTMLButtonElement>(null);
const sidebarDrawerRef = useRef<HTMLDivElement>(null);

useEffect(() => {
  if (!collapsed) { setSidebarDrawerOpen(false); return; }

  let timer: number | null = null;
  const clearTimer = () => {
    if (timer !== null) { window.clearTimeout(timer); timer = null; }
  };

  const onMouseMove = (event: MouseEvent) => {
    const btn = sidebarToggleRef.current?.getBoundingClientRect();
    const drawer = sidebarDrawerRef.current?.getBoundingClientRect();
    const inBtn = !!btn
      && event.clientX >= btn.left && event.clientX <= btn.right
      && event.clientY >= btn.top && event.clientY <= btn.bottom;
    const inDrawer = !!drawer
      && event.clientX >= drawer.left && event.clientX <= drawer.right
      && event.clientY >= drawer.top && event.clientY <= drawer.bottom;

    if (inBtn || inDrawer) {
      clearTimer();
      setSidebarDrawerOpen(true);
      return;
    }

    if (timer === null) {
      timer = window.setTimeout(() => {
        timer = null;
        setSidebarDrawerOpen(false);
      }, 300);
    }
  };

  window.addEventListener('mousemove', onMouseMove);
  return () => {
    window.removeEventListener('mousemove', onMouseMove);
    clearTimer();
  };
}, [collapsed]);
```

**与 Hana 的一致性**：

| 参数 | Hana | moheng |
|---|---|---|
| 关闭延迟 | `rc = 300` | 300 |
| 保活条件 | 在触发区 **或** 在抽屉内 | 同 |
| 只在收起态生效 | `if (!collapsedRef.current)` | `if (!collapsed)` |
| 监听方式 | `window` mousemove | 同 |

### 2.2 DOM 结构

```jsx
{collapsed && (
  <div ref={sidebarDrawerRef}
       className={`sidebar-drawer ${sidebarDrawerOpen ? 'is-open' : ''}`}
       aria-hidden={!sidebarDrawerOpen}>
    <div className="sidebar-drawer-inner">
      {/* titlebar 占位：与主侧栏同高，保证 profile 位置对齐 */}
      <div className="app-sidebar-titlebar">
        <span className="sidebar-toolbar-spacer" />
      </div>
      <div className="app-sidebar-profile">
        <span className="sidebar-brand-mark"><AppIcon id={appIcon} /></span>
        <div className="sidebar-wordmark"><strong>墨衡</strong><span>工程经营管理</span></div>
      </div>
      <div className="app-sidebar-scroll">
        <nav aria-label="业务导航（抽屉）">
          {/* 复用主侧栏的导航渲染逻辑 */}
        </nav>
      </div>
    </div>
  </div>
)}
```

**只在 `collapsed` 时挂载**，展开态完全不渲染（省 DOM、省内存）。

### 2.3 CSS

```css
.sidebar-drawer {
  position: fixed;
  top: var(--panel-edge-gap);       /* 6px，与主侧栏同起点 */
  bottom: var(--panel-edge-gap);
  left: var(--panel-edge-gap);
  z-index: 31;                      /* 高于侧栏 10，低于 traffic-strip 32 */
  width: var(--sidebar-width);      /* 240px */
  display: flex;
  flex-direction: column;
  border: var(--panel-card-border);
  border-radius: calc(var(--panel-card-radius) * var(--corner-radius-scale, 1));
  corner-shape: squircle;
  background: var(--sidebar-bg);
  box-shadow: 0 4px 32px rgba(0, 0, 0, 0.05);
  overflow: hidden;
  transform: translateX(calc(-100% - 12px));
  opacity: 0;
  pointer-events: none;
  visibility: hidden;
  transition:
    transform var(--duration-space) var(--ease-ios),
    opacity var(--duration-space) var(--ease-ios),
    visibility 0s linear var(--duration-space);
}

.sidebar-drawer.is-open {
  transform: translateX(0);
  opacity: 1;
  pointer-events: auto;
  visibility: visible;
  transition:
    transform var(--duration-space) var(--ease-ios),
    opacity var(--duration-space) var(--ease-ios),
    visibility 0s linear 0s;
}

.sidebar-drawer-inner {
  display: flex;
  flex-direction: column;
  height: 100%;
  min-height: 0;
}

.sidebar-drawer .app-sidebar-profile { flex-shrink: 0; }
.sidebar-drawer .app-sidebar-scroll {
  flex: 1;
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;
}
```

**几个关键设计：**

**① 位移量 `calc(-100% - 12px)`**

与 Hana 的 `slide = width + 12` 一致。那 12px 是滑出余量，确保完全移出视野。

**② `visibility` 的延迟切换**

```css
/* 关闭时：等过渡结束才隐藏 */
visibility 0s linear var(--duration-space);

/* 打开时：立即显示 */
visibility 0s linear 0s;
```

这是标准技巧：`visibility` 不能平滑过渡，但可以延迟。关闭时延后 0.4s 才 `hidden`，动画期间仍可见。

**③ z-index 分层**

```
侧栏            z-10
抽屉            z-31    ← 高于侧栏
traffic-strip   z-32    ← 高于抽屉，开关按钮不被遮挡
```

## 三、过程中修掉的三个问题

### 问题一：类名写错导致图标竖排

第一版我给抽屉的导航项写了 `sidebar-nav-item`，但主侧栏用的是 `sidebar-nav-link`。

后果：抽屉里的图标和文字竖排（没有 flex 布局）。

```diff
- className={`sidebar-nav-item${isActive ? ' is-active' : ''}`}
+ className={`sidebar-nav-link${isActive ? ' active' : ''}`}
```

**教训：复用样式必须核对真实类名，不能凭命名习惯猜。**

### 问题二：抽屉盖住收起按钮

第一版抽屉 `top: 6px` 全覆盖，把 traffic-strip 里的开关按钮盖住了（虽然 z-index 更高，但视觉上紧贴）。

我先改成 `top: calc(6px + 44px)` 让出按钮区，但实测发现这样 profile 位置和主侧栏对不上（主侧栏 profile 在 y=23，抽屉在 y=67）。

最终改回 `top: 6px`，并在抽屉内部加 titlebar 占位：

```jsx
<div className="app-sidebar-titlebar">
  <span className="sidebar-toolbar-spacer" />
</div>
```

**这样 profile 位置精确对齐（都是 y=23），滑出时没有视觉跳跃。**

### 问题三：tooltip 遮挡品牌标识

开关按钮有 `data-tooltip="展开导航"`，抽屉打开时 tooltip 会浮在品牌标识上方。

```diff
- data-tooltip={collapsed ? '展开导航' : '收起导航'}
+ data-tooltip={sidebarDrawerOpen ? undefined : (collapsed ? '展开导航' : '收起导航')}
```

抽屉打开时移除 tooltip（此时用户已经看到抽屉，不需要提示）。

## 五、与 Hana 的差异（有意为之）

| 项 | Hana | moheng | 原因 |
|---|---|---|---|
| 动画实现 | Framer Motion spring | CSS transition | 不为一个抽屉引入整库 |
| 抽屉内容 | 完整侧栏副本 | 导航 + 品牌（不含项目列表） | 抽屉只做快速跳转，项目切换在主侧栏 |
| 触发区 | `ki()` 返回按钮矩形 | 按钮 ref 的矩形 | 等价 |
| 兜底 | 拿不到矩形时全屏 | 无兜底（ref 必然存在） | moheng 按钮常驻，不会拿不到 |

**关于动画实现**：Hana 用 `paperGentle = spring(350, 32, 1)`（ζ≈0.855，有轻微回弹），moheng 用 `cubic-bezier(0.22, 1, 0.36, 1)`（不过冲）。

视觉差异：Hana 的抽屉会有极轻微的回弹，moheng 是平滑减速。

**如果要完全一致**，可以用 CSS `linear()` 函数模拟 spring 曲线（Hana 自己也这么做，`--ease-paper-spring` 就是 50 个关键点的 `linear()`）。
