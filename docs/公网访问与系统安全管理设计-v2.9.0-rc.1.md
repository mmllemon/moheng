# 墨衡公网访问与系统安全管理设计（v2.9.0-rc.1）

## 1. 目标与边界

本版本采用“同源 Web + Fastify API + PostgreSQL”的模块化单体，不拆分微服务。公网入口使用 Windows 主机上的 Caddy 终止 TLS，再反代到仅监听 `127.0.0.1:3001` 的墨衡 API。PostgreSQL 仍只允许本机/受控管理网络访问，不建立公网数据库端口。

本版本提供系统管理员 TOTP MFA、会话记录/吊销、刷新令牌轮换与重放检测、账号与 IP 双维度失败限流、账号停用/密码重置/强制改密及安全事件页面。它不提供邮件/短信找回、地理位置识别、自助 MFA 解绑或云端托管身份认证；管理员丢失所有恢复因素时需走经授权的受控数据库恢复流程；若只有一位管理员，不要在尚未验证应急恢复流程前启用公网入口。

## 2. 公网模式启动闸门

仅当 `PUBLIC_BASE_URL` 配置为最终 HTTPS 源站地址时才启用公网模式。服务端启动同时要求：

- `NODE_ENV=production`
- `PUBLIC_BASE_URL=https://your-real-domain.example`，使用正式主机名，不包含路径、查询或片段
- `COOKIE_SECURE=true`
- `MFA_ENCRYPTION_KEY` 为独立随机 32 字节十六进制密钥（64 个十六进制字符）
- API `HOST=127.0.0.1`（公网模式启动闸门强制回环绑定，避免直接暴露 Fastify 端口）
- `TRUST_PROXY` 必须非空且仅列出真实反向代理的地址/CIDR；不允许 `*`、`true` 或 `1`
- `CORS_ORIGIN` 为空（同源部署）或只包含 `PUBLIC_BASE_URL` 的 origin

生产部署应生成两个互不相同的随机秘密：`JWT_SECRET`（至少 32 字符）和 `MFA_ENCRYPTION_KEY`（32 随机字节十六进制）。MFA 种子以 AES-256-GCM 加密保存在 PostgreSQL；恢复码哈希也使用 MFA 密钥作 HMAC，因此轮换该密钥前必须安排管理员重新登记 MFA 并生成新恢复码，或先执行专门的受控迁移。丢失/误换 MFA 密钥会使已登记的 TOTP 种子无法解密、已发恢复码无法校验，因此必须通过受控秘密管理和离线备份保存它，不能把值提交到 Git。

公网模式启用 HSTS、限制性 Content-Security-Policy，并不注册 Swagger UI/API 文档路由。应用仍提供健康检查用于运维探测，健康状态不包含数据库凭据。

## 3. Windows + Caddy 部署拓扑

```text
Public browser
  -> DNS domain / public TCP 443 (TCP 80 used for certificate validation/HTTP redirect)
  -> Windows Firewall + Caddy automatic HTTPS
  -> reverse_proxy 127.0.0.1:3001
  -> Fastify + React SPA
  -> PostgreSQL 127.0.0.1:5432 (not forwarded)
```

部署步骤：

1. 为域名配置 A 记录指向公司公网 IPv4（或使用经测试的动态 DNS）。确认 ISP/路由器没有 CGNAT；若没有可入站公网地址，不要通过暴露数据库或映射 Node 端口绕过，改用合适的公网入口方案。
2. 在 Windows 安装 Caddy，并将 `deploy/caddy/Caddyfile.example` 复制为 Caddy 实际读取的 `Caddyfile`；替换域名。确保 Caddy 进程运行账号可读取配置并写入其受保护的数据目录。
3. 在公司路由器上仅转发 TCP 80/443 到 Windows 主机；在 Windows 防火墙中仅为 Caddy 建立必要入站规则。**不要**为 `3001` 或 PostgreSQL `5432` 添加公网入站规则。
4. 复制 `apps/api/.env.example` 为 `apps/api/.env`，使用密码管理器/受控终端生成并写入 `JWT_SECRET`、`MFA_ENCRYPTION_KEY` 和数据库凭据。设置 `NODE_ENV=production`、`HOST=127.0.0.1`、`COOKIE_SECURE=true`、`PUBLIC_BASE_URL=https://你的正式域名`、`TRUST_PROXY=127.0.0.1,::1`、`CORS_ORIGIN=`。若 Caddy 不是从回环接口连接 API，请按真实架构设置精确可信代理地址，并先验证 `request.ip` 解析结果；禁止无条件信任 `X-Forwarded-For`。
5. 用 Node.js 24 LTS 执行 Windows 部署准备脚本、生成 Prisma Client、执行迁移并构建 UI/API。API 仍只监听回环接口；验证 `http://127.0.0.1:3001/health/ready` 后，再由 Caddy 对外服务。
6. 确认 `https://你的正式域名` 自动取得有效证书、浏览器没有混合内容/证书错误，并切换公网模式后浏览器需重新登录，确认刷新 Cookie 名为 `__Host-refreshToken`，属性包含 `Secure; HttpOnly; Path=/; SameSite=Lax`。
7. 使用管理员账号登录。若管理员尚未启用 MFA，会被引导进入专用受限流程；在验证器中添加 TOTP 项后输入 6 位验证码确认，并安全保存一次性恢复码。确认重新登录必须提供 TOTP/恢复码。不要把恢复码发到聊天、邮件或工单中。
8. 使用独立普通用户验证项目权限隔离；确认普通用户不能打开 `/system/security` 对应的 API，不能读取其他用户会话和安全事件；确认 API 文档 `/docs/` 在公网模式不可访问。

## 4. 登录与会话安全规则

- 访问令牌有效期 15 分钟；服务器端 `AuthSession` 固定最长 7 天，连续 12 小时无操作则强制重新登录；刷新令牌最长 7 天，单次消费并轮换。每次业务 API 请求都会检查会话未撤销、未过期且用户仍启用；会话活动时间最多每 5 分钟写一次。
- 已消费刷新令牌在 10 秒内再次出现时视为可能的跨标签页轮换竞争，返回 `REFRESH_ROTATION_RACE`，浏览器最多延迟重试一次且不清除共享 Cookie；超过该窗口的重放会撤销关联会话并记录 `REFRESH_TOKEN_REUSE`。浏览器端刷新请求采用 single-flight，减少并发刷新引起误撤销。
- 账号/IP 组合键和来源 IP 分别维护 15 分钟窗口失败计数，达到 8 次后临时阻断 15 分钟；组合键避免一次攻击在某个来源网络外全局锁死目标账号。登录、刷新及退出的 Cookie 端点要求 Origin 与 `PUBLIC_BASE_URL` 严格同源。此外登录路由还有每 IP 15 分钟上限。反代地址不可信时，IP 限流不能正确区分真实访客，故代理可信范围必须显式配置。
- 管理员公网登录必须启用 TOTP。恢复码只在生成时展示，数据库只存 HMAC 哈希；单个恢复码只能消费一次。MFA 的加密密钥和 JWT 密钥不能相同。
- 新建账号和管理员重置密码会设置强制改密标记；密码重置、账号停用和 MFA 重置会撤销该账号全部现有会话。不能停用最后一个启用状态的管理员，也不能通过同一会话停用自己或自行重置自己的 MFA。
- 安全事件记录账号、事件、时间、来源 IP、User-Agent、会话 ID 和有限的业务上下文。安全事件超过 180 天、失败限流桶超过 7 天、过期刷新令牌超过到期后 30 天在刷新流程中清理。IP/设备信息属于受限个人信息；当前页面不做地理定位，IP 不能作为实际地理位置的确定证据。
- 日志不得记录密码、TOTP、恢复码、JWT 或原始刷新令牌。所有秘密通过环境文件/受控秘密存储配置，限制文件 ACL 并纳入备份恢复流程。

## 5. 关键验收项

- 公网模式缺少正式 HTTPS URL、`COOKIE_SECURE=true` 或合法 MFA 密钥时，API 应拒绝启动。
- 远程访问 HTTP 会被 Caddy 规范化跳转到 HTTPS；响应包含 HSTS、基础 CSP、`X-Content-Type-Options` 与 `X-Frame-Options`。
- 公网模式访问 `/docs/` 得到 404；API 端口 3001 无法从公网直接连通；PostgreSQL 5432 无公网监听/转发。
- 未登录/临时 MFA 或强制改密令牌不得访问业务 API；会话撤销/账号停用后，当前 access token 与 refresh token 均不能继续访问。
- 双并发刷新只允许一个单次令牌消费成功；再次使用已消费令牌触发会话撤销事件。
- TOTP 有效向量测试通过，过期/错误码被拒绝；相同时间步 TOTP 不能重复使用；恢复码每个只能成功使用一次。
- 登录账号/IP 达到失败阈值后被限流，成功登录后对应失败桶清除。
- 账号密码重置后必须改密；管理员启用 MFA 后必须在下次登录验证；停用账号或撤销其他设备会话后立即被拒绝。
- 项目级授权/财务金额规则未因安全工作台调整而变化。

## 6. 验收限制与回退注意

本提交需在 Node.js 24+ 下安装锁定依赖、执行 `prisma generate`、`prisma validate`、严格 lint/build、数据库迁移与真实浏览器测试。本开发环境为 Node.js 22 且依赖未安装，因此不把静态检查结果当作生产安全认证。

这是一个有数据库迁移的安全升级。不要在保留公网入口的情况下直接回滚到旧版认证逻辑：旧版本不会检查 `AuthSession` 的即时吊销状态，也不会检查账号 `authVersion`。回滚时应先在 Caddy 关闭公网入口/限制访问，再恢复应用版本，并完成会话与令牌安全处理后才重新开放。
