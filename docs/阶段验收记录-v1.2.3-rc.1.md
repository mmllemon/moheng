# 阶段验收记录：v1.2.3-rc.1（对下合同与成本归集）

日期：2026-10-14

## 1. 本轮目标

补齐施工单位成本管理系统的支出侧合同关系，明确对下合同金额、已承诺成本、预计成本、实际发生成本与付款现金流之间的区别。当前基于 v1.2.2-rc.4 源码，新增内容均通过独立迁移 `20261013050000_downstream_contract_management` 加入；此前已经交付的迁移文件保持不变。

## 2. 本轮实现范围

1. 新增对下合同主数据：采购、劳务/专业分包、设备租赁、服务及其他合同；草稿、执行中、完工待结算、已结算、终止状态流转；激活后原始合同基准不可直接覆盖。
2. 新增追加式补充协议记录。合同当前金额 = 原始签约金额 + 已登记的有效补充协议增加/减少净额。
3. 新增对下付款计划与付款/退款流水。付款计划表示计划现金流，不是成本；实际付款与退款使用独立正数流水；退款必须指向同一合同下的原始非退款付款、继承原付款计划，且不能超过该原付款、合同净已付款或计划净已付款。
4. 实际成本可选关联到同项目对下合同；新增成本可以选择合同；历史成本只能依据合同、发票、验收或结算证据人工补关联，关联操作会留审计且不改动成本金额。
5. 业主侧进度款和变更签证新增 `mainContractId` 关联。迁移会为已有项目中存在主合同的收入记录回填；后续补建主合同时只补齐空关联并写审计。
6. 成本分析新增执行中/完工待结算合同额、关联合同实际成本、累计净付款、退款和“合同额减已关联实际成本（预警差额）”指标。将预警差额明确为算术差额，不冒充精确的未履约承诺或预计完工成本。
7. 新增 Windows 项目页面、付款/退款及关联成本交互、API、数据库模型、迁移、测试和设计/维护/用户文档。

## 4. 金额口径（防止重复计算）

- **对下合同金额**：原始签约合同金额加有效补充协议净额，是合同价款基准，不是预测成本。
- **已承诺但未履约金额**：严格计算需要履约、验收/计量、累计结算、应计未开票、扣款、质保金等数据。当前系统尚不具备这些完整模型，所以只展示“执行中/完工待结算合同额”，不将它称作精确未履约承诺。
- **预计成本/EAC**：应由累计实际成本加剩余工程/采购/分包工作量的预测得出。当前已有的“预计完工成本”仍是目标成本基准，不是专业 EAC 模型。
- **实际成本**：只从 `CostEntry` 汇总。付款流水不自动创建成本，退款也不自动冲减已确认实际成本；如有退货/红字/折让，仍需走单独的成本更正/冲销流程（本轮未实现）。
- **付款计划**：预计现金流计划，不是实际付款，也不是实际成本。
- **合同当前金额减已关联实际成本**：仅为预警差额，不能当作未履约承诺、应付余额或 EAC。

## 5. 部署前必须完成

由于 v1.2.2-rc.4 的五条历史迁移之外，本版本新增第六条迁移。在 Windows 测试环境部署之前，必须先完整备份测试数据库，建议复制一份独立测试库；切勿首次直接在生产库执行。

在 Node.js 24 LTS 环境及可连接 npm registry 的机器上：

```powershell
node --version
npm install
npm run validate:release-candidate
npm run db:generate
npm run lint
npm run build
npm test
```

需要保存 `package-lock.json` 并复查依赖解析后，再对测试数据库运行：

```powershell
npm run db:deploy
npm exec --workspace=@cms/api -- prisma migrate status --schema prisma/schema.prisma
```

迁移后核对第六条迁移已应用；检查 `ProgressBill.mainContractId` 与 `Change.mainContractId` 的历史回填；确认现有 `CostEntry` 金额、记录数未变化且旧成本 `downstreamContractId` 默认为空；对下合同表从空状态创建测试合同、补充协议、付款计划、付款及退款，并核对退款不能超过原付款。还需验证成本手动关联只改变关联关系，不改动成本金额。

## 6. 已知限制 / 下一迭代建议

- 本轮支持合同头信息、补充协议、付款计划与现金流；尚未实现完整合同清单、履约计量、供货验收、分包阶段结算、发票核销、预付款抵扣、质保金结转和应付账款模型。
- 下游合同与成本的关联目前基于项目校验；历史记录禁止推测自动匹配，需人工核实后补关联。
- 一个项目仍只允许一份业主主合同。如未来同一项目存在多份独立主合同，应把项目的收入侧业务设计成多主合同模型并迁移，而不是用编号字段绕过关系约束。
- 公司审批流程仍为固定状态流；审批配置、成本红字/冲销和专业 EAC 预测属于后续迭代。
- 当前候选 ZIP 不包含 `package-lock.json`，不具备可重现依赖安装的完整发布条件。

**结论：** 对下合同、现金流付款/退款、成本来源关联和业主主合同关联已完成源码级实现；33 项独立测试、45 个 TS/TSX 语法转译和 28 项静态检查通过。由于完整依赖构建、Prisma 验证及真实 PostgreSQL/Windows 集成尚未执行，本版本仍是 RC 候选，不可视为已通过生产发布验收。
