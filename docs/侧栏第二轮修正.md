## 一、我上一轮做错的三件事

### 错误一：漏了搜索框的分隔线

Hana 的搜索框上方有一条细线：

```css
._sessionSearchBox_afbfa::before {
  content: "";
  position: absolute;
  left: 50%;
  top: -10px;
  width: 72%;
  height: 1px;
  transform: translate(-50%);
  background: color-mix(in srgb, var(--text-muted) 18%, transparent);
}
```

**这条线才是「搜索区与上方内容」的视觉分界。** 我漏了它，只用了 `margin: 15px`，所以显得离上方太远。

### 错误二：漏了「排序与显示」组件

Hana 的分组标题是 `wC` 组件，接收 `actions`：

```jsx
function wC({ children, actions = null, className = '', pinBoundary = false }) {
  return (
    <div className={sessionSectionTitle}>
      <div className={sessionSectionTitleMain}>{children}</div>
      {actions && <div className={sectionTitleActions}>{actions}</div>}
    </div>
  );
}
```

实际调用（项目分组）：

```jsx
<h.jsx(wC, {
  pinBoundary: true,
  actions: <>
    <button className={sectionIconButton} aria-label="新建项目" onClick={onCreate}>＋</button>
    <button className={sectionIconButton} aria-label="排序" onClick={(e) => openSort(e.currentTarget)}>排序图标</button>
  </>,
  children: <span>项目</span>
})
```

**`sectionTitleActions` 默认 `opacity: 0`，悬停才显现。** 这就是你截图里红框的那两个图标。

排序菜单的选项（i18n key）：

```
sidebar.view.sorting  → time（时间）/ project（项目）/ agent（agent）
sidebar.view.display  → singleLine（单行）/ twoLine（双行）
```

### 错误三：拖拽做成了排序，而 Hana 是拖出成卡片

**这是最严重的一个。** 我明知 moheng 没有卡片系统，却擅自换成了排序，还当成交付。

Hana 的会话拖拽：

```js
const MIME = "application/x-hana-session-path";

// 拖动中判断是否进入 detach 区域
if (detachable && isInDetachZone(x, y, w, h)) {
  Oe.outcome = { kind: 'detach-window' };
  shellEl.setAttribute('data-detach-armed', 'true');
}

// 释放
if (r.kind === 'detach-window') {
  dispatchChalkboardLayoutCommand({ kind: 'detachCard', reason: 'detached-window', ... });
}
```

这依赖整套 chalkboard 卡片系统：`chalkboardLayoutDocument`、`detachCard`、独立窗口、卡片在容器间迁移。

**moheng 没有这些，所以做不到。** 已把排序代码全部删除。

### 2.4 贴纸行显隐

Hana 的实现：

```jsx
identity={showHeader && <PrimaryAgentRow />}
```

侧栏是 `flex-direction: column`：

```
profile（贴纸行）  flex-shrink: 0
scroll（导航区）   flex: 1      ← 吃掉剩余高度
footer（用户区）   flex-shrink: 0
```

moheng 照此实现：

```tsx
{showSidebarBrand && <div className="app-sidebar-profile">...</div>}
```

状态持久化：

```tsx
const [showSidebarBrand, setShowSidebarBrand] = useState<boolean>(() => {
  try { return localStorage.getItem('moheng.sidebarBrand') !== 'hidden'; } catch { return true; }
});
```

**注意**：目前只有状态和条件渲染，**还没有给用户提供切换入口**（设置页开关待加）。

## 四、一个看起来像 bug 但不是的地方

### 4.1 侧栏 titlebar 的 `padding-left: 50px`

```
padding: 8px 16px 8px 50px
```

CDP 查到的来源：

```css
.app-sidebar-titlebar {
  padding-left: calc(28px + var(--space-8) + var(--panel-edge-gap) + var(--space-8));
}
```

**这是为侧栏开关按钮让位**（按钮在 `trafficStrip` 里，x 范围 14-42px）。

Hana 有同样的机制：

```css
padding: calc(var(--card-top-inset) - var(--card-top-btn-pad))
         max(calc(...), var(--ttb-clearance-right, 0px))
         0
         max(calc(...), var(--ttb-clearance, 0px));
```

`--ttb-clearance` 就是「标题栏左侧让位量」。**设计正确，不是 bug。**

### 4.2 分组标题 38px vs 表面上的 28px

Hana 写的是 `min-height: 28px`，但实际高度是 38px：

```
按钮 26px + padding 8px + 4px = 38px
```

`min-height` 只是下限。**moheng 的 38px 是对的。**

### 4.3 搜索框看着像白色块

实测颜色：

```
搜索框: rgb(238, 235, 229) = #eeebe5
侧栏:   rgb(244, 240, 234) = #f4f0ea
差值: 6, 5, 5  → 只深 2.4%
```

**与 Hana 的计算值逐位一致。** 截图里看着白，是缩放和显示器对比度造成的错觉。
