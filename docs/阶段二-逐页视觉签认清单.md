# 阶段二：逐页视觉签认清单

这份清单给业务同事用，不替代门禁。门禁只能证明「结构一致、没有横向溢出、没有控制台报错」；**页面上的口径、列、措辞对不对，只有懂业务的人能判断**。逐页走一遍，在最后一节的表里写结论即可。

测量条件：`cb9d40b`、1500×1000 视口、`admin@local.test`、默认内容列宽（未开「铺满」）。数字都是实测，不是设计稿推算。

## 1. 通用口径

| 项 | 期望 | 说明 |
| --- | --- | --- |
| 结构 | 每个区块是 `.ldg-section`（标题 + 说明 + 操作）套一张 `.ldg-section-card` | 标题在卡外，卡体只放内容 |
| 卡头高度 | 42px（副标题折行时 60px） | 统一 14.4px/600 标题、右下角计数 |
| 卡片圆角 | 14.7272px | 由 `--radius-card` 推导；Windows 圆角适配开启时会更小 |
| 卡内左右内距 | 18px | 表格、块、说明都对齐这条线 |
| 区块间距 | 24px | 纵向 |
| 横向溢出 | 0 | 任何页面都不该出现整页横向滚动 |
| 控制台 | 0 条报错 | 数据为空、接口报错应以界面提示呈现 |

## 3. 看起来不一致但属于正常

签认时如果看到下面几种情况，不算缺陷：

1. **`/` 与 `/projects` 不是台账卡结构。** 经营总览用 v6 区块（50 个块、2 张表），项目档案是单表台账；这两页在阶段二就按各自形态定稿，不套三件套。
2. **`/reports/designer` 的 4 张卡没有卡头。** 那是工作区卡（配置区 / 属性栏 / 预览 / 编辑区），卡头由内部工具条承担。
3. **`/reports/preview` 直接访问会显示「缺少报表类型或模板编号」。** 这页需要从报表中心带参数进入，直连报错是预期的。
4. **同一页里卡头高度出现 42 / 60 / 0 三种值。** 60 是副标题折成两行（如 `/system/accounts` 的「系统账号列表」、`/system/operations` 的「数据库备份与恢复演练」）；0 是整段被权限或开关隐藏（实测 `/system/security` 的「安全事件」、`/system/policies` 的「变更签证内部审批流程」是 `hidden` 整段），不是卡头塌了。
5. **设置窗内的卡头是 20px。** 设置窗比业务页紧凑一档，`/settings/appearance` 与 `/account/security` 都按这档走。
6. **`/system/assistant` 在功能关闭时卡片宽度为 0。** 关闭状态下不渲染输入区，只保留说明。

## 5. 如何复测

```
# 结构与环境一致性（26 条路由，含两个 target）
npm run ui:parity
node scripts/gate-ui-parity.mjs

# 逐页清点（临时脚本，不提交）：统计 .ldg-section / .ldg-section-card / 卡宽 / 卡头高度 / 横向溢出
# 选择器就是上面这几个类名，直接在浏览器控制台跑也能得到同样口径
```

如果改了 UI 导致指标变化，要按 `docs/双target一致性检查.md` 重跑 `npm run ui:parity` 并提交新基线；基线里的 `legacy` 一侧必须是 Chromium <139（用 `LEGACY_CHROME_PATH` 指过去），否则退化分支会被跳过。
