# 指标区清单与判据

全站「标签 + 数值 + 说明」的摘要区统一由 `Metrics` 组件渲染，规格基准是经营总览的资金计划摘要（`/` 的「未来六个月现金缺口」）。这份清单记录每处指标区用的是哪种形态、为什么，避免新增页面时再各写一套。

## 一、规格

| 项 | 值 |
| --- | --- |
| 结构 | 三段式：标签 / 数值 / 说明；可选强调格 |
| 标签 | `--fs-hint`（11.52px），行高 1.55，`--text-muted` |
| 数值 | 19px / 600 / `tabular-nums` / 行高 1.55 / 墨色 `--text`，单行 + 省略号，`title` 兜底看全文 |
| 说明 | `--text-2xs`（11.52px），行高 1.5，`--text-muted` |
| 分隔 | 每格左侧 2px 竖线（含首格），`--line-2`；格间距 14px；无卡片底色、无圆角 |
| 强调 | 只把竖线换成 `color-mix(in srgb, var(--accent) 45%, transparent)`，不改数值颜色 |
| 列数 | 由 `data-cols` 声明；容器查询按实际容器宽度降列，不看视口 |

列数降级规则（`stat-metrics.css`，断点按「单格 ≥190px」倒算）：

- 6 列：容器 ≤1200 降 3 列，≤620 降 2 列
- 5 列：≤1000 降 3 列，≤700 降 2 列
- 4 列：≤640 降 2 列
- 3 列：≤520 降 2 列
- 任意列数：≤420 降 1 列

为什么用容器查询而不是媒体查询：正文列有 640 / 720 / 800 三档用户设置，视口 1600 时容器也可能只有 664px。按视口判断会在这种组合下把六格压到 99px/格，19px 的金额必被截断。竖线画在每格本体上，多行不会出现旧方案那种「第二行多根线 / 行首缺线」的错位，所以降列是安全的。

## 三、保留磁贴 / 卡片的（不转三段式）

| 区块 | 类名 | 为什么不转 |
| --- | --- | --- |
| 系统概览四入口 | `.system-overview-metrics` | 可点击磁贴，带图标与箭头，是导航入口而不是读数 |
| 设置窗安全项 | `.security-metrics` | 每格是独立卡片，窗内空间语言不同，且各有自己的次级操作 |
| 报表工作室入口 | `.report-studio-entry-grid` | 卡片列表，每张卡有标题、说明与动作 |
| 授权范围 | `.system-authorization-scope-grid` | 同上，卡片内含多行角色信息 |
| 助手检查项 | `.assistant-check-grid` | 卡片列表，带状态徽标与折叠内容 |

判据：**可点击 / 带图标与次级动作 / 自身承担卡片层级**，满足任一就不套三段式。这类区块即使不转，标签、数值、说明的字体层级仍应参照第一阶段规格（11.52 / 19-600 / 11.52），不要退回到 10px 标签 + 26px 数字。

## 四、新增指标区时的四条规则

1. 只有「标签 + 数值 + 说明」且不可点，一律用 `Metrics`，不要新写类名。
2. 一格里要放两个金额（如预付款 / 质保金），先考虑拆成两格；拆不开就显示合计值，把拆分放进说明行（「预付款 … · 质保金 …」），不要把两个金额挤在同一行里各压到 14px。
3. 强调只染竖线。需要标红的是数值本身（逾期、负净额）才用 `tone`，而且要有业务含义，不是装饰。
4. 指标区不再自建卡片壳。区块标题由外层 `Section` / `panel-heading` 承担，指标条直接落在纸面上。
