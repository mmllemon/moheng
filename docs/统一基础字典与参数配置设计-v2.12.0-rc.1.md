# 统一基础字典与参数配置设计（v2.12.0-rc.1）

## 1. 本轮目标与范围

本轮基于 `v2.11.0-rc.1` 增量建设，不重构成本工作台，不调整合同金额生效、变更签证内部审批/外部确认、业主结算应收、分供结算应付、付款退款核销或现有财务状态机。

正式新增两个系统管理能力：

- **统一基础字典**：集中管理稳定编码、显示名、用途说明、排序、启用状态；停用而非删除，保留历史引用的含义。
- **统一参数配置**：以版本记录保存参数值、类型、作用范围、变更说明、创建人和发布人；草稿不生效，显式发布后生效，回滚通过复制历史值创建新草稿。

同时增加面向已认证业务页面的只读配置 API，并把“实际成本录入”的计量单位字段接入 `MEASURE_UNIT` 字典提示（仍保留自由输入，兼容既有和项目专用单位）；本轮不将既有硬编码枚举和财务算法自动改造成动态配置。

## 2. 数据模型

### 2.1 基础字典

- `SystemDictionary`: 分类编码 `code` 全局唯一，保存名称、描述、系统内置标记、启用状态和时间戳。
- `SystemDictionaryItem`: 在分类内以 `(dictionaryId, code)` 唯一；保存显示名称、描述、排序、内置标记、启用状态和时间戳。
- 编码一经创建不能通过管理 API 修改；条目停用不会硬删除或改写合同、结算、付款等历史记录。
- 内置分类不能被停用；内置条目可软停用，以兼顾系统必需分类和实际选择项变更。

首批内置分类：`PAYMENT_METHOD`、`MEASURE_UNIT`、`DOCUMENT_CATEGORY`、`WARNING_LEVEL`。其中，实际成本录入的“计量单位”通过只读 API 获取 `MEASURE_UNIT` 提示选项，同时保留手动输入；其余字段仍需逐项评估后再接入，不自动覆盖财务核心状态和规则。

### 2.2 参数版本

- `SystemParameterRevision`: `key` + `scopeKey` + `version` 唯一；字段包括类型化 JSON 值、读取范围、作用域、项目关联、状态、变更说明、创建/发布时间及创建/发布操作者。
- 参数类型限定为 `STRING`、`NUMBER`、`BOOLEAN`、`JSON`；后端校验类型、长度、有限数、JSON 大小和键格式。同一参数键在所有版本和作用域内必须保持值类型与读取范围一致；如需不同类型或访问级别，使用新的参数键。
- 读取范围为 `ADMIN_ONLY` 或 `BUSINESS_READABLE`，默认 `ADMIN_ONLY`。只有显式设置为 `BUSINESS_READABLE` 并发布后，普通业务页面才可通过公共只读 API 获得该键；管理员管理页仍可查看所有已发布参数。
- 范围为全局 `GLOBAL` 或项目级 `PROJECT`。项目级 scopeKey 固定为 `PROJECT:<projectId>`；数据库 CHECK 约束保证 `scope`、`scopeKey`、`projectId` 一致。
- 每个参数键/范围最多一个 `PUBLISHED` 版本，数据库部分唯一索引提供最后一道并发保护。
- 发布会把同键同范围的上一发布版置为 `RETIRED`，再发布草稿。版本通过可串行化事务递增；冲突返回 409，要求刷新重试。
- 回滚不重写旧值的状态或历史，而是复制所选历史值，创建版本号更高的新草稿，再由管理员审核并发布。

### 2.3 生效优先级

请求带 `projectId` 时，先读取已发布全局参数，再由同键已发布项目参数覆盖；没有项目覆盖时回退到全局值。请求不带 `projectId` 时只返回全局参数。草稿与归档版本不参与计算。

## 3. 权限与安全

- 字典/参数管理页面和写 API 仅系统管理员可以访问；管理 API 继承系统管理父路由的 session + ADMIN 前置校验。
- 只读 API 要求有效登录会话。字典只返回启用分类和启用条目；参数只返回已发布配置。
- 读取项目参数时，系统管理员可查看任意未归档项目；普通账号必须是该项目成员，否则返回 404，避免暴露项目是否存在。公共只读 API 仅返回 `BUSINESS_READABLE` 参数；管理员配置管理 API 才可查看 `ADMIN_ONLY` 值。
- 参数键包含密码、密钥、Token、私钥、API key 或凭据等敏感特征时拒绝保存；只读接口也会过滤此类键。敏感凭据继续使用环境变量或独立集成凭据保险库。
- 参数值不会写入参数草稿/发布的审计变更详情；审计只记录键、范围、版本、类型、状态与变更说明，避免在审计日志中复制可能敏感的业务值。
- 字典分类/字典项增改、参数草稿、发布和回滚草稿均写入 `AuditLog`。没有提供硬删除接口。

## 4. API 路由

### 管理员写/管理接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/system-management/dictionaries` | 查询分类及条目（包含停用项以便维护） |
| POST | `/api/system-management/dictionaries` | 新增自定义分类 |
| PATCH | `/api/system-management/dictionaries/:id` | 修改分类名称、说明或启停 |
| POST | `/api/system-management/dictionaries/:id/items` | 新增条目 |
| PATCH | `/api/system-management/dictionary-items/:id` | 修改条目名称、说明、排序或启停 |
| GET | `/api/system-management/parameters/revisions` | 查参数版本历史，最多返回 250 条并标记截断 |
| GET | `/api/system-management/parameters/effective?projectId=...` | 管理页查看最终生效值及来源 |
| POST | `/api/system-management/parameters/drafts` | 创建新草稿版本 |
| POST | `/api/system-management/parameters/:id/publish` | 显式发布草稿 |
| POST | `/api/system-management/parameters/:id/rollback` | 从历史版创建回滚草稿 |

### 已认证业务页面的只读接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/config/dictionaries/:code/items` | 返回启用分类的启用条目，按排序/编码排列 |
| GET | `/api/config/parameters/effective?projectId=...` | 返回授权范围内被标记为 `BUSINESS_READABLE` 的最终有效参数，不返回草稿和敏感键 |

## 5. UI 与导航

系统管理分组新增“统一基础字典”和“统一参数配置”，均需管理员权限。字典页支持分类/条目创建、说明编辑、排序和启停；参数页支持值类型、全局/项目范围、创建草稿、发布、历史浏览和生成回滚草稿。实际成本录入页的计量单位字段已消费 `MEASURE_UNIT` 字典，并在读取失败时保留自由输入。系统管理概览提供入口与简要职责说明。

## 6. 接入规则与明确不做的事

1. 现有的 `Project.status`、合同/结算/付款/审批等 Prisma enum、状态机及金额生效规则仍由强类型模型/专用业务服务控制。
2. 不允许通过动态字典或普通参数配置把核心财务状态变成任意字符串，也不允许参数页面直接修改历史财务数据。
3. 后续若要将某个预警阈值或非核心表单选项切换为参数/字典驱动，必须为具体消费方增加读取、默认值、类型校验、项目授权测试、历史兼容策略和独立验收；不能仅因管理 UI 已存在，就宣称该业务已配置化。
4. 配置读取采用同步数据库查询；本轮不加入 Redis、分布式缓存、微服务或配置推送基础设施。

## 7. 迁移与恢复

新增 Prisma migration：`20261016020000_system_dictionaries_parameters`，新增三种参数枚举、三个数据模型、索引、外键、scope 一致性约束、单范围单发布版唯一索引和初始字典种子。部署时必须先备份 PostgreSQL；在测试库运行迁移并生成 Prisma Client 后，才能部署依赖新模型的 API。
