# 系统管理工作台完善与导航方案 v2.13.0-rc.1

- 产品：墨衡｜施工单位成本管理系统
- 基线：v2.12.1-rc.1
- 候选版本：v2.13.0-rc.1
- 状态：源码已增量实现；完整构建、迁移和端到端验收待目标环境执行

## 1. 本轮目标

1. 补齐系统管理关键治理入口：现行权限基线、跨项目数据范围说明、持久化授权快照与复核记录。
2. 主侧栏只保留“系统管理”单一入口，详细管理页面放入系统管理工作区二级导航；侧栏导航区独立滚动，避免长菜单挤出视口。
3. 在统一基础字典分类、字典项和参数键创建表单中，根据显示名称自动生成编码建议；编码仍可编辑，服务端格式、敏感键及唯一性校验仍为最终依据。
4. 将数据质量巡检主操作改为低强调的中性色按钮，避免与卡片标题及风险指标争抢视觉权重。

## 2. 导航评估与决策

### 2.1 推荐方案

采用“全局一级侧栏 + 工作区内二级导航”：全局一级侧栏负责经营中心、成本工作台、项目管理和系统管理等不同工作空间；进入系统管理后，在页面内容上沿显示概览、账号管理、登录安全、权限治理、组织规则、基础字典、参数配置、运维备份和操作追溯等横向二级导航。

### 2.2 为什么不把所有管理项继续放在侧栏

- 系统管理页面持续增加后，九个详细入口会与经营、项目、工作台入口争抢纵向空间；把它们都留在主侧栏会形成过长菜单。
- 系统管理是一个有共同上下文的管理工作区，二级导航可以让页面内切换更近，同时保留“系统管理概览”作为入口。
- 成本工作台已有页面内导航范式，复用同一信息架构比再引入第三套导航模式更一致。
- 二级导航容器具有横向滚动、键盘焦点样式和较窄屏幕适配；主侧栏自身的菜单滚动区与底部账号/收起控件分离。

### 2.3 有意保留的边界

- 主侧栏仍保留系统管理入口，方便跨工作区定位。
- 二级导航不是权限边界。页面路由与 API 仍需执行服务端管理员校验。
- `/audit-logs` 在管理员系统管理二级导航内呈现；其 API 对普通用户的项目范围约束不因导航改变。
- 不新增可随意配置导航权限的通用菜单引擎，以免出现 UI 声明与后端授权不同步。

## 3. 权限矩阵与授权复核

新增管理员专用 API：

- `GET /api/system-management/authorization/matrix`：返回公司角色、项目角色、主要模块权限边界与数据范围规则。
- `GET /api/system-management/authorization-reviews`：返回最近授权复核摘要。
- `GET /api/system-management/authorization-reviews/:id`：读取指定快照和复核状态。
- `POST /api/system-management/authorization-reviews`：生成带时间点的账号、项目成员、项目负责人和相关安全状态快照。
- `PATCH /api/system-management/authorization-reviews/:id/complete`：写入管理员复核说明，以条件更新保证同一待复核记录只能成功完成一次。

### 3.1 权限矩阵的准确含义

矩阵是基于现有后端守卫和成员角色约束的只读说明，不是动态角色配置引擎。它用于让管理员看清目前公司级角色与项目级角色的区别，以及主要模块的授权边界。具体 API 每次请求仍执行自身服务端授权；修改此矩阵展示结果不会改变实际访问控制。

跨项目范围：公司级 `ADMIN` 依现有服务端规则可访问公司范围业务数据，但仍受业务状态机、自审批防护、外部确认及财务过账约束；普通 `USER` 只能根据 `ProjectMember` 关系访问项目数据。部门/岗位只是组织属性，不自动授予项目权限。

### 3.2 快照的范围与限制

快照为生成时的记录，不随之后的用户/成员变更自动改写。当前每次最多取 2000 个账号、5000 条成员授权和 2000 个未归档项目；超过上限会标注截断，并添加提示。成员清单被截断时，不根据不完整列表推断项目缺少负责人或普通账号未获授权。页面最多展示 1000 条成员明细，原始快照保留更完整的受限记录。

生成与完成复核均写入 `AuditLog`。复核只记录人工检查结果，不自动撤销授权或改动项目成员；需要更改成员角色时仍经现有项目管理 API 处理。

## 4. 编码自动推荐规则

基础字典分类编码、字典项编码和参数键均按显示名称产生建议：

- 常见施工成本与管理中文字符采用内置首字母映射；连续英文/数字保留并转为大写；未知汉字用显式 Unicode 标记表示，不静默猜测读音。
- 对于同一显示名称建议结果可能重复的情形，不自动改写成未确认的唯一值；由用户确认或编辑，并由后端唯一约束/冲突响应处理。
- 用户一旦手动编辑编码字段，继续输入显示名称时不覆盖用户编辑结果。
- 只在前端提供建议，不绕过后端编码格式、唯一性、作用域或敏感参数键的验证。

此功能的目标是减少编码录入成本，不保证完整汉语拼音转换。用户可以手动改成公司约定的标准编码。

## 5. 数据质量巡检按钮样式

巡检是只读检查操作，不应在视觉上高于卡片中的关键风险指标。按钮采用透明/中性色背景、细边框和较低字重；悬停时再提高对比度；执行中保持禁用并显示旋转图标，焦点仍有可辨认的轮廓。巡检行为、错误/警告计算及审计不因样式调整而改变。

## 6. 数据库迁移与验证

新增追加式 Prisma migration：`20261016030000_system_authorization_reviews`。新增 `SystemAuthorizationReview` 表，用 JSON 快照与摘要保留生成时状态，使用状态一致性 CHECK、创建者/复核者外键及索引；没有修改历史 migration。

源码静态验证应覆盖：

- 管理 API 的 session + `ADMIN` 前置授权；
- 角色矩阵、范围说明及授权复核 API/页面路由；
- 被截断的成员快照不会造成“未获授权/无负责人”的错误推断；
- 快照生成/完成复核审计和并发状态条件；
- 侧栏只保留系统管理入口，二级导航包含各子工作台且独立可滚动；
- 编码建议在三个录入位置启用，手动编辑可保留；
- 数据质量按钮不再使用高强调主按钮样式。

## 7. 尚未实现或尚未验证的边界

本版本尚不支持在 UI 上任意增删运行时 RBAC 权限；现行矩阵为只读基线。部门级行权限、授权自动撤销策略、完整授权审批工作流需要单独设计，不应仅以本轮页面宣称已实现。完整严格 TypeScript 检查、前后端生产构建、Prisma Client 生成、PostgreSQL 迁移与并发测试、浏览器 E2E 和 Windows 目标环境部署验收均需在 Node.js 24+ 完整依赖环境执行。本版本仍为 RC。
