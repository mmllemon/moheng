# 墨衡报表中心与报表工作室设计方案 v2.4.0-rc.1

- 基线：`v2.3.0-rc.1`
- 候选版本：`v2.4.0-rc.1`
- 定位：报表工作室与预览流增量开发；不是生产验收签字
- 目标：项目级与公司级综合报表、单元格绑定、集合自动延伸、统一样式编辑体验、正式导出前预览，并维持低运维部署

## 1. 技术选型结论

### 1.1 采用 Univer 作为前端单元格编辑器

本候选固定使用以下 npm 直接依赖版本：

- `@univerjs/presets@1.0.4`
- `@univerjs/preset-sheets-core@1.0.4`

依据：

- Univer 是面向电子表格、文档与演示的可嵌入 SDK；其仓库 README 标注 Apache-2.0，并说明开源包可独立使用，Pro 为可选能力。
- 1.0.4 release 包含工作表单元格编辑、键盘导航、合并区域、边框与粘贴相关修复。
- 本项目仅用其浏览器 Sheets Core 作为模板编辑界面；不导入任何 `@univerjs-pro/*` 包，也不依赖 Pro XLSX 转换服务。
- 工作簿的业务绑定、动态区域扩展和最终财务数据仍由墨衡服务端控制；XLSX 生成使用现有 ExcelJS 4.4.0 和 PostgreSQL 后台任务，不由浏览器编辑器导出业务权威文件。

参考：

- Univer 1.0.4 发布说明：https://github.com/dream-num/univer/releases/tag/v1.0.4
- Univer 官方仓库与开源许可证：https://github.com/dream-num/univer
- Univer Sheets Starter Kit：https://github.com/dream-num/univer-sheet-start-kit
- Univer Presets 仓库：https://github.com/dream-num/univer-presets

选型风险：当前执行环境无法从 npm registry 拉取依赖，因此本候选完成了依赖版本固定、源码接线和静态校验，但没有声称已经完成 Univer 浏览器运行、生产 bundle 体积、键盘/复制粘贴或真实 XLSX/WPS 端到端验证。许可证说明不替代发布时对实际安装的所有 transitive dependency 与商业分发条款的法务核对。

### 1.2 保留现有后端和部署形态

- React + TypeScript + Vite。
- Fastify + Prisma + PostgreSQL。
- ExcelJS 是最终 XLSX 生成器。
- 当前 PostgreSQL `BackgroundJob` 是异步任务队列；Worker 默认随 API 运行，可按需要独立启动。
- 不增加 Redis、RabbitMQ、Kafka、对象存储、外部转换服务器或 Kubernetes 强制依赖。

## 2. 信息架构

### 项目级报表

围绕一个经授权的项目输出单份综合工作簿。可组合：项目档案、业主主合同、经营指标、分供合同、业主应收、收退款流水、实际成本、变更签证、进度款和分供应付。

### 公司级报表

汇总当前登录用户有权访问的项目，支持公司指标和项目横向对比，并可以选择跨项目分供合同、应收、收退款、实际成本、变更、进度款和应付明细数据源。公司级范围不等于无条件全公司访问；后端仍根据用户角色及 `ProjectMember` 约束项目集合。

### 公共入口

保留标准台账目录、模板设计、报表工作室、正式预览、后台任务状态与下载。项目/公司范围是数据权限和查询范围；个人/项目共享/系统模板是模板可见性，两者不得混为一谈。

## 3. 数据源注册表和稳定字段契约

`apps/api/src/lib/report-studio-data.ts` 定义可选数据源、字段 ID、类型、业务含义与基数：

- `ONE`：单个值对象，允许绑定到任意指定单元格。
- `MANY`：一组明细对象，必须绑定到显式重复区域。
- 字段 ID 为稳定契约，中文标签可调整；变更字段语义时须版本迁移，不得重用 ID 表示其他含义。
- 模板不提供任意 SQL、JS 或任意数据库字段访问能力。

### 主要项目级来源

`project`、`mainContract`、`financialSummary`、`downstreamContracts`、`ownerReceivables`、`ownerReceipts`、`actualCosts`、`changes`、`progressBills`、`downstreamPayables`。

### 主要公司级来源

`companySummary`、`companyProjects`、`companyDownstreamContracts`、`companyOwnerReceivables`、`companyOwnerReceipts`、`companyActualCosts`、`companyChanges`、`companyProgressBills`、`companyDownstreamPayables`。

当前指标口径中特别区分：

- 当前有效合同额：按已生效外部确认变更和增减方向计算；不采用送审金额或内部审批中的变更。
- 累计登记净收款：明确排除预付款相关流水，不等于总现金流入。
- 登记净应收合计：未作废应收单净额之和，不等于实际未收余额。
- 已登记净应付：应付台账净额，不等同于现金已付款。
- 已录入实际成本：仅为已经录入的实际成本，不代表预计完工成本或未开票应计成本。
- 分供合同当前金额、分供应付和实际支付分开输出，避免混用。

### 行数上限和财务完整性

- 金额字段和所有汇总使用整数“分”进行精确加减，不先将 PostgreSQL Decimal 转成 JavaScript 浮点数。屏幕预览显示精确的十进制字符串；若单个金额的“分”整数超过 Excel 约 15 位有效数字可可靠保留的界限，XLSX 将其输出为文本，避免悄悄舍入，并保留完整金额字符。
- 每类明细数据源当前查询上限为 10,000 条；目标成本树数据源上限为 100,000 条。
- 若相关数据源超过上限，明细可能截断，且依赖该来源的汇总指标显示为空，并给出可见警告；不可将部分数据静默显示为精确财务总额。
- 公司级大规模精确聚合、按数据库端聚合并分页输出，是后续扩展点。提高限制前必须完成性能和数值完整性测试。

## 4. 模板 schema v2

使用现有 `ReportTemplate` 与 `ReportTemplateRevision` 数据库模型保存 schemaVersion 2 的 JSON，不新增业务表、不修改财务表和既有迁移。

模板定义包含：

- `domain`：`PROJECT` 或 `COMPANY`。
- `workbook`：Univer 的工作簿数据模型，含工作表目录、单元格值/样式、合并、行高、列宽、冻结设置。
- `bindings`：工作表 ID、A1 单元格地址、数据源 ID、稳定字段 ID 与受控格式。
- `regions`：集合来源、样板行、起止列、最大扩展行数。
- `page`：纸张、方向、宽度适配、说明页和页脚配置。

### 单元格绑定

一个字段绑定到任意确定单元格，例如 `B3 -> project.name` 或 `F6 -> financialSummary.netReceipts`。模板只保存不可执行的占位文本与绑定契约；输出渲染器用经授权的数据值替换占位内容。

### 自动延伸区域

每个集合来源绑定到一行样板区域，例如 `A10:F10 -> downstreamContracts`。区域内的每个单元格可分别绑定字段；一个工作表可以有多个不同来源的区域。导出时按每个来源的记录数复制样板行，后续版式行与合并区域按扩展行数下移。当前第一阶段每个重复区域必须是单行样板，同一工作表同一行不能定义多个区域，且区域不能与跨行合并单元格相交。

### 安全与边界

- 第一阶段拒绝任意公式，使用服务端定义的财务指标和绑定字段。
- 工作簿最多 8 张工作表、每张 400 行/40 列，整体最多 8,000 个非空格、500 个绑定、30 个重复区域、600 个样式目录条目，模板 JSON 最高 1.5 MB。
- 模板不能修改业务台账，导出工作簿为只读快照。
- 项目模板锁定归属项目；导出和预览都重新检查项目访问权。个人模板的项目归属不能被绕过，系统模板的发布/修改需要管理员策略。
- 不支持公式计算引擎、宏、脚本、外部连接、透视表、协作编辑或像素级 Excel/PDF 同构。

## 5. 编辑体验

工作簿交互由 Univer Sheets Core 提供；墨衡侧栏提供数据源、字段绑定与重复区域管理。工具栏的常见编辑能力包括字体/字号、粗斜体、颜色、填充、边框、水平/垂直对齐、文本换行/截断、数值格式、合并、行高/列宽与多工作表。绑定写入不可执行占位文本，例如 `{{project.name}}`，便于编辑时识别；预览及导出渲染为实际值。

用户可以先选中实际单元格，再将白名单字段绑定至该地址。明细绑定必须先创建匹配的集合区域。将来如需条件格式、专用图表、公式、跨工作表引用或数据透视，须单独进行范围和安全性评估。

## 6. 预览与导出流程

1. 用户选择标准台账或已保存的项目/公司综合模板。
2. 系统显示正式预览页：数据范围、模板版本、生成时间、每张工作表、样式、合并、截断状态及数据源警告。
3. 用户可以打印/另存为 PDF，或确认生成 XLSX。
4. XLSX 通过 PostgreSQL 后台任务队列创建；完成后按现有安全下载端点取得文件。
5. 标准台账和综合报表 XLSX 都先经过正式预览入口。旧设计器的“预览并导出 XLSX”也导航至正式预览页。

当前预览时间与后台 XLSX 生成时间可能不同：导出 Worker 会在执行时重新查询授权数据，因此如业务数据在预览后被修改，最终 XLSX 的数值可能与屏幕预览存在时间差。预览和导出使用相同模板版本/绑定定义与业务数据源口径，但本版本尚不冻结完整的数据快照。需要法律/审计意义的可复现报表时，应在后续工作包引入 `ReportRun` 快照/数据集摘要和可追溯文件哈希，不应把当前即时预览当成不可变审计快照。

## 7. 全仓统一控件

页面日期选择和普通下拉统一复用 `apps/web/src/components/DatePicker.tsx` 与 `SelectField.tsx`。这两个组件内部保留原生输入代理以兼容表单注册；业务页面不得自行重新造下拉样式或普通日期弹窗。日期时间混合输入不属于纯日期选择器，后续需要统一时另做 DateTimePicker。

## 8. API 边界

- 综合报表接口通过模块注册表独立挂载于 `/api/reports/studio/*`。
- `/catalog` 返回当前 domain 的数据源和稳定字段契约。
- `/templates` 负责模板列表、创建、读取、版本检查、发布和历史。
- `/preview` 只接受保存后的 `templateId`，服务端再次检查模板可见性、发布版定义和项目归属后，使用同一数据源注册表与服务端渲染器生成屏幕预览；不信任客户端提交的任意工作簿定义，也不允许将项目模板跨项目预览。
- `/templates/:id/xlsx/jobs` 创建版本化后台导出任务。
- 输出 XLSX 由 `report-studio-render.ts` 的纯渲染结果再送入 ExcelJS；不让浏览器工作簿定义直接指定 SQL 或下载任意文件。

## 9. 发布 Gate

发布前必须完成：

1. 在 Node.js 24+ 干净环境锁定依赖并执行完整 `npm ci`；审查并提交 `package-lock.json`。
2. `tsc`、Vite production build、lint、全量 API 测试、Prisma validate/generate 成功。
3. 测试数据库运行既有迁移状态核查；本候选没有新增数据库迁移，但综合报表 API 需要真实数据库 schema 与数据验证。
4. 浏览器测试 Univer 初始化、保存、加载、选区绑定、复制粘贴、撤销重做、合并、边框/填充/字号/对齐、多工作表、重复区域自动下移。
5. 财务精度回归：多笔收款和合同变更以整数分汇总；边界金额超过安全数值范围时，预览与 XLSX 文本均保留完整小数，不得发生浮点舍入。
6. 真实 Excel 与 WPS 打开项目级和公司级综合报表，检查数值/日期、边框、填充、合并、分页、页脚和公式安全。
7. 对项目越权、个人/共享模板权限、超过行数上限、缺失绑定、无数据区域、任务重试和文件过期做 E2E。
8. 验证所有业务普通下拉/纯日期选择器复用统一控件，并在主题/窄屏/键盘操作回归。

## 10. 当前明确未完成项

- 当前 npm registry 无法访问，未生成并审查根 `package-lock.json`；Univer 依赖已固定为精确直接版本，但 transitive dependency 尚未由 lockfile 固定。
- 未实际运行 Univer 浏览器编辑器，未执行 `npm run build`、全量 `tsc`、真实 PostgreSQL 数据联测、浏览器 E2E 或 Excel/WPS 打开测试。
- 当前只是明确、开放的 schema v2 设计器第一阶段，不是完整 Excel：暂不支持公式、透视表、跨工作簿引用、协同编辑、复杂条件格式与图表。
- 公司级财务汇总在源明细达到限制时会标记相关汇总不可用，而不是自动做数据库端完整聚合；如公司级规模超过阈值，需要下一阶段实现独立 aggregate queries 和分页/分组策略。
