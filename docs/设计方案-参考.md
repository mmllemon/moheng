# 施工单位成本管理系统 完整设计方案

> 版本：v1.0 · 2026-10-12

---

## 一、岗位职责与系统边界

造价人员在施工单位的核心工作分三个侧面：

**收入侧** — 向业主申请付款、处理变更增减、追踪签证审批、推进竣工结算

**支出侧** — 拆分目标成本、跟踪劳务/材料/机械/分包的实际发生、与分包商结算

**分析侧** — 三算对比（合同价 vs 目标成本 vs 实际成本）、利润预测、超支预警

### 业务能力与系统模块映射

| 业务能力 | 系统模块 |
|---------|---------|
| 合同计量、变更估价 | 进度款申报、变更签证 |
| 目标成本分解 | 预算管理 |
| 五算（量、价、费率） | 成本录入 + 材料台账 |
| 分包合同管理与结算 | 分包管理 |
| 资金流动预判 | 收支计划 + 仪表盘 |
| 三算对比分析 | 成本分析模块 |

系统边界设定为**施工阶段**（中标后到竣工结算完成），不含设计阶段或招投标，可后期扩展。

## 二、技术栈与架构

### 前端

```
框架:       React 18 + TypeScript
路由:       React Router v6
状态管理:   Zustand（客户端全局状态）+ TanStack Query v5（服务端状态/缓存）
表单:       React Hook Form + Zod（验证）
样式:       Tailwind CSS v4（utility）+ CSS custom properties（token系统）
组件基础:   Radix UI Primitives（无障碍行为）+ 自建业务组件
图表:       ECharts（丰富的工程图表类型，国内支持好）
表格:       TanStack Table v8（高性能、可排序/筛选/分组）
日期:       date-fns
构建:       Vite
```

### 后端

```
运行时:     Node.js 20
框架:       Fastify（性能好，TypeScript原生）
数据库:     PostgreSQL 16
ORM:       Prisma（类型安全，迁移管理）
缓存:       Redis（session、热数据、请求去重）
文件存储:   MinIO（私有化部署）/ 阿里云OSS（云上）
认证:       JWT（access token 15min）+ RefreshToken（7天，存Redis）
任务队列:   BullMQ（报表生成、数据导出等异步任务）
搜索:       PostgreSQL全文检索（规模不大时足够）
API规范:    RESTful，资源命名清晰，统一响应结构
文档:       OpenAPI 3.0 + Scalar UI
```

### 部署架构

```
Client (React SPA)
    ↓ HTTPS
Nginx（静态资源 + 反代）
    ↓
Fastify API Server（横向扩展）
    ↓
PostgreSQL（主从）  Redis  MinIO
```

多项目单实例，通过 `project_id` 做数据隔离，不走多租户数据库分片（施工单位项目数量在百量级，不需要）。

## 三、设计语言

### 色彩系统（OKLCH）

```css
/* 中性色 ramp */
--color-neutral-50:  oklch(97% 0.003 250);   /* 页面背景 */

/* 主强调色：靛蓝（专业感，不刺眼） */
--color-accent-50:   oklch(96% 0.018 250);
--color-accent-500:  oklch(52% 0.19  250);   /* 主操作按钮 */
--color-accent-600:  oklch(45% 0.19  250);   /* hover */

/* 语义色 */

--color-warning: oklch(72% 0.17 65);    /* 临界/待确认 */

```

暗色模式：另一组 token，lightness 整体上移 15-20%，chroma 略降（5-10%）。

### 间距与尺寸

- 基准单位：4px
- 常用间距：4 / 8 / 12 / 16 / 24 / 32 / 48px
- 圆角：卡片 `8px`，按钮 `6px`，标签 `4px`，弹窗 `12px`，内层元素永远 ≤ 外层
- 阴影：`0 1px 3px rgba(0,0,0,0.06), 0 1px 2px rgba(0,0,0,0.04)`（卡片），浮层再加一层

### 字体

```css
font-family: "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;

/* type scale */
--text-xs:   12px / 1.5;
--text-sm:   13px / 1.5;
--text-base: 14px / 1.6;    /* 正文 */
--text-lg:   16px / 1.5;
--text-xl:   20px / 1.4;
--text-2xl:  24px / 1.3;
--text-3xl:  30px / 1.2;
```

数字（金额、面积、工程量）使用 `font-variant-numeric: tabular-nums`，保证列对齐。

### 交互规则

- 过渡时长：120ms（micro），200ms（panel），300ms（弹窗）
- 所有过渡只动 `transform` / `opacity`，不动 layout 属性
- 空状态：骨架屏匹配最终布局；错误态说明原因 + 操作入口
- 表单验证：`onBlur` 后触发，不在每次 keystroke 干扰用户

## 五、各页面详细设计

### 5.1 仪表盘 Dashboard

让造价人员一眼看到所有项目的整体健康状态，以及当前项目的关键指标。布局分三区。

**上区 — 全局项目概览卡片组（横向滚动列表）**

每张卡片（280px宽）显示一个项目：
- 项目名称 + 项目编号
- 状态 Badge：施工中 / 待结算 / 已结算
- 合同金额（万元，大字）
- 本月收款进度（小进度条）
- 利润率当前值（颜色编码：绿/黄/红）
- 点击跳转项目详情

**中区 — 当前项目关键指标（4格 stat cards）**

| 指标 | 数值 | 趋势 |
|------|------|------|
| 合同总额 | ¥X,XXX万 | |
| 已收款 | ¥X,XXX万 | 较上月+X万 |
| 实际成本（已发生） | ¥X,XXX万 | |
| 预计利润 | X.X% | ↑ / ↓ |

点击任意指标卡可钻取详细报表。

**下区 — 两列布局**

左列（60%宽）：三算对比折线图
- X轴：时间（按月）
- 三条线：合同价累计 / 目标成本累计 / 实际成本累计
- 鼠标 hover 显示该月三个值和偏差率

右列（40%宽）：
- 上半：待处理事项列表（待审批变更、即将到期合同、本月应申报进度款倒计时、分包结算待确认，每条可点击跳转）
- 下半：最近操作记录（时间轴样式，5条）

无项目时显示空态引导卡"创建你的第一个项目"。


**5.5.2 新建进度款申报页（全页表单）**

**收款登记**：审批通过后「登记到账」按钮，填写实际到账日期和金额，支持部分到账（多次登记）。

### 5.10 成本分析

展示型模块，数据来源于前面所有录入。

#### 5.10.1 三算对比总览

## 八、关键设计决策

### 1. Excel 是无法绕过的

工程行业深度依赖Excel，系统在每个关键表格都需要提供"导入/导出Excel"。导入时必须有预览+映射+错误行高亮，不能直接报错让用户去猜。

### 2. 离线场景

现场网络可能不稳定，成本录入应支持离线缓存（PWA + IndexedDB），网络恢复后自动同步，冲突时提示用户解决。

### 3. 权限粒度

不同项目同一用户可能有不同权限（A项目只读、B项目编辑），权限模型需设计在 `ProjectMember` 层而非全局角色层。

### 4. 审计日志

金额相关的任何修改都需要记录「谁在什么时候改了什么」，不能物理删除，只能软删除。所有金额表加 `deletedAt`，核心表加 `audit_logs`。

### 5. 实际成本的滞后性

需要明确区分"已发生并录入"的成本和"已签约但未录入"的分包成本，在三算对比中分别呈现，避免假性乐观。
