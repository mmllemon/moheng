# 阶段验收记录：v1.2.2-rc.4（Windows 启停安全加固）

## 1. 本轮范围

沿用 v1.2.2-rc.3 的合同金额与凭证业务规则，本轮继续处理 Windows 原生部署前的进程管理风险，并在当前环境重新执行可做的单元测试和发布候选检查。未修改既有数据库迁移 SQL。

## 2. 本轮修改

1. `start-windows.ps1` 现在以绝对 `apps/api/dist/src/server.js` 路径启动 Node.js，并通过 `Win32_Process` 核验 PID 文件中已有进程的命令行。PID 对应其他或身份无法验证的进程时直接报错，不会终止该进程。
2. `stop-windows.ps1` 在停止前要求 PID 对应进程名为 `node.exe`，且命令行含有本项目绝对入口路径；随后核对 CIM 进程创建时间与已打开进程句柄的启动时间，并通过该进程句柄结束进程。身份不匹配时不终止进程、不清除 PID 文件。
3. 启动后对 `http://127.0.0.1:<PORT>/health` 最多轮询 20 秒，必须同时确认 `success=true`、`data.status=ok` 和 `data.database=ok` 才报告成功。超时会停止本次启动的确切进程并清除本次 PID 文件。
4. 发布候选静态检查加入 Windows 进程识别、健康检查及版本一致性检查。候选版本更新为 `1.2.2-rc.4`。

## 4. 在 Windows 测试机必须验证

在隔离测试机上安装 Node.js 24 LTS 和 PostgreSQL 16，备份测试数据库后，执行：

```powershell
node --version
npm install
npm run validate:release-candidate
npm run db:generate
npm run lint
npm run build
npm test
npm run db:deploy
npm run db:seed
.\scripts\windows\start-windows.ps1
Invoke-RestMethod http://localhost:3001/health
.\scripts\windows\stop-windows.ps1
```

另外必须测试以下 Windows 进程情形：PID 文件过期、PID 被无关进程复用、旧版以相对路径启动的实例、错误数据库密码、数据库未启动、API 端口被占用、启动成功后停止本应用。对非本系统进程，停止脚本必须拒绝调用任何终止操作。

## 5. 合同数据迁移与业务验收仍然有效

迁移前先备份测试数据库。迁移后核对 `ContractBaselineMigrationReconciliation`；若迁移因有效合同额为负数或超过 `DECIMAL(18,2)` 上限而失败，停止升级并先核实主合同台账与已生效外部确认记录。A/B/C 凭证生效、C 类非提交人核验、原始合同金额锁定、外部/内部金额差异快照与不改变有效合同额的复核规则沿用上一候选版本。

本轮确认源码包结构、已实跑的 18 项独立测试、41 个文件的语法转译及 16 项静态候选检查。尚未完成 Node.js 24+ 正式构建、依赖锁文件生成、Prisma/PostgreSQL 迁移和 Windows PowerShell 实机验收，版本仍属于 RC 候选，不可据此认定已经具备生产发布资格。
