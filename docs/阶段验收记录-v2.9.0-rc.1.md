# 墨衡 v2.9.0-rc.1 阶段验收记录

日期：2026-10-15  
范围：系统管理工作台增强、账号生命周期管理、管理员 MFA、会话管理和公网直接登录部署基础。

## 一、交付内容

- 系统管理工作台新增“登录安全中心”，集中查看最近登录安全事件与会话，并可撤销其他会话。
- 系统账号页面支持账号创建、启用/停用、管理员重置密码和重置他人 MFA；创建账号和重置密码后要求修改密码。
- 管理员首次在公网模式登录时必须启用 TOTP MFA；一次性恢复码仅在生成时返回，数据库保存 HMAC 哈希，TOTP 种子以 AES-256-GCM 加密。
- 增加 `AuthSession`、`SecurityEvent`、`LoginAttemptBucket`、`MfaRecoveryCode` 与 `User.authVersion` 等结构，使用新增的 `20261015040000_public_access_security` 迁移；没有修改历史迁移。
- 公网模式要求生产环境、正式 HTTPS `PUBLIC_BASE_URL`、API 只绑定回环接口、明确代理白名单、Secure Cookie、独立 MFA 加密密钥；禁用公网 API 文档，启用 HSTS/CSP，并对 cookie 端点执行同源 Origin 校验。
- 加入 Caddy HTTPS 反向代理示例与公网部署手册；PostgreSQL 不应暴露到公网。

## 四、上线前硬性 Gate

1. 先备份 PostgreSQL 数据库和秘密配置；独立备份 `JWT_SECRET` 与 `MFA_ENCRYPTION_KEY`，绝不能提交到 Git。
2. 在 Node.js 24+ 环境安装依赖、生成 Prisma Client、运行 `prisma validate`、构建、测试并先在数据库副本上应用迁移。
3. 使用正式域名部署 Caddy，验证证书、HTTPS 跳转和响应安全头；确认公网只能访问 80/443，端口 3001 和 PostgreSQL 5432 不可从公网访问。
4. 首位管理员完成强制改密、启用 TOTP、保存恢复码，并实际验证 TOTP 登录和恢复码单次使用。若只有一名管理员，应先演练应急恢复流程。
5. 使用普通账号验证项目权限边界；测试停用账号、重置密码、撤销会话后旧 access/refresh token 均不能继续访问。
6. 只有以上全部通过才可以从 RC 升级为生产发布。旧版本不检查会话即时吊销与 `authVersion`；回退时必须先在 Caddy 关闭公网入口，不能在公网入口开启的状态下直接回退认证代码。

## 五、重要安全边界

- 会话最长 7 天、连续 12 小时无操作失效；access token 15 分钟。
- 管理员公网登录必须 MFA；应用使用 TOTP，不依赖邮件/短信服务。
- 账号/IP 失败限流采用 HMAC 键；安全事件按策略保留 180 天。
- `MFA_ENCRYPTION_KEY` 不只用于解密 TOTP 种子，也用于恢复码 HMAC。轮换该密钥前必须执行受控迁移或重新登记管理员 MFA；密钥丢失会使现存 MFA 因素不可验证。
- 公网模式拒绝关联不到服务器端会话的旧刷新令牌，切换到公网 HTTPS 后用户需要重新登录。
- IP 与 User-Agent 用于安全审计，不等于可靠地理定位结果。
