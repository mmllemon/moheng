# 墨衡后续四阶段开发路线图

本路线图是当前产品开发主线，不按测试门禁的数量定义产品进度。各阶段需要提交可审查源码、可复现测试和对应用户体验结果；阶段状态必须根据实际代码和运行证据更新。

## 阶段一：完成报表中心与 XLSX 交付体验

### 目标

形成成本人员可日常使用的项目级综合报表和公司级经营报表，并保证报表预览、打印和 XLSX 文件表达一致。

### 工作包

1. **工作簿导出总览页：** 将报表类型、模板版本、生成时间、数据范围、工作表目录、截断/提示放在 XLSX 首张表；保留模板实际报表页与可选说明页。
2. **项目级综合报表：** 支持项目概况、主合同、有效外部变更、分供合同、收款/退款、进度款、应收、目标成本、实际成本、应付等已具备的数据源组合。需要明确哪些指标是汇总值、哪些是明细集合。
3. **公司级报表：** 汇总口径必须限定为当前用户有权查看的项目；可提供公司概览、项目清单及分供合同/收付款/成本明细。
4. **单元格绑定与区域扩展：** 单值字段绑定到指定单元格；多值数据集通过重复区域扩展；同一记录的多个字段必须来自同一数据源记录；多个重复区域互不串行、不得错配。
5. **自由布局与工作表体验：** 保留合并单元格、行高/列宽、字体、字号、颜色、填充、对齐、边框、格式、冻结窗格和分页属性；为重复/无效工作表名提供稳定处理。
6. **可用性细节：** 明确空数据、行数上限、截断、权限过滤、金额精度与生成失败状态。导出文件只读，不回写业务数据。

### 验收

- 自动化测试读取真实 XLSX buffer，验证工作表顺序、单元格值、格式、合并、打印设置、精确金额和截断信息。
- 预览和下载必须由同一服务端渲染结果生成；不得让前端预览与后端导出各自计算一遍业务金额。
- 使用有多个分供合同、变更和收付款流水的脱敏项目做真实浏览器验收。
- 产品负责人确认版面信息层级和 Excel 使用体验；未确认的视觉呈现不能标记为满意。

## 阶段二：全站 UI 与交互统一

### 目标

在保留墨衡独立、克制、面向专业成本工作的视觉风格前提下，统一页面布局、控件与状态表现，减少“每页一套”。

### 工作包

1. 以 `docs/设计系统规范-Pro-Tier-Suite-v4.2.0.md` 为唯一设计令牌基准，清查硬编码颜色、间距、圆角、字体、阴影和重复 CSS。
2. 检查日期选择器、下拉选择器、搜索/多选、输入框、金额输入、弹窗、表格、分页、筛选栏、按钮和状态标签的实际使用点；共享组件优先，不为统一而牺牲原生可访问性。
3. 统一页面标题/说明、主要操作位置、筛选折叠、表格密度、加载/空/错误/无权限/保存中/保存成功/脏数据状态。
4. 验证响应式布局、键盘导航、焦点管理、中文输入法、屏幕阅读器语义和动效降级；修复门户/工作台之间的层级与间距问题。
5. 按业务流程逐页整改，而不是只改控件皮肤；至少覆盖项目、主合同、成本台账、变更签证、收付款、分供结算、系统管理和报表工作室。导航清理需把“项目成员与权限”放在项目/系统管理边界，不当作成本业务标签；没有真实指标定义的“经营健康度”指示器不得作为 KPI 展示，并移除只为装饰、没有真实数据的指标。

### 验收

- 建立页面/控件清单与实际改动清单，拒绝只靠字符串静态断言宣称视觉通过。
- 相同类型控件在主工作流中视觉、尺寸、错误提示、键盘与焦点行为一致。
- 浏览器截图/实操检查桌面主分辨率与窄屏；记录残留差异和明确例外，包含项目驾驶舱与项目成员导航位置。
- 产品负责人按页面验收，未验收页面保持“待确认”，不能声明 UI 已满意。

## 阶段三：完成 AI 助手的产品闭环

### 目标

让成本人员通过自然语言查询墨衡已有的经营台账，获取可追溯、边界清楚的只读分析，而不是让模型执行模糊的财务写操作。

### 工作包

1. 完成模型配置就绪检查：模型 ID、密钥、兼容 API 地址、checkpoint 数据库、功能开关；状态接口不得回显秘密。
2. 打磨助手入口、示例问题、会话/项目隔离、消息流、工具运行轨迹、来源摘要、生成时间、口径与局限说明、错误重试及空结果反馈。
3. 让现有只读工具覆盖项目经营概览、成本偏差核查、变更资料完整性；先完善数据证据和可解释性，再扩充工具。
4. 处理真实模型超时、结构异常、空回答、工具异常、断线重连、取消/重试、重复提交和进程重启；持久化事件为恢复依据。
5. 完成提示注入、越权、猜测会话 ID、模型无效参数、输出泄漏、敏感日志、限流/成本预算和业务表只读断言。
6. 使用 fake provider 的无费用 E2E 作为持续回归；由用户在受控环境提供模型凭据后开展真实模型验收。

### 验收

- 必须证明每次工具调用使用认证用户和服务端项目权限；模型不能选择可信 userId、绕过项目授权或调用任意 SQL/HTTP/文件/命令。
- 回答展示使用了哪些工具/数据范围、生成时间和局限；不能伪称每句话都由某一条记录精确支持。
- 同一会话并发、SSE 重放、取消/失败恢复和 worker 重启行为通过自动化与目标环境实测。
- `ASSISTANT_POC_ENABLED` 在完成只读内测与独立准入批准前保持关闭。

## 阶段四：统一回归、整理交付与发布评审

### 工作包

1. 以 Node.js 24+ 干净工作树和锁文件执行安装、Prisma Client 生成、schema 校验、严格类型检查、lint、构建、API 单测、Web 测试及发布候选检查。
2. 使用隔离 PostgreSQL 覆盖全量历史迁移、关键状态机、权限隔离、并发幂等、财务金额和审计。
3. 在脱敏预发布快照上逐项目核对迁移前后原始合同基线、有效合同额、对账原因和主体关联；所有无法恢复的历史责任人/单位身份保留为明确异常。
4. 做真实浏览器 E2E：登录、角色/项目权限、报表设计/预览/下载、AI 会话和错误恢复、主业务流程。
5. 完成 Windows 原生安装/启动/停止、目录 ACL、备份与恢复、密钥配置、运行日志与故障处置演练。
6. 清理文档、移除过时报告和提交进仓库的临时产物，生成版本说明、源代码交付清单和发布限制。
7. 汇总阻断/例外，按证据决定是否提升版本或放行；任何关键项未通过则保持 RC。

### 最终交付物

- 完整源码与迁移文件、锁文件、必要脚本。
- 唯一有效文档索引、用户手册、开发/部署手册、业务规则、AI/报表规格及更新日志。
- 自动化测试和 CI 证据链接。
- 仍未完成事项、环境前置条件、风险与已知限制的明确清单。

## 依赖与顺序

阶段一、阶段二可以并行小步推进；阶段三可以在 UI 规范确定后完善体验，但不得因真实模型密钥未到位而停止其可独立实现的源码与 fake-provider 工作；阶段四持续执行并在前三阶段完成后集中验收。产品实现与回归同步进行，但回归不能取代功能开发。
