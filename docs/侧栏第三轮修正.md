## 一、左上角：抽屉按钮与品牌区重叠

### 1.1 实测数据（修正前）

```
抽屉按钮:   y=5   h=28  → 底部 33
品牌图标:   y=23  h=31  → 顶部 23
重叠:       10px
```

按钮和品牌图标在垂直方向重叠 10px，视觉上就是「按钮紧贴着品牌区」。

### 1.2 根因

moheng 的 `app-sidebar-titlebar` 只有 16px 高：

```css
.app-sidebar-titlebar {
  flex: 0 0 auto;
  padding: var(--space-8) var(--space-16);   /* 8px 上下 + 内容 */
}
```

**它没有起到「让位」的作用。**

### 1.3 Hana 的做法

```css
._fpTrafficRow_5ddeb {
  flex-shrink: 0;
  height: var(--fp-traffic-row-height, var(--titlebar-h, 44px));
  -webkit-app-region: drag;
}
```

**`fpTrafficRow` 是一条 44px 高的纯让位行，里面不放内容。** 它的唯一作用是把侧栏内容推到窗控按钮下方。

### 1.4 修正

```css
.app-sidebar-titlebar {
  /* 对齐 hana ._fpTrafficRow：纯让位行，44px，无内容 */
  flex: 0 0 auto;
  height: var(--titlebar-h, 44px);
  display: flex;
  align-items: center;
  gap: var(--space-4);
  padding: 0 var(--space-16);
}
```

实测（修正后）：

```
titlebar 让位行: y=1  h=44  ✓
品牌区:          y=45 h=45
品牌图标:        y=51 h=31
抽屉按钮:        y=5  h=28  → 底部 33
重叠判定: 按钮底部 33 vs 图标顶部 51 → ✓ 不重叠（间隙 18px）
```

## 二、右上角：多余的「项目档案」按钮

### 2.1 问题

`sidebar-profile-action`（打开项目档案）位于 y=26 x=201，占用了品牌区右侧。

截图里看起来像「多出来的按钮」，很突兀。

### 2.2 判断

**导航区已经有「项目档案」项：**

```tsx
{ to: '/projects', label: '项目档案', icon: FolderKanban, group: '项目管理', end: true }
```

品牌区再放一个，是**重复入口**。

### 2.3 对照 Hana

Hana 侧栏顶部右侧放的是 `fpWorkspaceModeMenu`：

```css
._fpWorkspaceModeMenu_693c3 {
  display: inline-flex;
  flex-shrink: 0;
  margin-inline-start: auto;      /* 推到最右 */
}
```

**它是「工作区模式菜单」，导航里没有这个功能，所以不重复。**

moheng 没有对应功能，所以这个位置应该空着。

### 2.4 修正

删掉两处（主侧栏 + 抽屉）的 `sidebar-profile-action`。

```
删除 2 处
残留 sidebar-profile-action: 0
```

实测：

```
右上角多按钮: ✓ 已删除
```

## 三、排序图标：显隐范围搞错了

### 3.1 我的错误

我以为是「鼠标移到排序图标区域才显示」：

```css
.sidebar-section-title:hover .sidebar-section-title-actions { opacity: 1; }
```

**这只在鼠标精确移到标题行时才生效。**

### 3.2 Hana 的真值

```css
._sessionListScroller_5f4dd:hover ._sectionTitleActions_8338c,
._sessionSectionTitle_eb6ae:hover ._sectionTitleActions_8338c {
  opacity: 1;
}

._sessionSectionTitle_eb6ae:focus-within ._sectionTitleActions_8338c {
  opacity: 1;
}
```

**关键是 `._sessionListScroller:hover`** —— 鼠标进入**整个会话列表滚动区**（包含导航 + 会话列表）时，操作区就显示。

不是只悬停标题。

### 3.3 修正

```css
.app-sidebar-scroll:hover .sidebar-section-title-actions,
.sidebar-drawer .app-sidebar-scroll:hover .sidebar-section-title-actions,
.sidebar-section-title:hover .sidebar-section-title-actions,
.sidebar-section-title:focus-within .sidebar-section-title-actions {
  opacity: 1;
}
```

实测：

```
鼠标在画布区:     opacity=0  ✓
鼠标在导航项上:   opacity=1  ✓ 已显现（对齐 hana）
鼠标移出:         opacity=0  ✓
鼠标在标题上:     opacity=1  ✓
```

## 六、这轮暴露的方法问题

我连续三轮在同一个地方出错：**用「看起来合理」代替「查源码」**。

| 轮次 | 我的假设 | 实际情况 |
|---|---|---|
| 第 1 轮 | 搜索框只需要 margin | 还有 `::before` 分隔线 |
| 第 2 轮 | 排序图标悬停标题才显示 | 悬停整个滚动区就显示 |
| 第 2 轮 | 侧栏拖拽是排序 | 是拖出成独立卡片 |

**共同的错法：看到一个近似的实现，就当成等价。**

修正方法：每做一个交互，先去 CSS/JS 里搜该组件的**所有规则**（不是第一条），确认触发条件、默认态、过渡属性。
