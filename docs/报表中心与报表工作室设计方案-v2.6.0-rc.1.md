# 墨衡报表中心与报表工作室设计方案 v2.6.0-rc.1

- 基线：`v2.5.0-rc.1`
- 目标候选：`v2.6.0-rc.1`
- 性质：增量产品/架构设计与源码候选，不等于生产验收签字

## 1. 本轮决定

1. 预览表格按模板声明的每列宽度渲染，列数少时不把最后一列扩展来填满视口；容器允许横向滚动。打印输出单独适配页面宽度。
2. 报表中心按使用场景组织：标准台账、项目综合经营、公司经营报告、往来单位经营档案；导出历史/任务状态为公共功能。项目级与公司级的数据范围分别受授权控制，公司级报告不是简单等同于所有项目。
3. 各业务工作区复用同一预览/导出工作流，不实现每个页面独立的导出器。按钮仅传入白名单报表 key 和当前业务上下文，服务端仍做权限校验。
4. 新增 `PARTY` 域与 `businessPartyId` 模板范围，内置往来单位经营档案默认模板。单位模板需绑定明确单位 ID，不会把一个单位的模板或报告误用于另一个单位。
5. 自动延伸区域使用同源记录对象逐行渲染；不同集合区域独立扩展，不按行号跨集合配对。

## 2. 自动延伸区域怎样保证准确

### 2.1 绑定契约

每条业务记录有稳定主键；每个字段绑定包含稳定的 `sourceId`、`fieldId`、工作表 ID 和单元格坐标。每个重复区域声明 `sourceId`、样板行、起止列和最大行数。后端会验证：

- `sourceId` 属于当前报表域白名单，字段 ID 存在；
- 集合字段 (`MANY`) 必须位于其同 `sourceId` 重复区域的样板行和列范围；
- 单条记录 (`ONE`) 不得误放在重复区域样板行；
- 一个样板行只允许一个重复区域，区域不得超出表格边界或与不支持的跨行合并冲突；
- 模板中不允许可执行公式、任意 SQL 或脚本。

### 2.2 渲染规则

后端先按当前用户授权范围查询数据集。重复区域接收有序记录数组；第 *i* 个输出行的所有绑定字段，都从同一条记录（即该区域的第 *i* 个记录对象）读取值。不能让同一行里的每个单元格分别查数据，不能把合同第 *i* 行和收款第 *i* 行按索引关联。没有记录时保留一个空样板行，以免后续版式行意外上移。独立区域分别扩展，后续行和合并区域按之前扩展的行数统一偏移。

每个集合数据源都必须采用确定的排序，并用数据库 ID 作为最后 tie-breaker。需要跨实体关联时只在受控数据源查询层按实际外键/业务 ID 关联，不能凭名称或呈现行号匹配。数据源查询有上限，并用上限加一条的方式识别是否真正截断；发生截断时相关金额汇总不可输出为“完整总额”。单位经营档案的分供合同明细若超过上限，明细显示受限样本，同时将依赖该集合的合同、应付、成本和发票相关汇总置空并给出警告。

### 2.3 测试要点

- 2 条分供合同、3 条收款分别展开时，合同区域输出 2 行、收款区域输出 3 行；同一合同号与合同额来自同一合同记录。
- 把收款字段绑定到合同重复区域必须被定义校验拒绝。
- 空集合保留空样板行，下面标题/页脚位置稳定。
- 多次查询排序稳定；不同集合数量不同不会制造虚假关联。

## 3. 页面入口与体验

### 3.1 报表预览列宽

预览宽度根据模板每列的有界宽度设置，普通预览使用自然宽度与固定布局。视口变宽时剩余空间留白，不能自动放大最后一列造成视觉误导。打印页面可选择适配纸宽，但预览屏幕布局不能被打印规则影响。长文本应换行并设置合理最大宽度。

### 3.2 报表中心

主页区分快速生成和模板设计。标准台账按成本、业主财务、分供分类；项目综合报告、公司经营报告及单位经营档案作为独立入口。模板列表、权限和历史版本仍由原模板 API 管理。

### 3.3 工作区快捷入口

- 目标成本、实际成本、进度款、变更签证、分供合同、分供应付、业主应收、业主收退款：快捷打开对应标准报表的预览页。
- 项目驾驶舱和合同/财务相关项目工作区：打开项目综合经营报告；主合同信息纳入该报告的数据源，不再重复创建独立、口径不一致的汇总算法。
- 往来单位经营档案：提供“预览/导出经营档案”和“编辑报表模板”两个入口；前者打开单位专属默认报告，后者加载该单位已保存的个人模板，避免重复建立空白模板。

各按钮是入口，不是绕过权限的后门。服务端按会话与项目/单位关联再次判权。

## 4. 默认往来单位经营档案报告

默认模板展示单位主档和身份核验状态、按授权范围聚合的关联项目、业主/主合同关联、分供合同、独立成本记录及经营摘要。历史名称回填或待核验的单位身份要显式显示核验状态，不能将名称相同自动当成同一法律主体。

模板上下文通过 `businessPartyId` 隔离。新迁移 `20261015030000_party_report_template_context` 为模板增加可空单位关联、索引与外键；旧迁移保持不变。创建、读取、保存、发布、预览和导出均需验证单位是否在用户可访问范围内，跨单位模板使用应拒绝。

## 5. 精确金额与上限

财务聚合以 BigInt 整数分累计，输出十进制字符串供模板渲染。不要先把 Decimal 转成 JavaScript `number` 再加总。对于超出 Excel 15 位有效数字安全范围的金额，渲染器以文本保留精度。数据源超过查询上限时相关汇总标为空并出具警告，不得把部分行合计冒充完整金额。

## 6. 兼容性与范围边界

- 保留 v2.4 的项目/公司报表工作室、Univer 编辑界面、ExcelJS XLSX 渲染、PostgreSQL 后台任务及标准报表。
- 保留旧模板的读取路径；当前新版工作室的定义为 schema v2，模板迁移或转换必须显式执行，不静默 reinterpret 旧模板。
- 工作区快捷导出共用相同 preview/export 端点，不复制数据查询与格式逻辑。
- 本轮不引入 Redis、RabbitMQ、Kafka、独立报表服务，不开放任意 SQL、JavaScript、宏或可执行公式。

## 7. 当前交付与未完成验证

源码候选增加稳定排序、重复区域同源验证、单位模板上下文、工作区快捷按钮、预览列宽与导航调整。当前静态契约、纯逻辑渲染测试、仓库原生下拉/日期扫描和 TypeScript 语法转译可在本机可用工具范围内执行。

由于当前环境没有完整的 Node.js 24+ 依赖安装，严格 TypeScript 类型检查、前后端完整构建、Prisma Client 生成、真实 PostgreSQL 迁移与权限/事务联测、浏览器 Univer 操作、Excel/WPS 打开及打印仍需目标环境完成。版本仍为 RC。


## 5. v2.6.0-rc.1：报表中心减负与导航语义

### 5.1 报表中心布局判断

v2.5 页面中“3 张介绍卡 + Hero 内重复报表数量 + 下方大型标准报表卡片 + 上方报表类型选择器”提供重复信息和多个选择路径。本轮移除三张介绍卡和重复 Hero，消除“报表类型下拉”与大型卡片目录的重复入口。新布局只保留：

1. 页面标题与一行用途说明；
2. 两个具有明确 CTA 的综合经营报告入口（项目级、公司级）；
3. 标准台账单一主区域：左侧紧凑目录/分类，右侧项目范围、日期、说明、CSV、模板设计和预览导出操作。

综合报告入口仍是整块可点击按钮，但新增“打开项目级工作室/打开公司级工作室”的动作文案、箭头提示、hover 和 focus-visible 状态。尊重系统减少动效偏好。标准台账目录按短行呈现并限制描述为单行，不再用大卡片反复展示字段说明。

### 5.2 经营健康度的语义修正

v2.5 侧栏“经营健康度 / 收入与支出持续跟踪”是静态装饰元素：没有真实数据、数值、计算定义、数据源、状态判定或跳转功能，不能视为健康度指标。本轮移除这个容易误导用户的名称，替换为真正可操作的“项目驾驶舱 / 查看当前项目经营摘要”入口，点击导航至 `/workspace`。如果未来建设经营健康度，应先正式定义维度、权重、阈值、缺失数据处理、数据截止时间与明细解释；未建成前不使用评分/健康度话术。

### 5.3 项目成员导航归属

项目成员与权限属于项目治理/协作能力，不属于“成本与支出业务”，也不应在视觉分组上挨着分供合同。已从 `costTabs` 移出，作为独立“项目管理”分组呈现；路由 `/workspace/members` 与权限实现不变。

### 5.4 本轮验收要点

- 不再同时出现说明卡、Hero 计数徽章和大型重复目录；标准台账只保留一套选择入口。
- 经营报告按钮具有明确动作文案、鼠标悬停反馈和键盘焦点提示。
- 1120px 以下报表区域纵向堆叠；小视口下表单、动作按钮可换行，不发生横向溢出。
- 项目成员位于独立项目管理分组；不属于成本/分供分组。
- 侧栏不再出现虚构的经营健康度指标，改为可点击项目驾驶舱快捷入口。
- 全部现有合同、结算、收款、成本和权限业务规则保持不变。
