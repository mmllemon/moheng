# 安全、账号与公网部署

## 1. 身份与会话

- Access token、HttpOnly refresh cookie、会话撤销与刷新令牌重放防护由服务端实现。
- 普通登录用户只能访问服务端判定授权的项目；公司级只读范围必须有明确权限策略，不以“管理员之外的所有用户”默认开放。
- 管理员 MFA/TOTP、恢复码、登录失败限流和强制改密有相应服务端路径；权限页面的隐藏不替代后端守卫。
- 密码、TOTP、恢复码、session token、API key、数据库连接串不得进入普通日志、审计变化快照或 Git 仓库。

## 2. 公网访问前置条件

公网模式不是安装后自动安全。只有在真实公网/内网 HTTPS 反向代理、密钥、账号和恢复步骤均经验证后才能评估上线；静态配置检查通过不能认为已经正式上线。

需要按实际拓扑明确设置：

| 配置 | 要求 |
|---|---|
| `PUBLIC_BASE_URL` | 正式 HTTPS URL；不得含用户名/密码或使用 HTTP |
| `COOKIE_SECURE=true` | 公网模式启用 secure cookies |
| `HOST=127.0.0.1` | API 仅监听本机，由可信代理转发 |
| `TRUST_PROXY` | 明确列出受信代理地址；不得使用通配信任 |
| `JWT_SECRET` | 独立随机高熵密钥，至少 32 字符 |
| `MFA_ENCRYPTION_KEY` | 与 JWT 密钥分离；需要安全备份以恢复 MFA 数据 |
| `LOGIN_ATTEMPT_HMAC_KEY` | 与 JWT/MFA 密钥分离；不要通过轮换 JWT 密钥重置限流桶 |
| `BACKUP_ENCRYPTION_KEYS` | 备份加密密钥环，按版本维护恢复能力 |

Caddy/IIS/企业反向代理应终止 TLS 并把请求转发到 `127.0.0.1:3001`。通常对外只开放 TCP 80/443；PostgreSQL 5432 不对互联网开放。实际防火墙规则以运维拓扑为准。

## 3. 数据范围和只读授权

- 项目列表、经营报表、往来单位跨项目摘要和 AI 工具都必须基于服务端可访问项目集。
- 只读范围不自动产生新增/修改/删除权限。AI 使用 `PROJECT_READ` 等已有策略，并在每次工具执行时重新核验。
- 管理权限、项目角色和公司级只读范围要分开管理；某个用户被授权跨项目查看，不意味着它成为公司管理员。
- 变更签证的内部审批和外部业主/授权代表确认分离。提交人不得审批本人提交的业务。

## 4. 密钥、附件与备份

- `apps/api/.env` 只存本机/服务运行身份可读取的密钥，不纳入源代码管理。
- 变更凭证附件使用持久化受控目录；Windows 部署配置 NTFS ACL，限制 API 运行账号及指定备份管理员。
- 数据库备份应加密、校验 hash，并安全保管密钥。恢复演练使用单独的 `RESTORE_TEST_DATABASE_URL` 或独立测试目标；必须核验目标集群身份，不能将恢复操作指向生产。
- 备份与恢复既要包括数据库，也要考虑附件目录、配置密钥、数据库角色/权限和日志/审计留存；记录恢复耗时与数据损失窗口。
- 轮换 JWT、MFA、登录限流和备份加密密钥应分别制定兼容/恢复步骤，不要在生产同时试验多项密钥轮换。

## 5. 当前发布边界

当前版本仍是 RC。真实公网 HTTPS、MFA/会话失效、Windows ACL、异地加密备份、恢复目标隔离、浏览器关键流程和真实预发布数据验证必须以部署环境证据为准。具体阻断项见[发布与迁移验收](发布与迁移验收.md)。
