## 按钮尺寸的透明边框机制

```css
.titlebar-icon {
  width:  calc(var(--card-top-btn-size, 24px) + var(--card-top-btn-pad, 2px) * 2);   /* 28 */
  height: calc(var(--card-top-btn-size, 24px) + var(--card-top-btn-pad, 2px) * 2);   /* 28 */
  box-sizing: border-box;
  padding: 0;
  background: transparent;                                        /* ← 必须在前面 */
  border: var(--card-top-btn-hover-inset, 3px) solid transparent;
  background-clip: padding-box;                                   /* ← 必须在后面 */
  border-radius: calc(var(--radius-action) * var(--corner-radius-scale, 1));
  corner-shape: squircle;
}
```

**悬停底色只填内部 22×22，四周留 3px 透明边。** 这就是 Hana 的按钮看起来更「疏」的原因。

## 一个 CSS 顺序陷阱（花了四轮才定位）

`background` 是简写属性，**会重置 `background-clip` 为默认值 `border-box`**。

```css
/* 错误顺序 */
border: 3px solid transparent;
background-clip: padding-box;    /* ← 被下一行覆盖 */
background: transparent;         /* ← 重置 clip 为 border-box */

/* 正确顺序 */
background: transparent;
border: 3px solid transparent;
background-clip: padding-box;
```

我最初写的是错误顺序，实测 `bgClip: border-box`。

**排查过程**：
1. 以为是覆盖规则 → 查全部 CSS，只有两处声明，无覆盖
2. 以为是环境不支持 → 纯净测试（独立 HTML）三种 corner-shape 全部正常
3. 以为是 `var()` 边框的问题 → 纯净测试也正常
4. 用 CDP 读 `cssText` → **发现 `background-clip` 根本不在规则里**，被浏览器丢弃

**教训**：`cssText` 里缺某条声明，说明它被后续声明覆盖后丢弃了，不是选择器问题。查 CSS 生效问题，`cssText` 比 `computed style` 更能定位根因。

hover 和 is-active 也都要补 `background-clip`：

```css
.titlebar-icon:hover {
  background: var(--overlay-light);
  background-clip: padding-box;   /* 简写会重置，必须重声明 */
  border-color: transparent;
  color: var(--text);
}
```

## 面板开关的语义映射

Hana 有 `preview` / `workspace` 两个独立面板，moheng 只有一个面板两个 tab：

| Hana | moheng |
|---|---|
| `preview` 开关 → 打开预览面板 | 预览按钮 → 面板打开 + 切到「对话文件」 |
| `workspace` 开关 → 打开工作区 | 工作区按钮 → 面板打开 + 切到「工作室」 |

`workspaceTab` 从 WorkspacePanel 的内部 state 提升到 uiStore，因为顶栏也要切它。

## 一处保留 moheng 现状

**右岛保留 6 个系统按钮**（搜索 / 待办 / 助手 / 快捷 / 设置 / 头像），Hana 的右岛是「收藏 / 截图 / 最小化 / 关闭」窗口操作。

按「重叠按 hana、独有暂不改造」的原则保留。
