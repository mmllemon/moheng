# 门禁债务清单

本仓库有 35 条门禁，由 `scripts/run-gates.mjs` 逐项运行（不再是一条 `&&` 长串，第一项失败即全停）。
分级决定写在 `scripts/run-gates.mjs` 的 `GATES` 表（`tier` / `reason` 字段）。

```bash
node scripts/run-gates.mjs --list                 # 看门禁与分级
node scripts/run-gates.mjs --tier blocking        # 必须通过：失败即应拦 PR
node scripts/run-gates.mjs --tier advisory --capture   # 已知债务：摘要式明细
node scripts/run-gates.mjs --only architecture     # 单跑一条
```

CI 接入：`.github/workflows/source-gates.yml`。blocking 失败拦 PR；advisory 用
`continue-on-error` 不拦 PR，但每次都在 Job Summary 输出债务明细。

**第一批：三条 `assistant-*` 断言指向已搬迁的实现**

| 门禁 | 改法 |
| --- | --- |

| `assistant-conversations` | 同上；另一条 `isAssistantBaseUrlValid(process.env.OPENAI_BASE_URL)` 改为断言 `isAssistantBaseUrlValid(runtime.baseUrl)` **且位置在入队之前**（保序语义，且基线已是同款写法，此条此前一直被遮蔽） |
| `assistant-ui` | 助手按钮已下沉到标题栏组件，改为断言 `WindowControls.tsx` 里的 `{assistantEnabled && <button`，并保留 Layout 传参与 `AssistantModal`、禁止工作区页签的负向断言 |

**遮蔽效应（本轮最有价值的发现）**：这三条用 `assert` 抛错而非累计 `check()`，首条失败即中止整个脚本，
其后约 30 条断言**根本没跑**。解蔽后 `assistant-conversations` 立即暴露出另一条早已失效的断言（见上表）。
教训：抛错式门禁的红是“信息量最低的红”，它看着只红一条，实际是整段检查静默失效。

**`architecture`：硬编码计数改结构不变量**

原先断言 `moduleIds.length === 19` 与 `mountPrefix === 19 && integrationVisible: true === 16`；
模块由 19 增至 21（`workspace`、`project-artifacts`）后没人同步魔法数，门禁长红。现改为：

- 模块条目数 == 顶层路由插件数（`system-config.ts`、`assistant-conversations.ts` 属内联挂载例外）；
- 每个条目都声明 `mountPrefix` 与 `integrationVisible`；
- 不上集成目录的模块集合必须与显式登记名单逐个一致（新模块要隐藏就得加一行，而不是靠总数对不上）。

变异测试实测：新增一个可见模块 + 路由文件 → 两查仍通过，无需改门禁（即不再漂移）；
新增隐藏模块但未登记 → 失败；新模块漏写 `mountPrefix` → 失败。改后 11/11 通过。

### 1b. `v2-work-packages`：一条是我误判，一条是真缺陷（均已修）

**一、头部作用域标签：不是缺口，门禁钉的是旧设计。**
旧断言要 `location.pathname.startsWith('/reports') ? '全局报表中心'` 这种 per-route 文案，
全仓 0 命中。但 `isGlobalContext`（`Layout.tsx:383`）仍然存在，顶栏状态段渲染
`{isGlobalContext ? '全公司' : '项目'}`（第 693 行），且项目选择器在全局上下文直接不渲染
（第 705 行）。Playwright 实测 380 / 900 / 1440 三档下，`/`、`/reports`、`/notifications`、
`/projects/members` 的头部作用域均为“全公司”，项目下拉均不出现。→ 门禁改为断言该机制本体。

附带：`hana.css:1421` 的 `.titlebar-global-scope` 胶囊已成为孤儿样式（它对应的就是被
两岛改版替掉的旧写法）。不删：基线 `3feb702` 本身就是一次“完全回滚死规则清理”的 revert，
说明这类清理你已经否决过一次，这里不再自行动手。

**二、窄屏：确实坏了，两个独立缺陷。**

1. `@media (max-width: 900px)` 里的抽屉只用 `transform: translateX(-100%)`，侧栏虽然看不见，
   却仍然占住 `--sidebar-width` 的弹性空间 → ≤900px 时主区右侧被挤出一条死白。
   实测（修复前）：380px 时 `.app-content` 仅 128px 宽（L246→R374），900px 时也只有 648/900。
   后果是顶栏两岛重叠并被裁切：左岛 258→448 与右岛 306→366 重叠，越出视口 19～68px。
   同块里的 `.app-main { margin-left: 0; }` 说明当初就想让主区吃满，只是 margin 不是占位来源。
   修法：侧栏 `position: fixed` 真正脱离 flex 流。实测（修复后）：380px 主区 374px、
   900px 主区 894px，侧栏停在 -252→-12，各宽度顶栏溢出节点 0，桌面 1440 不变。
2. 修完 1 后暴露第二个问题：该媒体块把顶栏 `padding-left` 写成 12px，而
   `.shell-traffic-strip` 是 `position: fixed` 占 0→42px，抽屉按钮被压在它下面。Playwright
   实测：修复前点击“打开主导航”超时，事件被窗口控制岛/固定条抢走。修法：标题栈 `padding-left`
   让开固定条（42px + 间隙）。修复后实测：点击生效，侧栏进入 `app-sidebar mobile-nav-open`
   且位于 0→240，遮罩 `display: block`，`data-focus-trap=modal`，无横向溢出。

门禁相应改为断言“减动效全局规则 + ≤900 抽屉外壳 + ≤760 断点骨架”（逐页媒体规则在 V6
改版时被有意删除，见 `legacy.css:461-463` 的删除说明注释），已升为 blocking。

**三、`document-links`：6 个断链已清。** 它们全指向 `docs/gates/*.md`，而该目录下的过程证据文档
已随 `cf92654 chore: 移除 docs/gates 过程产物（82MB）` 从仓库删除。没新建文档顶替，而是把
`docs/INDEX.md` 与 `docs/架构与核心业务规则.md` 的引用改指仍存在的活文档（`发布与迁移验收.md`
已按精确头提交记录 PR #17 / #18 的 CI 证据），并在正文留下被删文档的出处提交号与可复现脚本入口。
现在 142 个本地链接目标全部可解析。

**全仓扇扫（防同类复发）**：各门禁脚本里含裸 `\n` 的正则共 10 处，逐个判定后只有 hairline
滚动条那一处会因 CRLF 失配（已修）；其余是 `[^)\n]` / `[^\n]*` / `\s*\n` 这类对 `\r` 包兼容的
写法，以及 `replace(/\r\n/g, '\n')` 这种归一器本身。结论：这一类假红已无残留，不值得为此
改动全局行尾策略。

## 升 / 降 tier 的规则

1. 一条 advisory 门禁修绿后，把 `GATES` 里它的 `tier` 改成 `blocking`，并在提交说明里带上修绿的断言。
2. 不要在门禁红着的时候把它从 CI 里摘掉——那等于让质量闭环再次静默。
3. 新增门禁默认 `advisory`，连续在 CI 里绿过若干次后再升 `blocking`，避免新写的断言一上来就阻塞所有人。
4. 禁止用“删除检查项”的方式让门禁变绿。
5. 若某条断言与另一条门禁互斥（历史上出现过两次：`系统管理扩展入口`、`!important` / `window.confirm`），
   禁令只由一条门禁持有，另一条改指现行实现，避免同一份代码永远无法同时满足。
