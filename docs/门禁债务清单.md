# 门禁债务清单

本仓库有 35 条门禁，由 `scripts/run-gates.mjs` 逐项运行（不再是一条 `&&` 长串，第一项失败即全停）。
分级决定写在 `scripts/run-gates.mjs` 的 `GATES` 表（`tier` / `reason` 字段）。

```bash
node scripts/run-gates.mjs --list                 # 看门禁与分级
node scripts/run-gates.mjs --tier blocking        # 必须通过：失败即应拦 PR
node scripts/run-gates.mjs --tier advisory --capture   # 已知债务：摘要式明细
node scripts/run-gates.mjs --only architecture     # 单跑一条
```

CI 接入：`.github/workflows/source-gates.yml`。blocking 失败拦 PR；advisory 用
`continue-on-error` 不拦 PR，但每次都在 Job Summary 输出债务明细。

## 19 条债务按性质分组

### 1. 断言文本已过时（优先修，成本最低）

这三条都断言 `apps/api/src/routes/assistant-poc.ts` 源码里含
`process.env.ASSISTANT_POC_ENABLED` 字样，而该判断已迁到 `assistant-config`。

| 门禁 | 现象 |
| --- | --- |
| `assistant-runtime-decision` | `PoC route must be hidden unless explicitly enabled` |
| `assistant-conversations` | `assistant must remain feature-gated off by default` |
| `assistant-ui` | `assistant must be a global modal button hidden unless enabled, not a workspace tab` |

**遮蔽效应（本清单里最危险的一项）**：这三条用 `assert` 抛错而非累计 `check()`，
首条失败即中止整个脚本，其后约 30 条断言**根本没跑**。所以它们看起来"只红一条"，
实际是整段检查静默失效。修法是让门禁指向开关判断的真实位置，而不是删断言。

### 3. 封版证据过期（需 owner 决策，暂缓）

| 门禁 | 现象 |
| --- | --- |
| `source-bundle` | 根 `package-lock.json` 的 SHA-256 与 R7 封版记录不一致。基线 lock 哈希 `575F…` 同样不等于期望 `A6F8…`，即**本轮 zod 升级之前就已不一致**；升级只是把哈希变为 `B182…` |

记录在 `docs/发布与迁移验收.md`）。这属于"修改验收证据"，未经 owner 同意不做。

## 升 / 降 tier 的规则

1. 一条 advisory 门禁修绿后，把 `GATES` 里它的 `tier` 改成 `blocking`，并在提交说明里带上修绿的断言。
2. 不要在门禁红着的时候把它从 CI 里摘掉——那等于让质量闭环再次静默。
3. 新增门禁默认 `advisory`，连续在 CI 里绿过若干次后再升 `blocking`，避免新写的断言一上来就阻塞所有人。
4. 禁止用"删除检查项"的方式让门禁变绿。
