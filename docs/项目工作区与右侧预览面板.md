# 项目工作区与右侧预览面板（方案）

日期：2026-10-23

把 Hana 的「会话工作目录 + 右侧文件树 + 预览」移植为 moheng 的「项目工作目录 + 右侧文件树 + 预览」。

---

## 一、映射关系

| Hana | moheng |
|---|---|
| 会话绑定工作目录 | 项目绑定 `workspaceRoot` |
| `_previewPanel` 右侧面板 | 同结构 |
| `_rightWorkspaceSection` 文件树区 | 同结构 |
| `_previewPanelBody` 预览区 | 同结构 |
| PDF / Markdown / 媒体预览 | PDF / 图片 / 文本 / XLSX |

**一个关键修正**：Hana 不是「两个浮层」，而是**一个面板内上下分区**。

```
_previewPanel (580px)
  ├─ 上：文件树（search 30 + toolbar 25 + tree）
  └─ 下：预览（_previewBodyShell + _previewPanelBody）
```

选中文件后预览在同一面板下半部分渲染。做成两个浮层会争宽度，屏幕放不下。

---

## 二、已确认的决策

| 项 | 决策 |
|---|---|
| 存储位置 | 服务器本地路径 |
| 上传方式 | 手工上传 |
| 文件数量 | 较多 → **必须懒加载** |

---

## 三、后端设计

### 3.1 数据模型

`Project` 加一个字段：

```prisma
workspaceRoot String?   // 相对 STORAGE_ROOT 的子路径，为空时用默认规则
```

默认规则：`{STORAGE_ROOT}/projects/{projectId}`

**不存绝对路径**。绝对路径在多实例部署、容器迁移时会失效。存相对路径，根目录由环境变量 `WORKSPACE_STORAGE_DIR` 决定。

### 3.2 文件系统布局

```
{WORKSPACE_STORAGE_DIR}/
  projects/
    {projectId}/
      合同/
        主合同.pdf
      凭证/
        2026-10/
          发票-001.pdf
```

**直接用文件系统目录结构**，不建数据库表。理由：

- 目录就是树，不需要维护 parentId、path、depth
- 用户可以用资源管理器直接看、直接改
- 删库不会丢文件

代价是没有文件元数据（谁上传的、什么时候）。如果需要，加一个旁挂表 `WorkspaceFileMeta`，以相对路径为主键。**第一版先不做**，等有需求再加。

### 3.3 API

```
GET    /api/projects/:projectId/workspace/tree?path=      列出目录（单层，懒加载）
GET    /api/projects/:projectId/workspace/file?path=      读文件内容（inline）
POST   /api/projects/:projectId/workspace/file            上传（multipart 或 base64）
DELETE /api/projects/:projectId/workspace/file?path=      删除
POST   /api/projects/:projectId/workspace/dir             新建目录
```

**懒加载**：`tree` 只返回一层（`readdir` 不递归），前端展开时再请求。文件多也不会卡。

响应结构：

```ts
type WorkspaceEntry = {
  name: string;
  path: string;          // 相对项目根
  kind: 'file' | 'dir';
  size?: number;
  mtime?: string;
  ext?: string;
  hasChildren?: boolean; // dir 是否非空，用于决定要不要显示展开箭头
};
```

`hasChildren` 需要额外一次 `readdir`，目录多时是 N+1。用 `fs.opendir` 读到第一个 entry 就停，成本很低。

### 3.4 安全

复用 `evidence-storage.ts` 的范式：

```ts
const root = resolve(process.env.WORKSPACE_STORAGE_DIR || 'data/workspace');
const target = resolve(root, projectId, relPath);
if (!target.startsWith(`${projectDir}${sep}`)) throw new Error('WORKSPACE_PATH_INVALID');
```

**必须做的四件事**：

1. 路径穿越防护（`..`、绝对路径、符号链接）
2. 扩展名白名单（禁止 `.exe` `.bat` `.ps1` `.sh` `.dll`）
3. 单文件大小上限（默认 50MB）
4. 项目权限校验（`denyIfNoProjectAccess`）

**符号链接要特别处理**：`readdir` 返回的 `Dirent.isSymbolicLink()` 必须跳过，否则可以链到系统目录。

## 四、前端设计

### 4.1 骨架（Hana 真值）

```css
.preview-panel {
  width: 580px;
  flex-shrink: 0;
  display: flex;
  flex-direction: column;
  border-left: 1px solid var(--overlay-light);
  --paper-texture-surface: var(--bg);
  isolation: isolate;
  transition: width var(--duration-slow) var(--ease-out);
}
.preview-panel.is-collapsed {
  width: 0;
  border-left: none;
}
```

**纸纹**：`isolation: isolate` + `--paper-texture-surface` 是 Hana 的通用纸纹开关，moheng 的侧栏和设置窗已经用了这套。

### 4.2 文件树区

```css
.workspace-section {
  --right-workspace-search-height: 30px;
  --right-workspace-list-toolbar-height: 25px;
  position: relative;
  flex: 1 1 0;
  min-height: 0;
  overflow: hidden;
}
.workspace-search  { height: 30px; margin: 0 var(--space-8); }
.workspace-toolbar { position: absolute; top: 30px; height: 25px; justify-content: flex-end; }
.workspace-tree    { position: absolute; top: 55px; bottom: 0; left: 0; right: 0; overflow-y: auto; }
```

### 4.3 树行（关键：三列网格）

```css
.tree-item {
  --tree-leading-inset: 0px;
  --tree-indent-step: 12px;
  display: grid;
  grid-template-columns:
    calc(var(--tree-leading-inset) + (var(--tree-depth, 0) * var(--tree-indent-step)))
    22px
    minmax(0, 1fr);
  height: 28px;
  padding: 0 var(--space-8) 0 var(--space-2);
  margin: 0 var(--space-2);
  border-radius: calc(4px * var(--corner-radius-scale));   /* 7.36px */
  corner-shape: squircle;
  font-size: var(--fs-caption);                             /* 12.48px */
}
.tree-item:hover { background: var(--overlay-subtle); }
```

**为什么用三列网格而不是 `padding-left`**：`padding-left` 会挤掉内容宽度，深层目录的文件名会过早省略号。三列网格里缩进是独立轨道，名称列始终有空间。

缩进由 `--tree-depth` 内联样式控制，组件只传数字。

### 4.4 选中态

```css
.tree-item.is-selected { background: rgba(var(--accent-rgb), .1); }
.tree-item.is-selected:hover { background: rgba(var(--accent-rgb), .14); }
```

### 4.5 悬停操作区

```css
.tree-item:hover .tree-main    { padding-right: 122px; }
.tree-item:hover .tree-actions { opacity: 1; pointer-events: auto; }
.tree-actions {
  position: absolute; right: 6px; top: 50%; transform: translateY(-50%);
  display: inline-flex; gap: 2px;
  padding-left: 8px;
  background: linear-gradient(90deg, transparent, var(--overlay-subtle) 10px, var(--overlay-subtle));
  opacity: 0; pointer-events: none;
  transition: opacity var(--duration-instant) var(--ease-out);
}
```

`padding-right: 122px` 是给按钮让位，避免文件名和按钮重叠。这个值是 Hana 实测的。

### 4.6 预览区

按扩展名分流：

| 类型 | 渲染 |
|---|---|
| `.pdf` | `<iframe src="...">` |
| `.png/.jpg/.jpeg/.webp/.gif` | `<img>` |
| `.txt/.md/.json/.csv/.log` | `<pre>`（限 2MB） |
| `.xlsx/.xls` | SheetJS 解析成表格（后续） |
| 其他 | 图标 + 「不支持预览，点击下载」 |

### 4.7 组件结构

```
WorkspacePanel.tsx          面板容器（宽度、折叠、纸纹）
  ├─ WorkspaceSearch.tsx    搜索框
  ├─ WorkspaceToolbar.tsx   排序按钮
  ├─ WorkspaceTree.tsx      树（懒加载、展开状态）
  │    └─ TreeItem.tsx      单行（三列网格）
  └─ WorkspacePreview.tsx   预览分流
```

**展开状态**存组件内 `Set<string>`，不存全局 store。切换项目时清空。

## 五、与现有页面的接入

**第一阶段只接一个页面**：`ProjectsPage`。

点击项目列表里的某个项目 → 右侧面板显示该项目的文件树。项目详情页不动。

理由：先验证“树 + 预览”能跑通，再决定是否推广到详情页、变更单页。

## 六、实施顺序

| 步骤 | 内容 | 验收 |
|---|---|---|
| 1 | Prisma 加 `workspaceRoot` + 迁移 | `prisma migrate dev` 通过 |
| 2 | `workspace-storage.ts`（路径校验、readdir、读写） | 单测覆盖路径穿越、符号链接、白名单 |
| 3 | `workspace.ts` 路由（tree/file/upload/delete/mkdir） | 接口能列出目录、上传、下载 |
| 4 | `WorkspacePanel` 骨架 + 纸纹 | 580px、可折叠、纸纹可见 |
| 5 | `WorkspaceTree` 懒加载 + 展开 | 展开目录只请求一层 |
| 6 | `WorkspacePreview` PDF/图片/文本 | 三类都能预览 |
| 7 | 上传 + 删除 + 新建目录 | 操作后树自动刷新 |
| 8 | 接入 `ProjectsPage` | 点项目右侧出现树 |

## 七、明确不做的

| 项 | 原因 |
|---|---|
| 拖拽移动文件 | 需要完整的 dnd + 冲突处理，第一版不做 |
| 文件版本历史 | 需要额外存储层 |
| 在线编辑 | Hana 是预览，不是编辑器 |
| 全文搜索 | 文件多时成本高，先用文件名搜索 |
| 虚拟滚动 | 懒加载 + 单层目录，通常不超过 200 项，够用 |
| 对象存储 | 已决策用本地路径 |

## 八、风险

**一、Windows 路径大小写**

`resolve` 之后大小写不敏感，但 `startsWith` 比较是敏感的。要统一 `toLowerCase()` 再比。

**二、文件名编码**

Windows 允许 GBK 文件名，Node 读出来是 Buffer。要 `Buffer.from(name, 'binary').toString('utf8')` 尝试纠正，失败则原样保留。

**三、大量文件的 `hasChildren` 开销**

用 `opendir` 读第一个 entry 就 `break`，不要 `readdir` 全量。

**四、PDF 的 iframe 与 CSP**

`helmet` 默认有 `X-Frame-Options: sameorigin`，同源 iframe 可以。但要确认 `Content-Disposition: inline`，否则会触发下载。
