# 墨衡 WP2–WP8 实施计划与状态

- 基线：`v1.9.0-rc.1`（`b95e3e7`）
- 本候选：`v2.0.0-rc.1`
- 依据：`施工单位成本管理系统完整设计方案 v1.0` 与 `下一阶段开发计划与实施记录-v1.9.0-rc.1.md`
- 原则：逐 WP 增量开发；保留主合同原始/有效金额分离、变更审批与外部确认、业主竣工结算与应收、分供结算与应付、付款退款冲销规则。本轮不修改 Prisma Schema / migration。

## 总体结论

本轮已把 WP2–WP7 中可以安全叠加的第一阶段能力写入源码。WP2 的八类台账 CSV 导出和目标成本 CSV 的列映射/服务端预检已实现；但并未把全部财务台账开放为批量导入。WP3 项目成员角色界面已实现。WP4 完成源码覆盖契约检查，但完整数据库集成证明仍待 Node.js 24+ 环境。WP5 上线动态待办与预警规则，未建立已读状态或外部推送。WP6 建立同步 CSV 报表中心。WP7 只实现目标成本表单的本机草稿，不实现财务离线写入。WP8 已执行可运行的静态和纯逻辑检查；完整构建与实机 Gate 被环境限制阻塞，因此本版本仍是 RC，不是生产通过。

## WP2 — 核心台账交换

### 已实施

- 报表中心支持八类 CSV：目标成本、实际成本、业主进度款、变更签证、业主应收、业主收退款、分供合同、分供应付。
- 每个导出 API 在服务端重新核验用户可访问项目；传入无权项目 ID 返回拒绝，不依赖前端隐藏选项。
- CSV 使用 UTF-8 BOM、标准引号转义和公式起始字符中和，单报表最多导出 10,000 条并在响应头暴露截断标记。
- 目标成本导入支持中英文常见列名自动匹配、用户手工字段映射、重复表头/重复映射检查、逐行错误提示、服务端预检和最终提交前二次预检。
- 预检涵盖字段格式、文件内部重复编号、与现有项目编号冲突、父级引用存在性和父级必须先于子级；未全部通过时不提交任何记录。
- 单条目标成本录入/编辑可在当前浏览器保存草稿；恢复需用户确认，正式写入仍需明确点击保存。

### 未扩大的范围

- 本轮不支持原生 `.xlsx`，不声称 CSV 为 Excel 工作簿。
- 目标成本是当前唯一支持批量导入预检/确认的正式台账；进度款、变更、应收/收款、分供结算/应付暂不开放批量导入，因为这些对象具有状态机、分配、冲销或过账语义。后续必须先定义幂等、关联、重复记录处理和事务边界。

### Gate

- 导出在权限内且仅包含用户所选筛选范围；敏感凭证与未授权项目不得泄露。
- 导入必须先完成映射、完整服务端预检与人工确认；任何错误行/冲突都不允许部分落库。
- 需要 Node.js 24+ 完整构建和真实数据库权限/事务 E2E 后才能关闭 WP2。

## WP3 — 项目成员与权限

### 已实施

- 项目工作台新增“项目成员与权限”页。
- 可用已注册的登录邮箱添加成员，并更新角色；不展示可枚举的公司全量账号目录。
- 当前项目负责人和经理可分配的角色不同；全局管理员可执行完整角色分配。
- API 每次都按项目权限和角色矩阵做服务端判断；不能把 UI 隐藏按钮当作安全控制。
- 添加/调整记录通过现有 AuditLog 写入；最后一名项目负责人不能被降级，需先添加另一名负责人。

### 尚未实施

- 当前不提供删除/移除成员操作；没有完整的跨项目权限矩阵与批量角色变更。禁止用此页面改变公司级用户身份。

### Gate

- 非成员访问 API 返回 403；普通成员不能自我提升为负责人或经理；角色更新审计记录存在；最后负责人约束由 API 强制执行。

## WP4 — 审计覆盖率专项检查

### 已实施

- 新增 `scripts/check-audit-coverage.mjs`，对项目、合同、目标成本、成本、进度款、变更签证、分供合同/付款、业主结算/应收/收付款、单位主档与账号创建等 11 类源码审计契约进行检查。
- 合并前每次发布候选可执行源码覆盖检查；失败会以非零状态退出。

### 未关闭项

- 11/11 通过仅表示对应源码 marker/实现路径存在，不能替代真实业务调用测试。必须继续核对成功写事务是否与审计同事务、金额快照是否包含前后值、失败事务是否没有成功日志、退款是否有反向关联、日志是否可篡改。

### Gate

- 高风险写操作逐端点集成测试；成功操作均有正确关联的审计记录，失败事务不留成功日志；历史审计不可通过 UI/API 更新或删除。完整 Gate 仍待 WP8 的真实 DB 环境。

## WP5 — 站内待办与预警

### 已实施

动态计算当前用户有权访问项目的：内部待审批变更、外部确认补件/核验/争议、进度款待审核、逾期业主应收、逾期分供应付计划、待办分供结算、30 天内到期的有效分供合同，以及有目标成本基线且实际成本超过末级目标成本基线的项目预警。

规则从现有业务台账实时生成，按高风险优先；前端每 120 秒刷新，并提供严重性筛选和对应页面跳转。没有增加通知表，也没有“已读/永久关闭”按钮，避免用户关闭提示却未处理业务。

### 未实施

- 未建立进度款计量周期配置，因此不会凭空推算“本月应申报倒计时”。
- 暂无邮件/企业微信等外部推送、通知已读状态和永久静默规则。

### Gate

- 预警以业务状态和权限范围为唯一输入；缺少目标成本基线时不得产生超支预警；合同结束日期未配置时不产生到期提醒。

## WP6 — 报表中心

- 采用同步 CSV 实现，不先引入队列、Redis 或对象存储。
- 导出表头、金额单位、日期字段、排序和记录上限在报告目录中显式列明；接口设置 `x-report-row-count` 与 `x-report-truncated`。
- 每次最多返回 10,000 行。若真实使用量证明需要异步报表，再依据文件大小/耗时实测决定任务队列，不预先新增必需服务。

## WP7 — 本地草稿与离线写入边界

- 当前只为目标成本新建/编辑表单保存浏览器 `localStorage` 草稿；恢复需用户确认，关闭表单不会把草稿自动提交到 API。
- 不实现正式合同、结算、应收应付、付款或退款的离线写入，也没有 Service Worker 或离线同步。
- 后续若支持离线，必须先定义幂等键、版本号、冲突检测、重试、回滚与人工合并；否则维持在线正式提交。

## WP8 — 发布验收与部署门禁

新增 `scripts/windows/verify-release-candidate.ps1` 以及 `docs/WP8-Windows与浏览器端到端验收清单-v2.0.0-rc.1.md`：检查 Node.js 24+、锁文件与依赖，运行静态契约、Prisma 校验/生成、完整 lint、API 测试和生产构建；可选执行数据库迁移/状态检查与 API 健康检查。它不会替代浏览器 E2E 和备份恢复。当前仓库还没有 `package-lock.json`，首次执行需用 `-BootstrapDependencies` 生成后人工审查并提交锁文件。

### 在 Windows Node.js 24+ 机器上的 Gate 顺序

1. 安装 Node.js 24 LTS 和 PostgreSQL 16；`npm install` 生成经审查的 lockfile，复核后提交 `package-lock.json`。
2. 运行 `npm run validate:release-candidate`、`npm run lint`、`npm test`、`npm run build`。
3. 运行 `npm run db:generate`、`npm run db:deploy`；在独立空库执行迁移与恢复演练，确认已有库仅增加预期迁移。
4. E2E 测试：普通成员跨项目读取/导出必须 403；目标成本 CSV 映射和错误行阻断；最后负责人保护；预警触发/消失；合同原始/有效金额、业主结算应收、分供应付与退款反向核销；失败事务不能留下成功审计记录。
5. 使用 `scripts/windows/prepare-windows.ps1` / 启停脚本进行内网 Windows 原生部署验收，再通过配置 HTTPS 的内网入口共享访问。

只有所有 Gate 完成并生成可重复报告后，才能发布去掉 `-rc` 的稳定版本。
